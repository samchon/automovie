# @automovie/template

`@automovie/template` renders and installs the bundled `scaffold` for a new AutoMovie production. The installed files then belong to the project; package upgrades never overwrite them.

## Generated project

- `AGENTS.md` routes the shipped skills, and `CLAUDE.md` only imports it.
- The screenwriting skill groups narrative planning, stage methods, expression revision, evidence and repair behind one task table. Creation groups production coordination, screenwriting, modeling, motion and audio by their actual owners. Production keeps video generation and editing/finishing in directly linked task documents; source and output evidence has its own contracts guide. Implementation/evidence and independent assessment retain their separate roles. Simple figures and coarse objects can carry the intended performance; Human is optional. Long work retains settings, treatments, scripts, final screenplay, and both expression passes; a short can enter at final screenplay. Overviews link their conditional detail directly from `.agents/skills`, while installed packages own their APIs.
- The scaffold owns its skills and compact contracts. Only `development/repair.md` and `development/writing.md` are byte mirrors of repository instructions, generated by `build/syncScaffoldInstructions.ts` on `prepare` and `build` and ignored by git.
- `evidence.config.ts` calls `@automovie/evidence` with one options object. By default, exported types and functions under `src` answer two engineering questions, and exported test functions answer two testing questions. Adding narrative options to that same object retains the engineering checks and selects stage, scope, evidence, current independent review, and expression-transfer duties. The reusable implementation stays in the package. Asset and delivery obligations retain their own respondents; the [evidence skill](scaffold/.agents/skills/evidence/SKILL.md) explains ownership. `lint.config.ts` configures ordinary source correctness lint independently of narrative selection.
- `test/index.ts` runs every exported `test_*` function under `test` through `node:test` for `npm test`, and passes when there is none; the development skill's [testing guide](scaffold/.agents/skills/development/testing.md) decides when a production has tests.
- The scaffold ships no production content, viewer stub, or provider-specific hook.

`renderScaffold` excludes working artifacts from its source population: a `node_modules`, `.git`, or `.cache` directory, or a file with a builder-output shape, belongs to whoever ran a tool there, and a generated project's loader would prefer an emitted `.js` to the `.ts` beside it. The scaffold's ignore rules ship as `scaffold/_gitignore` and install as `.gitignore`, because npm renames a packed `.gitignore` to `.npmignore`; supplying both root identities is refused.

A separately commissioned screenplay, whole motion hint, finished direct 3D film, and finished post-diffusion film are distinct outputs. Movie hints require programmed motion and staging for the main scenes and the whole assembled video; stills or pilot clips cannot replace it. A motion hint does not require a finished diffusion film, and direct 3D can finish without diffusion. The shipped [production skill](scaffold/.agents/skills/production/SKILL.md) routes their files and completion; [motion](scaffold/.agents/skills/motion/SKILL.md) owns programmatic scene performance, staging, and frame-time evaluation. Production skills and story contracts adapt [wrtnlabs/novels](https://github.com/wrtnlabs/novels/tree/6a9178bb2d96038d93b5313cd28682061cf44a03/packages/template/scaffold/.agents/skills), retaining its [MIT notice](scaffold/.agents/skills/LICENSE.novels).

The installed project-root `PROJECT.md` owns adopted scope, delivery method, representation, tools, runtime and setup authority. Creative instructions stay under `docs/instructions`. Runtime READMEs and `.env.example` hold nonsecret setup and variable names; actual secrets remain in ignored local `.env`. Optional integration code belongs under `src/integrations`.

## Public API

`renderScaffold` returns a deterministic project-relative file map with `{{name}}` and the catalog-resolved `{{version:*}}` tokens substituted. `publishFiles` validates and freezes that candidate, then returns a receipt naming every completed file and the first refused or parent-bound partial effect; `writeFiles` keeps the throwing API. New slots are created through Koffi-backed POSIX `openat` or Windows `NtCreateFile` parent-handle-relative adapters, so neither creation nor verification follows a successor child pathname.

## Development checks

`pnpm run build` syncs the scaffold's version placeholders and shared instructions, then compiles with source correctness lint and the shared evidence declaration guards. `pnpm run evidence` checks the declarations' checklist answers with `@wrtnlabs/evidence`.
