# 3D Modeling

Use the production's completed design and installed public package APIs. Keep part identities, parameter meanings, units, frames and shared boundaries consistent. Compute and measure from the same geometry; regenerate affected derivatives when their basis changes. Repair an unsound representation at its foundation.

## Visual debugging

If the viewer is broken, restore it first. Until its actual model display and controls work, do no work that requires visual debugging. Preserve the last valid display and protect other owners' processes.

- Inspect the actual current producer with a hardware renderer; record source, input, renderer and viewing conditions.
- Enlarge affected parts and inspect opposing views, assembled neighbors, use distance and required states, including intermediate motion.
- Judge appearance in beauty and use structural passes only for their documented quantities.
- Compare the render with the engine result and compare before/after under matching conditions.
- After each correction, render again and inspect it yourself. Record remaining defects and missing observations; stale, blank or unobserved output stays unverified.

Follow [project ownership](../../../README.md#ownership) for source and output placement. Use package documentation for viewer commands and API behavior.
