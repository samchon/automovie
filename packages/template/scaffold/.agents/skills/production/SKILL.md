# Production

Read the user's request, this project's instructions, and existing source and outputs. Identify the deliverable, creative constraints, available inputs, target environment, and what has already been verified. Resolve routine choices within that scope; ask only for decisions that block it.

Use the smallest working path. A short video can go directly to its final video script and implementation. A standalone model needs no screenplay. Read the [production guide](../../../docs/guides/production.md) when choosing files or changing the workflow, and [storytelling](../storytelling/SKILL.md) when the work needs narrative.

Choose asset paths through [3d-modeling](../3d-modeling/SKILL.md), and use [audio](../audio/SKILL.md) when sound is needed. Implement through [development](../development/SKILL.md), adopting [contracts](../contracts/SKILL.md) for the actual work units rather than imposing every checklist on every file.

Build and observe a representative result before expanding repetitive work. A pilot verifies that path, not the full deliverable. Carry changes through their source documents, consumers, and retained media, then finish with [review](../review/SKILL.md) on the requested scope and actual output.
