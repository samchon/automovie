# Production

Read the request, project instructions, current source, and outputs. Identify the deliverable, fixed choices, available inputs, target environment, and verified scope. Resolve routine decisions within the user's authority.

Ordinary coding and standalone assets start with the source/test baseline in `evidence.config.ts`. For narrative work, select the optional profile through the [workflow guide](../../../workflow/README.md#configure-the-production), retaining those engineering duties. A long production retains settings → treatments → scripts → final screenplay, with construction, rewriting, evidence, and independent review under [storytelling](../storytelling/SKILL.md). A short video may enter directly at final screenplay; an asset-only task requires no narrative. Disabled stages compose drafts; they do not waive the selected path.

For narrative work, use [instructions](../instructions/SKILL.md) for creative requirements and [discovery](../discovery/SKILL.md) for work-specific contracts. An asset-only task keeps its requirements in its brief and source controls, using the asset questions and optional engineering support contracts outside the narrative trees. Choose asset paths through [3d-modeling](../3d-modeling/SKILL.md), and use [audio](../audio/SKILL.md) when sound is needed. Implement with [development](../development/SKILL.md).

Read the [production guide](../../../docs/guides/production.md) when choosing source files or changing the workflow. Prove a representative execution path before expanding repeated work, keeping a pilot distinct from whole-work completion. Finish with [review](../review/SKILL.md) of the declared scope and actual deliverable.
