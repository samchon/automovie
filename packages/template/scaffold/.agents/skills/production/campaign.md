# Run and resume a production

Use this guide for sustained writing, review or media work, including an explicitly requested observation of one production. Keep the commissioned scope in PROJECT and creative decisions with their existing owners; the run record tracks execution and cannot grant approval or introduce a new stage.

## Establish the actual state

Read the current instructions, bodies, source, outputs and existing run record before assigning work. Follow relevant Git history, original review findings and failed logs when they explain a repeated failure or missing handoff. Distinguish old approval, current author work, independent review and actual media acceptance. An installed instruction's current bytes do not prove an earlier run used them.

Keep one concise current run record in ignored `.cache/` ([source ownership](layout.md#source-ownership)) linking the scope, exact inputs, active roles and process identities, observations, unresolved causes and next action. Link the existing evidence; retain raw logs and temporary comparisons in ignored `.cache/`, excluding credentials and private transcripts. Current review judgments belong in the direct review mirror, with past tracked judgments in Git.

## Execute and support

Dispatch the current task through [screenwriting](../screenwriting/SKILL.md), [motion](../motion/SKILL.md), [audio](../audio/SKILL.md), [development](../development/SKILL.md) or [review](../review/SKILL.md). One writer owns a changing body; reviewers receive the actual inputs and their required reading order. Use additional agents only when authorized, with explicit roles and disjoint write scopes. If independence is unavailable, record self-review as self-review and keep independent acceptance unperformed.

Inspect actual process state, artifacts and errors before calling a quiet run stalled. Resume a stopped run from its real identity and last valid output, preserving prior failure. Supply needed parent inputs, tooling or supported capabilities at their owner. A changed input starts a newly attributable result; restarting cannot inherit an earlier verdict or reset a review's stopping rule.

Keep the video or model viewer working throughout media production. Restore a broken viewer before other work: confirm the actual displayed artifact and relevant controls, seek/playback and capture with current source and renderer, then resume the dependent work. Build success and an error-free server log cannot establish visible operation. Report an unavailable path as unavailable.

When a reusable capability blocks the commission, repair its package owner and reconnect the production's actual consumer. If that owner is outside the accessible repository, report the exact missing behavior and affected consumer while continuing independent work. Use [explicit instruction sync](layout.md#project-ownership-and-customization) for authorized guidance updates; an instruction change alone repairs neither a body nor its runtime.

Finish each inspection round before cause-based repairs, then recheck the complete affected path. Follow [narrative rounds](../review/rounds.md) for text and [delivery review](../review/delivery.md) for the commissioned artifact. File counts, a running agent, passing validation, a generated voice or a preview are individually useful observations; none establishes an unobserved whole film.

## Observe without manufacturing progress

When periodic observation is requested, use an available scheduler or coordinator at the requested interval and record actual checks and interventions. An instruction or configured timer alone is not an executed loop. Check existing workers before starting replacements, protect other owners' services, and preserve cancellation and completion boundaries. Keep unchanged checks quiet; report meaningful progress, completion, failure or a decision that blocks work. Recurring observation adds no publication, merge or setup authority.
