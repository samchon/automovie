# Settings index section principles

Each section of the settings index answers for its contained file group. A settings fact H2 is not this respondent.

## Does this group help a reader find the right owner? {#group-purpose}

Do its title and explanation name a distinct reader question, with files that belong together for that purpose? Use the words the reader would search for, including established world names where appropriate, rather than contract labels or author work categories. Each file entry should explain what is found there and why it belongs here, with a route to a shared subject's canonical owner. Repeating file names, copying their facts or H2 lists, or mixing unrelated reference purposes fails. Work promises and production instructions may have their own clear reference group without pretending to be world entities.

## Are its files coherent and ordered for reference? {#group-order}

Does each file own one independently used subject, and do prerequisites and an overview precede dependent detail? Keep a subject's related attributes together; a large collection may divide into independently used subjects with explicit links to their containing whole. Unrelated institutions, objects, and people need separate reference homes when readers use them separately. For cyclic dependencies, provide an initial overview and exact references instead of duplicating facts. Reference order does not change story chronology or audience reveal order.
