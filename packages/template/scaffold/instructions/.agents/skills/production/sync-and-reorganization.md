# Sync and reorganization

Instructions reach a production only through an explicit sync, and only part of a production's organization may change.

## Sync and ownership

Package upgrades never rewrite this production. An authorized sync by the installed command-line tool updates generated routers and bundled task resources while preserving contracts, configuration, project decisions, content and proof. Inspect its check result before applying; that tool's README and help own the invocation and baseline handling.

Stored instruction digests detect local conflicts. When local instructions differ from the scaffold and no digest is stored, pass the scaffold version they came from as the baseline.

A sync keeps an instruction file the scaffold no longer ships, including one it moved or renamed, and reports it as retired; once nothing local links to it, delete it, because a retired file still reads as a current rule.

In a workspace the shared instructions, their sync state and their sync belong to the workspace root, never to one production.

Keep custom criteria and decisions with their production owners. Reusable checking belongs to the installed evidence package. When adapting paths, language or tools, keep every duty of the route and every relationship the graph records.

## What a production may reorganize

The source folders of [source layout](../development/source-layout.md#source) are fixed, because the installed evidence stages select declarations by those folders: a renamed folder silently leaves its contracts, and the graph reports fewer duties instead of an error. Add a subject, discipline, scene or film inside them rather than beside them.

A production may reorganize what no installed stage selects by name: how settings records split into subjects, how a screenplay is partitioned, and the media folders. Before moving any of them, map old addresses to their new owners and update links, citations, commands and consumers in the same change. Update source and media answers through [their evidence method](../evidence/answering.md); changes touching narrative answers or closed reviews follow [upstream repair](../story/correction/repair.md).
