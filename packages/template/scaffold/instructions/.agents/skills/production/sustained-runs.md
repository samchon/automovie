# Sustained runs

Sustained writing, review or media work, and a requested observation of one production, run under one record. The run record tracks execution; it grants no approval and adds no stage.

## Establish the actual state

Read the current instructions, bodies, source, outputs and run record before assigning work, and the Git history, findings and failed logs that explain a repeated failure. Keep one concise run record in ignored `.cache/` with the scope, exact inputs, roles, process identities, observations, open causes and next action, linking existing evidence rather than copying it and leaving out credentials.

## Execute and support

Dispatch each task through the skill that owns it in the production's [routing table](SKILL.md#route-the-work). One writer owns a changing body, and one owner holds a film's screenplay, scene and film composition and camera together, because the camera realizes the screenplay's camera decisions through that composition. Entity, motion and sound modules can have their own owners, who repair the module defects the film owner reports.

Use additional agents only when authorized and give them disjoint write scopes. [Review](../review/SKILL.md) owns who may review and what counts as independent.

Inspect the actual process, artifacts and errors before calling a quiet run stalled, and resume a stopped run from its last valid output and [stage caches](stage-caches.md), keeping its failure. A changed input starts a new result; a restart inherits no verdict.

A capability an installed package lacks is handled under [installed packages](../development/reuse.md#installed-packages) while independent work continues.

## Observe

For requested periodic observation, use an available scheduler at the requested interval and record the actual checks; a configured timer is not an executed loop. Check existing workers before starting replacements, report only meaningful progress, completion, failure or a blocking decision, and take no publication or merge authority from the loop.
