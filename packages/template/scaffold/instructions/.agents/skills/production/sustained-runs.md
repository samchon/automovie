# Sustained runs

Sustained writing, review or media work, and a requested observation of one production, run under one run record. The record tracks execution; it grants no approval and adds no stage.

## Actual state

Before assigning work, read the current instructions, bodies, source, outputs and run record, and the Git history, findings and failed logs that explain a repeated failure. Keep one concise run record in ignored `.cache/` with the scope, exact inputs, roles, process identities, observations, open causes and next action, linking existing evidence rather than copying it, and never a secret.

## Execution

Dispatch each task through the skill that owns it in the production's [routing table](SKILL.md#routing). One writer owns a changing body. One owner holds a film's screenplay, scene and film composition and camera together, because the camera realizes the screenplay's camera decisions through that composition; entity, motion and sound modules can have their own owners, who repair the module defects the film owner reports.

Use additional agents only when authorized, with disjoint write scopes. [Review](../review/SKILL.md) owns who may review and what counts as independent.

Inspect the actual process, artifacts and errors before calling a quiet run stalled. Resume a stopped run from its last valid output and [stage caches](stage-caches.md), keeping its failure on record. A changed input starts a new result, and a restart inherits no verdict.

A capability an installed package lacks is handled under [installed packages](../development/reuse.md#installed-packages) while independent work continues.

## Observation

For requested periodic observation, use an available scheduler at the requested interval and record the checks actually made, because a configured timer is not an executed loop. Check existing workers before starting replacements, report only meaningful progress, completion, failure or a blocking decision, and take no publication or merge authority from the loop.
