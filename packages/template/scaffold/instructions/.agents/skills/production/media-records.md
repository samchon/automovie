# Media records

Every generated or acquired file, every pipeline output and every generation request has a place and a record. Research originals stay under [research](../story/planning/research.md).

## Files

Commit images and generation requests. Never commit audio or video, which are too large for Git and gather in the ignored `media/` folders below. Never commit a file whose license forbids redistribution either: add a `private/` folder beside its kind to `.gitignore` before saving it there, and let its record restore it.

| Location, when used | Holds |
| --- | --- |
| `docs/prompts/<purpose>/<descriptive-name>.md` | Generation requests, the shared descriptions they cite, and the receipts that identify their results |
| `media/diffusion/images/<domain>/` | Images generated by external models, at the settings or brief record's domain path, including the canon references the records embed |
| Ignored `media/diffusion/audios/`, `media/diffusion/videos/` | Audio and video generated by external models (diffusion, speech, music), identified by their request records |
| `media/acquired/images/`; ignored `media/acquired/audios/`, `media/acquired/videos/` | Third-party production material, such as sound libraries, and research footage |
| `media/acquired/models/`, `media/diffusion/models/` | The frozen source of an acquired or generated 3D form or motion clip, with its sidecars |
| Ignored `media/capture/<film>/` | Each capture's stills, sheets and record, which the next capture replaces |
| Ignored `media/automovie/<film>/` | The pipeline's files for one film: `frames/accepted/<revision>/` the sheets of an accepted delivery, moved from its capture; `controls/` the motion hint's control channels; `videos/` renders and their reports; `audios/` audio made for the user to hear |
| `media/manifest.json` | One record for every media file Git does not hold |

## Records

A record lets the next person identify a file and restore it. Every record, in `media/manifest.json` or in the request that made the file, holds:

- where the file came from: the source URL and creator, or the generation request;
- its license, attribution and usage terms;
- its content digest.

A generated file's terms cover each layer: the code, the weights, any body model or training data, the territory and the plan it ran under. Its record also holds the provider, model and version, settings, prompt, input files by digest, job identifier, and a seed where the model exposes one.

The kept bytes are the source and the record only identifies them, because a seed, a URL or a finished job does not reproduce a file. The skill that makes a file adds the fields only it knows, and never a secret.
