# Media records

Record the origin, rights and identity of each request and media file.

## Files

Commit images and generation requests where redistribution is allowed. Keep audio and video ignored. Before saving restricted assets, ignore a `private/` folder beside the asset kind and record how to restore the file.

| Location, when used | Holds |
| --- | --- |
| `docs/prompts/<purpose>/<descriptive-name>.md` | Generation requests |
| `media/diffusion/images/<domain>/` | Images generated by external models |
| Ignored `media/diffusion/audios/`, `media/diffusion/videos/` | Audio and video generated by external models |
| `media/acquired/images/` | Acquired images |
| Ignored `media/acquired/audios/`, `media/acquired/videos/` | Acquired audio and video |
| `media/acquired/models/`, `media/diffusion/models/` | Frozen 3D form and motion clip sources, with their sidecars |
| Ignored `media/capture/<film>/` | Each capture's stills, sheets and record, which the next capture replaces |
| Ignored `media/automovie/<film>/` | The pipeline's files for one film |
| `media/manifest.json` | One record for every media file Git does not hold |

### Generated media

Keep requests, their shared descriptions and generation receipts together.

Save generated references in `media/diffusion/images/<domain>/`. Take the domain from the settings or brief record. When instructions own an appearance, name the domain there before generation. Use `cast` for portraits.

### Acquired media

Keep third-party assets and study footage in the acquired folders above. Research owns other study originals.

### Pipeline files

The pipeline keeps one film's files in these folders of `media/automovie/<film>/`:

| Folder | Holds |
| --- | --- |
| `frames/accepted/<revision>/` | The sheets of an accepted delivery, moved from its capture |
| `videos/` | Renders and their reports |
| `videos/controls/` | The guide passes a render draws with `--passes`, with their `record.json` |
| `transparent/` | The straight-alpha `film.mov` of a transparent-background render, with its report |
| `audios/` | Audio made for the user to hear |

The film's acceptance record holds its current verdict.

### Render reports

Each attempt writes `render-report.json`. A blocked or failed attempt leaves the previous video in place. Before using the files, verify `status: published` and match `source.sha256` to the video's SHA-256. Match `filmSha256` in `controls/record.json` to the same digest. Render again if a check fails.

The trusted report's `cut` lists each entry's output `liveFrames` as `[first, endExclusive)`. An entry starts at its transition's first frame, while the picture still shows mostly the previous shot in a dissolve or only the shot fading out in a fade's first half.

## Records

Record the following in `media/manifest.json` or the generation request:

- Source URL and creator, or the generation request
- License, attribution and usage terms
- Content digest

For guide passes, record the SHA-256 of `videos/controls/record.json`. It seals every frame digest in that record.

Record the license terms for code, weights, body models, data, territory and service plan. Record provider, model, version, settings, prompt, input digests, job ID and seed if exposed.

Preserve the original bytes and identify them by their record. Add fields the generating skill requires and omit secrets.

### Fonts and stills

<!-- @reference `IAutoMovieFontSource` and `IAutoMovieSurfaceGraphicLayer.IImage` in `@automovie/interface`, with the asset ledger's `IAutoMovieAssetProvenance`. -->

Record a font the production synthesizes in its own code as an `"embedded"` font source, with the source file and function that build it as its `origin` and the SHA-256 of its bytes as its `digest`. Record a licensed font file, and every still image a surface graphic shows, as a project asset whose provenance carries its `license`. Commit a font file only with that record, because font admission refuses a font asset whose provenance lacks its license or a `"font"` use under the font source's id.
