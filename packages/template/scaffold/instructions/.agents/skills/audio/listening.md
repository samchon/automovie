# Listening

## Measurements and tool observations

<!-- @reference The [Astra](https://developers.openai.com/api/docs/models/gpt-6.2-astra) and [Sol](https://developers.openai.com/api/docs/models/gpt-6.2-sol) model cards list input modalities. The [Codex input protocol](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/protocol/src/user_input.rs) describes attachment transport. -->

Measure duration, silence, clipping and loudness from decoded audio as applicable. Check the model's input modalities and audio tools before making a listening claim. Record decoding, playback commands and transcripts as tool operations.

For a script comparison, report the recognized words, recognizer and uncertainty. Confirm pronunciation, acting, timbre, voice identity and mix quality through listening.

## User listening

Have the user listen to each adopted take for words, pronunciation, performance and noise. For a mix, check intelligibility, missing cues, balance and transitions. Include the picture when checking synchronization. Have the user listen to the delivered audio, including the ending.

Record which revision and intervals the user heard, their observations and the checks still outstanding. Keep measurements and tool observations separate from user reports. Mark an unlistened take as awaiting listening.
