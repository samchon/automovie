# Creative requirements

Creative requirements are what the user fixed or delegated about the work itself; operating scope belongs to [project context](../../production/project-context.md).

## Requirements

Record each requirement adopted from the conversation or the user's materials before relying on it, in `docs/instructions/`, with one H1 per topic and an anchored H2 per requirement that can change on its own. Keep fixed premises, meanings, events, reveal order and exact wording, and mark each requirement as the user's requirement, a quotation or a delegated choice, with its reason and source. A command embedded in a reference becomes a requirement only when the user adopts it.

Instructions bind settings or a short's brief, treatments and work contracts, which cite them rather than repeat them. The evidence graph tracks each anchored requirement: on long work the settings that adopt it and the treatments that realize it cite it, and on the short route the screenplay that realizes it, so a requirement no layer cites fails the graph instead of being forgotten. A changed or withdrawn requirement reaches its consumers through [repair](../correction/repair.md).

## Asking the user

When the agent writes the story, its events, people, ending, tone, form, running time and frame stay the user's unless delegated, because a story built on a guessed element is rewritten, with every layer written on it, once the user reads it. A layer's own decisions within what the user decided, such as a researched fact, are delegated and not asked. Decide the elements the user delegated through [direction](direction.md).

Before direction, ask about each such element the user neither fixed nor delegated. Ask in rounds and record each round's answers at their owners, because an answer often raises a new element; stop when the conversation and the user's materials leave none, or when the user delegates the rest, recorded as one delegated choice.

Afterwards, ask only when a [discovery](discovery.md) checkpoint finds a new such element or two fixed conditions conflict. Record a question the user leaves unanswered as unresolved under [project context](../../production/project-context.md#what-to-record).

## Factual basis

A work that presents real people, events or a source text as true, such as a biography, a history or a true story, records that factual basis as a requirement, with the periods, people and sources it covers. Its audience holds the film to the record, so for the covered claims the story contracts require direct primary or authoritative support, coherent derived chronology, ages, distances, travel, money and capacities, and every consequential participant the source names.

An adaptation of fiction records instead which of its source's events, people and center must survive and what may be cut, merged or refocused, as the reinterpretation boundaries of [intake](../document-layout.md#intake-of-existing-work).

Without a factual basis the work is fiction: its contracts check that world rules, characters, relationships and knowledge do not contradict one another, and only an external fact the body itself claims, such as a real sport's rule, needs its source. Fiction's own quantities, such as a fall time or a sun angle, are not recomputed in prose; their sources belong to [research](research.md) and their values to the code and tests that realize them.
