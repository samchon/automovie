# Refusals

A refusal identifies an unsupported action or object before rendering. Read the installed package's README and types for the specific cause.

## Repairing the named axis

Change the axis the refusal names and rebuild. Adjust preceding action where needed. For an infeasible force, use a studied force or return the outcome to the screenplay.

Of the feasible repairs, choose the one that realizes the beat. Keep the refusal visible until its cause is fixed.

## When no repair holds

A feasible beat outside the installed vocabulary goes through [vocabulary extension](../laws/extension.md). Return a physically infeasible beat to the screenplay under [upstream defects](../../story/correction/repair.md#upstream-defects).

Report a package defect when documented use fails or its refusal gives no repairable axis. Include the composition and refusal or observed failure. Keep the case visible and continue independent work. Repair at the package owner.
