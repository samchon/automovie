# Programmed motion

Realize the screenplay's performance through code, in the order below, because each step can only use what the one before settled. Read [project context](../production/profile.md), the final screenplay and its [research](../story/planning/research.md) first. A single moving instance needs only its promised behavior; a whole-video commission needs its complete progression.

1. Start from the entities [entity work](../development/entities.md#coarse-first) builds: the polygon man for every person and the simplest identifying form for everything else. Motion is authored and accepted on them, whatever detail a delivery later selects.
2. Compose each person's performance from the installed human motion vocabulary, as its README and public types give it. The package owns its actions with their studies and checks, so a second implementation in the production duplicates that work without its checks. [Source layout](../development/layout.md#how-the-parts-work-together) says how a cast entity's capabilities carry those actions into a scene.
3. Write a production law only for an action the vocabulary lacks and for what is not a person, such as an animal, a vehicle, a crowd moving as a mass, a camera or a light. Confirm its [research](../story/planning/research.md) study first, because a law written without one invents the practice. Design it under [laws](laws.md) and the other shared rules below, answer the [behaviors contract](../contracts/development/behaviors.md), and unit-test it against its study's values through [testing](../development/testing.md). Contact and reactions use the installed engine through [physical feedback](physics.md).
4. Accept every entity and motion module in its [catalog cases](#catalog-cases) before composing the film.
5. Compose the film from accepted cases through their entity API and the screenplay alone, one short contiguous segment scene by scene under [staging](staging.md) and [frame evaluation](timeline.md), and pass [segment review](segments.md) before extending from its accepted ending. A defect the film shows in a body, contact or behavior is repaired in its owning module and re-accepted in its case, never patched in a scene, because a scene [only composes](../contracts/development/composition.md#composition-only).
6. Deliver a commissioned [detail option](../development/entities.md#detail) only after the coarse performance is accepted, and recheck on the same segments the contacts, deformation, visibility and timing the detail can change.

When a vocabulary action misbehaves in a case, hand the user the case and its numbers under [installed packages](../development/SKILL.md#installed-packages) rather than patching it in the production, because a local patch hides the defect from every other production.

## Catalog cases {#catalog-cases}

A catalog case plays one module alone: one action against one target, partner response and outcome, one movement, one official or bystander behavior, one fall, or one entity state the screenplay uses. Cases of one module differ only in parameters, so each module has one case composition that takes them, and the [catalog film](../development/layout.md#source) lists every row the screenplay uses in its own labelled interval.

Capture each case's interval with the README's frame capture, at the spacing [verification](verification.md#look-at-the-frames) requires. Review every still against the [performance study](../story/planning/research.md#performance-study) and the cast, prop and set records, repair each failing case at its module by cause and recapture it, and accept a case only when its checks pass and no still shows a flaw. Record each accepted case in the catalog's [acceptance record](../review/delivery.md#acceptance-record), so the next session knows which cases were accepted at which revision.

A rehearsal module the film registry does not list is scratch for work in progress. Acceptance happens only in the catalog film, because the catalog replays every case after a repair and a rehearsal does not.

## Shared motion rules

Author every body movement, composed or written, as effectors brought to targets rather than as coordinates or tuned joint angles, under [effector goals](authoring.md): a fist to the opponent's struck region, each foot to the floor at its step, both hands to a prop's grip, the hips to a seat or mount. The other rules build on that one:

- [Laws](laws.md) when designing an action: its plan, entry state, events, outcome and time scale.
- [Variation](variation.md) when a performance differs by parameters, skill or seed.
- [Transitions](transitions.md) when a performance changes action or target mid-motion.
- [Contacts](contacts.md) when it plants, sits, grips, hands over or meets another body.
- [Layers](layers.md) for gaze, breathing and other motion that runs over every action.
- [Verification](verification.md) for a case's bounded checks and frame review.
