# Vocabulary extension

A beat may need an action or a moving body the installed packages do not seem to have. Take the first route below that stages the beat, because each later one costs more to write and leaves more of the checking to the production. Generated or traced motion the user chooses follows [motion diffusion](../diffusion/SKILL.md) instead.

## Routes

### Composing again

Read the nearest action's parameters and the [operators](../compose/composition.md#operators) again in the vocabulary's types. Most missing actions are an existing one with another target, effector, object or manner, two joined as an overlay or a mutual join, or the same one at another seed.

### Registering a row

A row is one named entry of an action's table, such as a kind of gesture or task. When the vocabulary has the table and lacks the entry, register the row as its README shows. The action that owns the table then performs the row, with every axis the row leaves open and every operator.

### Registering a law

Write a law only when the missing action owns what no shipped action plans:

- a change of base, such as a way onto or off a support;
- an outcome rule between performers;
- a planner of its own, for a path, a pattern of steps or a sequence no shipped planner lays out.

Register the law with the vocabulary as its README shows, and the vocabulary composes, cuts, refuses and checks it like its own actions.

### What is not a person

Write a production law for a moving body no installed package provides, such as an animal or a machine no archetype offers. What people use and ride needs none, because the installed packages already move it. Contact and reactions of a body the production moves use the installed engine through [physical feedback](../physical-feedback.md).

## What an extension owes

Confirm its [research](../../story/planning/research.md#what-needs-a-study) study first, because a row or a law written without one invents the practice. Put it in the laws folder [source layout](../../development/source-layout.md#source) gives, where its declarations answer the [behaviors contract](../../contracts/development/behaviors.md), and unit-test it against its study's values through [testing](../../development/testing.md#motion-checks). Then accept it in a [catalog case](../catalog-cases.md) like any other module.

A row takes only its study's values. A law follows the pages this skill's router lists.

## Sending it upstream

Share a row or a law other productions would need as a [shared module](../../development/modules.md#shared-modules) of the workspace, tell the user, and keep the registered one in the production until the package ships it. Tell the user of an action registration cannot express.
