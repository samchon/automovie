# Catalog cases

Inspect the capability in its scene interval. Use a separate case for a standalone commission, reusable custom law or conditions needing an independent check. Register catalog cases in the [catalog film](../development/source-layout.md#scenes-and-films), label intervals and vary inputs through parameters.

## Capture and review

Play the complete case with the relevant body, load, support, surface and partner. When the action can miss, test that its contact-dependent effects occur only on contact. Capture with the README command and use joint marks where available. Apply [motion judgment](judgment.md) against the subject record and, for skilled practice, the observed exchange.

Resolve a case once on load. Audit it separately from loading, playback and capture. Reuse its report with the same inputs and package versions.

## What each case owes

Select automated checks for the implementation the catalog plays.

| Implementation | Check |
| --- | --- |
| Installed action used as documented | The package tests mechanics |
| Production row or law, or a body it moves | Motion checks and clean report |
| Other production code, such as entity or retargeted clip | Passing tests |

Follow [testing](../development/testing.md#motion-checks) for production code and [refusals](compose/refusals.md#when-no-repair-holds) for an installed action defect.

## Record

Record revision, inputs, conditions and interval in the scene review or `docs/acceptance/catalog.md`. Recheck repairs and untested conditions. Submit a commissioned case video for delivery review.
