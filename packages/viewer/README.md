# `@automovie/viewer`

The Human preview API under `@automovie/viewer/human/*` owns GPU decoding, materials, camera fitting, orbit controls and rendered observation. The numerical request runtimes live in `@automovie/human`; Playground supplies editor controls and example documents. The preview consumes numerical results without changing their model or admission result.

Use `human/face/createConnectedFaceViewport` for a face and `human/body/createConnectedBodyViewport` for a body or assembled person. The caller supplies its canvas, renderer, orbit controls and worker transport. `human/common/observation/createHumanObservation` observes the displayed group, including named parts and the current camera. Disposal attempts retirement of preview-owned GPU resources and reports failures; public completion does not certify native allocation release. It does not dispose a caller's renderer or numerical source.

The Human inspection runtime under `human/inspection` owns numerical transport, source generations, GPU display recovery, capture and publication of completed displays. Its HTTP source event stream does not own browser page lifetime. Playground composes this runtime with its UI and example documents through the `human:viewer` command described in its [README](../playground/README.md#run). Asset readers under `human/common/assets` share strict UTF-8 and content-based gzip decoding; recorded camera admission and placement live under `human/common/observation`.

The Node-only `@automovie/viewer/process/ProcessOwnership` subpath owns service process discovery and explicit termination; it is outside the browser root export. Resident service records retain the OS creation identity alongside the PID. Records without that identity cannot authorize stop. On Windows, a creation-ordered ancestry snapshot excludes stale parent links, and retained process handles are checked before termination instead of using `taskkill /T`. POSIX signals only the checked root PID; Node's PID-based signal API retains a creation-check-to-signal race on those platforms. Neither probe silence nor elapsed uptime authorizes termination.

The package builds native ES modules with NodeNext resolution. Published exports select `lib/index.js` and `lib/index.d.ts`, and Human subpaths select the corresponding emitted files. Node consumers require version 22.23.2 or later. ESM consumers may import Viewer and Three concurrently; the Viewer graph imports Three's ESM core and addons. CommonJS callers use Node's synchronous ESM loading for the public root, while the asynchronous inspection process entries run through Playground's checked ESM command. Browser hosts bundle the same ESM library graph.

Contract exclusions are grouped by semantic domain in `src/evidence/`; `src/AutoMovieViewerEvidenceExclusions.ts` retains actor and asset boundaries. `evidence.config.ts` selects these declarations from the complete source population. Exclusion carriers describe package boundaries and contain no rendering or lifecycle logic. The viewer exports that perform those operations retain their own positive contract citations.

After `AutoMovieTextureCache.prime`, `describeSources()` reads decoded dimensions, upload format, mip policy, inherited sampling and actual Source equality from the same objects that supply material clones. Pass these host facts as `textures` to `assessAutoMovieRenderBudget` in `@automovie/render`. A decoded source may serve several resident sampler or color-space variants; changing only UV placement does not allocate another upload. An unsupported or unreported representation keeps the byte bound unknown and refuses admission of required unbounded texture storage.

`samplerState` preserves every supported native filter, including choices outside the authorable sampler union. Observed invalid flags report null; a complete authored sampler replaces inherited state. The host passes actual cache facts after resolving all required assets, then refuses evidence before drawing:

```ts
await textureCache.prime(requiredBindings);
const assessment = assessAutoMovieRenderBudget({
  compiled, shot, budget, renderer: rendererIdentity, settings, assets,
  textures: textureCache.describeSources(),
  textureResidency: contextResidency,
});
const refusal = autoMovieRenderBudgetRefusal(autoMovieRenderBudgetEvidence({
  tier, budgets, assessments: [assessment],
}));
if (refusal !== null) throw new Error(refusal);
```

For a reused graphics context, pass `textureResidency` with every other live shot, its cache facts and stable owner, and retained runtime resources. Read each actual environment clone with `readAutoMovieTextureSource`; its cached CubeUV and background derivatives follow Texture identity, while raw uploads follow Source identity. PMREM blur scratch and the PBR DFG lookup are shared context resources and may survive source disposal. The host records actual retained target extents and excludes disposed residents. Runtime equality tokens are opaque: target sealing fingerprints their stable sharing relation, so new UUID spelling alone does not invalidate a report. Omitting this profile describes a fresh context containing only the assessed shot.

Native mip generation retains the full chain even under nearest or linear sampling. The source reader also supplies `environmentBackgroundFormat` from the actual component type: a red or RG half-float source produces an RGBA half-float background cube. An explicit raw internal format does not replace that inherited component type. Missing or unsupported cube output facts keep its bytes unknown and refuse normal admission. Framebuffer copies remain uncertified in this decoded-source lane; their existing display or attachment owner supplies the actual profile.

Sharp-background conversion can temporarily upload a mip-linear image with a linear filter, then restore its property while the native key remains linear. `environmentSampler` and `environmentSamplerState` report this factory intent. Preflight closes configured and conversion choices as a conservative initialization-order union and shares equivalent material variants within it. Its allocation count is an upper bound, not an observed handle census. Missing factory intent for inherited or mip-linear environment sampling, and explicitly null intent, refuse admission. Known legacy non-mip-linear sampling needs no additional choice. The reader leaves texture properties unchanged; hosts retain context resources until their actual physical lifetime ends.

`buildScene` hands its decoded environment clone to `applySceneEnvironment`, which claims that wrapper exclusively for the scene and publicly retires any earlier cube or PMREM conversion. An unchanged application retains its cache and does not raise another upload version. Legal content, sampling and generation changes require the same owning transition before preflight; dimensions, type or format changes require disposal and a new Texture and decoded Source. A wrapper already bound by a material, another scene or a shared shader lookup cannot be taken by this handoff. `readAutoMovieTextureSource` leaves changed, unowned equirectangular or unsuccessfully retired storage uncertified, so normal preflight refuses its byte and count metrics before drawing. Separate cache clones can still share decoded Source pixels. The observer tracks each wrapper's own version and actual input references, so creating another normal clone does not invalidate it through the shared Source version.

Before first issuance, a cache host may finish preparing its decoded original. Issuance fixes the original's inputs before native clone starts and verifies the original and copied fields after its success or failure. Host `userData` evaluation during copy cannot replace that earlier baseline. Each returned clone keeps its separate creation tuple. Changing the original cannot silently describe an earlier clone's generation or storage, and restoring fields does not erase an observed uncertain history. `resolveAutoMovieMaterialTexture` acknowledges its normal sampler/color/UV setup and upload increment only when it starts from a clean tuple. Successful exclusive environment retirement can refresh that clone; it cannot repair a changed original or another clone. For changes outside those owners, close the old cache and use a fresh decoded identity rather than certifying it by reobservation. A cache rejects another cache's actual original, and an already-issued binding wrapper cannot become a decoder original even inside its own cache. Aliases of its decoder original and separate wrappers sharing decoded Source pixels remain supported. The reader observes both ownership histories before extent/layout refusal; stable environment reuse considers its own wrapper without repeated retirement due to another wrapper's uncertainty.

`AutoMovieTextureCache.dispose()` independently attempts every owned wrapper and retains one failed or successful completion. Source detachment makes release indeterminate: native disposal can return while the previous Source's GPU allocation remains alive. Keep that unknown context footprint after the failure until physical context release. Empty cache bookkeeping, restored properties or a new cache in the same context do not prove clearance. Public disposal listeners are observations rather than a complete history when an earlier listener throws; the owning close marks uncertainty before calling them. Direct `readAutoMovieTextureSource` on an unregistered object describes a future before-upload bound. A reused-context host supplies its retained historical phase facts instead of treating that observation as a native census.

`readAutoMovieRenderTextureTarget` reads a host-owned framebuffer's color formats, cube faces, mip policy, samples and custom depth allocation. Pass retained targets as `textureResidency.renderTargets`; depth renderbuffers consume bytes while actual depth textures also increase allocation count. For physical-material transmission, `readAutoMovieTransmissionTextureTarget` bounds the native r186 target from the current physical viewport, camera viewport, transmission scale and graphics capabilities. Assign stable target and shot owners, retain one record per native scene/camera target, and include earlier targets until their context releases them. Missing required transmission target facts refuse admission. Array and volume sources remain unknown in the two-dimensional reader, and framebuffer textures require their owning attachment profile.

`buildGeometry` uploads optional `IAutoMovieMesh.colors` as a linear RGB attribute. `buildModel` reuses separate material variants for coloured and uncoloured parts sharing one material identity, so enabling vertex colour never changes a bare neighbour. A caller composing `buildGeometry` and `buildMaterial` directly sets the material's `vertexColors` flag to match the geometry. A material with a `subsurfaceRadius` gets `applySubsurfaceShading`: its direct diffuse term becomes the pre-integrated response of a translucent surface, the clamped cosine averaged over the circle with a Gaussian of the radius times the curvature each fragment estimates from its screen-space derivatives (`subsurfaceTable`, `subsurfaceFragment`); flat surfaces stay Lambertian, and specular, clearcoat and indirect light are untouched. A material with a `detailNormalTexture` gets `applyDetailNormal`: the detail map is sampled over UV 0 through its own transform and whiteout-blended over the normal map in tangent space, or stands in as the normal map when there is none. A material with `overlays` gets `applyMaterialOverlays`: each overlay's colour image, sampled over UV 0 through its own transform and times its colour factor, tints or replaces the base colour where its alpha times its strength covers, moves the roughness to its own there when it names one, and bends the tangent-space normal after any detail map by its normal map, times its normal scale: a tint whiteout-blends its slopes, times its strength too, and a replacing overlay's normal replaces the material's by its coverage (a material without a normal map gets a flat one-texel map for them to bend). Shader changes compose through `addMaterialShaderPatch`, which runs them in order under one program key. Patches that bend the tangent-space normal splice into it through `spliceTangentNormal`, so they compose in the order they run. A mesh with `reliefWeights` carries them as the `reliefWeight` attribute and draws with its own variant of its material (`applyReliefWeights`), which scales the normal map's slopes by the interpolated weight right after their own scale, before any detail or overlay blend; instanced flattening gives a bare neighbour weights of one.

Instanced model/object flattening preserves mixed coloured and bare parts. Its owned geometry copies use a common Float32 RGB(A) layout, decoding normalized imported attributes and filling absent RGB or alpha with one; entirely bare models remain buffer-free. Malformed colour cardinality or a non-RGB(A) tuple is refused before merging.

`AutoMovieGeometryPhysicalVertices` preserves declared physical source correspondence on generated geometry and reads it from an already-loaded static glTF geometry. `read(mesh.geometry)` returns an owned source domain/ID table and nullable render-vertex references; it never changes imported attributes or user data. Standard glTF references use two unnormalized Uint16 words, including interleaved accessors, while opaque safe integer IDs remain JSON values. Absence retains ordinary current-position incidence, and explicit null entries remain separate from declared source points. `writeOwned` replaces only metadata on viewer-owned generated geometry; imported wire records refuse writes. This is runtime ownership and inspection, not an assertion of anatomical identity or an exemption from geometry validation.

`resolveAutoMovieFilmBeautyComposition` classifies sampled beauty layers as direct, fade over opaque black or complementary dissolve. `renderFadeToBlackFrame` and `renderCrossDissolveFrames` draw each source through the direct canvas path, retain its resolved display bytes with GPU framebuffer copies, and apply nearest-integer byte weighting without another tone or transfer transform. Each callback owns and restores its scene's exposure and tone state, including material-level `toneMapped: false`. Source antialiasing is the canvas's own policy. A source callback must leave the default framebuffer selected. A caller-owned target receives the display product while its canvas backing and selected target are preserved. `disposeFadeToBlack` and `disposeCrossDissolve` release only compositor-owned copies and quad resources; `mountViewer` calls both when ending its renderer. Structural products choose one full-weight dominant layer, with incoming winning a tie, and never enter the beauty byte operator.

`renderAutoMovieFilmFrame(renderer, layers, pass, renderLayer)` connects that composition boundary to already sampled source records. The callback receives the original sample fields and the selected pass; use `renderAutoMovieScenePass` to draw its scene under reversible renderer environment and material-pass state. Isolated source captures use the same scene-pass call, so a delivery host never compensates exposure separately for a transition. Supported highp Float32 interpolation can differ by one opaque byte from Float64 delivery at rounding thresholds; weight-one, endpoint and identical opaque-source pictures retain exact identity. A bound offscreen destination must be complete and expose actual native unsigned-normalized RGBA channels of at least eight bits each, or homogeneous RGBA16F/RGBA32F storage. Integer, signed, missing-channel and lower-precision destinations refuse before source callbacks. Its native encoding selects the inverse transfer needed before automatic sRGB storage encoding, independently of a texture's label. Target, cube face, mip and both configured and effective raster state are preserved.

For transparent straight RGBA delivery, draw into an unassociated color target and capture its bytes. A premultiplied RGBA8 canvas is a presentation product: straight PNG extraction can lose substantial RGB precision at low alpha and must not certify that delivery product. Compare its associated bytes or its appearance over the declared opaque background, and record the actual alpha/storage contract. `readAutoMovieFilmDisplayTextureResidency` reports each live fade/dissolve owner's three RGBA8 copies at the current drawing-buffer extent for budget hosts. Failed drawing restores the complete previous canvas beyond a clipped viewport, and failed resource listeners cannot prevent independent scene or renderer restoration.

`mapImportedHumanoidBones` maps a loaded glTF/VRM scene onto a compiled proxy skeleton before `createImportedModelObject` wraps it. Production hosts therefore render and review the final registered mesh while engine validation continues to use deterministic proxy geometry and measurement data.

`buildInstancedInstanceSet` and `regenerateInstanceSlot` render general crowd, vegetation, prop, and debris chunks with seeded scale, palette, numeric traits, frustum culling, and automatic LOD without scene-node expansion.

The support patches from `buildSpaceObject` are structural guides for depth, mask, normal and outline passes. They write neither beauty colour nor beauty depth. Author a visible floor separately as physical geometry such as a slab, terrain or platform.

`@automovie/viewer` renders authored `@automovie/interface` models, poses, motion and expressions through Three.js, using the FK and interpolation results from `@automovie/engine`. Playground owns editing controls and example parameters; Viewer owns reusable playback, inspection and capture.

Promoted heroes remain owned by the host.

Pass the runtime's `describeTextureSources()` rows into `IAutoMovieRenderTextureResidency.runtimeTextures` when assessing the context's budget. These facts describe all retained, reachable gait tables from their actual decoded textures, including takes that a later seek may upload. The conservative byte bound is distinct from the currently uploaded texture count, and the released runtime reports no table rows.

## Asset paths

`buildModel` admits three model paths:

- Primitive parts use engine tessellation and ordinary `THREE.Mesh` objects.
- Mesh parts with `skin` and a null `attachedBone` use `THREE.SkinnedMesh` bound to skeleton bones.
- An `attachedBone` takes precedence: the complete part attaches rigidly under that bone, including when a skin payload is present.

The host loads glTF through `GLTFLoader` and its asset resolver, then supplies the root object, normalized bone map and expression targets to `createImportedModelObject`.

## Playback order

`AutoMoviePlayer.update(seconds)` performs these steps in order:

1. Sample pose and expression at the same time with `sampleMotion`.
2. Apply the selected ROM clamp and spring follow-through.
3. Update bones and root through `applyPose`.
4. Update morph targets or the VRM expression manager through `applyExpression`.
5. Invoke `afterAutoMovieFrame` with `deltaSeconds` when the hook exists.

This order keeps the imported VRM runtime's `vrm.update(dt)` on the same frame clock as AutoMovie pose and expression.

## Playground boundary

Playground owns the Human editor pages and the resident inspection application's buttons, document selection and example parameter sets. Viewer exposes the reusable numerical transport, GPU viewports and capture operations they call. The [Playground run guide](../playground/README.md#run) distinguishes the resident inspection command from the ordinary Vite editor pages.

`stickman.html` and the film/impact routes exercise motion playback. Human display and control checks use the actual Human application and its current numerical source; success on an unrelated route cannot establish Human recovery or appearance.

## Development checks

`pnpm run build` compiles with source correctness lint. `pnpm run evidence` independently checks the declarations' engineering-principle checklist answers with `@wrtnlabs/evidence`, then runs the native source evidence guards.

`requiredAutoMovieMaterialTexturePurposes` in Engine identifies implicit SSS, overlay normal fallback and rectangular-light lookup consumers. After building the actual scene, call `readAutoMovieMaterialTextureSources({scope, renderer, scene, retained})` and pass its rows into `textureResidency.runtimeTextures`. The shader factories publish the actual Texture they bind; LTC selection follows the host float-linear extension. Each row follows one actual Texture wrapper, while Engine shares equivalent Source/upload-key storage. Reobserving that wrapper updates its current state rather than retaining a native key released after upload. For an upload-transition peak, separately include the observed previous phase as an explicitly conservative union until its native release. Retain removed wrappers from this same renderer and prune them only after actual texture/context release. Current consumer labels are refreshed independently of retained storage facts. Other live scopes supply observed `areaLights` and shared-policy `shadowCasters`; omission cannot certify their required lookup or shadow closure.

The metadata source reader reports `allocationStateKnown: false` when manual mip history or native layout prevents current properties from identifying stored allocations. The closure preserves null bytes and null cardinality, keeps candidate users attributable, and preflight refuses both required metrics. Equal current flags are not native-handle equality: the SDK can mutate a generation flag while retaining a different key. A normal caller sets `needsUpdate` after changing texture properties and retains previous phase facts until actual upload/release; property observation alone proves no retirement. `sumAutoMovieRenderTextureAllocations` in Engine preserves these null counts and unsafe aggregates, with legacy omitted counts meaning one.
