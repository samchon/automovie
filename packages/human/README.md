# @automovie/human

Numerical human construction and editing. The package evaluates connected face and body bases, one-skin person generations and component-based procedural faces. Shared source assets belong to the application; replay uses numerical documents rather than photographs or a fitting runtime. Procedural facial construction uses millimetres and converts once at the model boundary. Connected sources use metres. Both declare +Y up, +Z anterior and anatomical left +X.

Optional numerical hair cards and skin-following eyebrow ribbons belong to the same static facial asset.

The eye component under `face/anatomy/eye` separates shape contracts (`IPortraitEyeShape` and its records under `structures`), copied input admission (`resolvePortraitEyeInputs`), transverse tissue formulas (`portraitEyeLidRows`), shared ring attachment (`appendPortraitEyeMargins`), optical shell construction (`buildPortraitEyeCornea` over `buildPortraitCornea`), final skin contact (`createPortraitEyeSurfaceContact`) and refined interior construction (`buildPortraitEye`). `createPortraitEyeComponent` orchestrates their fit/attach/finish lifecycle. Both skin constraints and emitted lid rings call the same section calculation; drawing and contact call the same optical shell builder. Upper lashes (`face/anatomy/lash`) and eyebrow fibres (`face/anatomy/brow`) are built against the refined lid and forehead skin by `buildPortraitEye`. Keep those numerical owners shared when adding a shape control, and test section arithmetic separately from whole-face fitting.

Node consumers require Node 22.23.2 or later. Older Node 22 loaders can expose an unevaluated ES-module dependency when a CommonJS package and an external ES-module glTF reader share the same import graph. Consumer import order must not be used to mask that runtime defect.

## Face documents and editing

### Anatomical parameter contract

`IAutoMovieHumanFaceAnatomicalParameters` is the type-first contract for a future measured editor. Its nested component types name neutral craniofacial, neck, ocular, brow, lash, nasal, cheek-compartment, layered soft-tissue, oral, primary/permanent dental, tongue and auricular measurements; scalp and facial hair biology, optical appearance and performed motion have separate owners. Individually observed jaw and eye motion capacities are distinct from a requested pose, and simultaneous endpoint motion still needs joint validation. Performed expression has measured displacements and separately named FACS appearance categories with ordinal intensity, not artist morph weights. The dental stage and jaw reference agree at type level when dentition is known. Clinical skin-condition grades keep each facial region and its own validated observation scale, including distinct resting and maximum-contraction upper-face lines; they are ordinal observations, not millimetre wrinkle controls. Hair biology includes measured scalp regions and categorical whorls, while numerical parting, gathering, bangs and regional flow compose without authoring individual guides. JSDoc states units, landmark pairs, sides and acquisition limits. Missing values remain unknown. The type admits no personal vertices, free curves, groom guides, card lists or mesh references. Its source references include the [3D Facial Norms measurements](https://pmc.ncbi.nlm.nih.gov/articles/PMC4841054/) and [3D landmark-definition study](https://onlinelibrary.wiley.com/doi/full/10.1111/joa.12407); each component documents its additional primary source.

Lower-eyelid bag contributors distinguish orbital-fat prolapse, orbicularis thickness, skin laxity and transient fluid from an infraorbital hollow. Oral shape distinguishes Cupid's-bow peak geometry, tooth crowns, the palatal vault and contrast-CBCT oral space. The latter protocol requires lower-incisor contact and cannot be supplied for an edentulous jaw. Observed regional skin colour uses calibrated D65/CIE L*a*b* measurements; authored PBR linear RGB albedo has a separate appearance owner. The connected editor still consumes `IAutoMovieHumanFaceBasisDocument`, whose 151 shape coordinates are basis-authored weights. Registered anatomical targets and observations have separate current consumers, described below; this does not interpret the complete parameter tree as geometry. A future resolver must measure matching landmarks on the exact shared basis, establish supported physiological and population domains, solve the coupled inverse without losing independently authored detail, and validate the rendered surface before offering a field as editable. The schema alone does not certify an anatomical range or a likeness.

### Connected facial priors

Connected documents now author skin reflectance numerically. `materials` stores linear RGB and roughness. Optional `skin` maps shared basis surface IDs to compact `IPortraitColourField` arrays: named neutral-space centres and radii in metres, RGB gain and strength. The builder evaluates the common C2 compact-support field on reference vertices and transports its colours through shape, expression and UV/material separation. No individual skin image is loaded. Omitted/null/empty records add no buffer; an empty array gives its surface white multipliers. Fields narrower than the source vertex spacing need additional sampling before fine detail can be claimed. The editor's **Colour and surface** section edits global values through the same transaction and undo history; the **Pigmentation regions** section adds, renames and removes fields and edits centres/radii in millimetres, linear RGB gains and strength. Both sections preserve the numerical document and share undo/redo.

Connected `hair` now accepts `IAutoMovieHumanFaceHair`, whose layers contain numerical growth, length, styling and finish parameters. A basis surface supplies shared `hairDomains` and optional query-only `hairContactClosure`. `createHumanFaceHairBuilder` samples owned neutral area correspondence, seats the same barycentric roots on the current surface, integrates metric curves against a closed signed-distance query and meshes those exact stations. The first curve bend establishes a strip's initial transverse plane; minimal rotations transport it thereafter. Colour and fibre pixels are generated from numerical finish inputs. Generated guides, private bitmaps and personal resource keys are absent from this document schema.

Optional `rootRegion` localizes a layer's roots with six Gaussian coefficients, `center` and positive `spread` triples in neutral metres. Count remains the requested number of accepted strips, with relative density weighted over the shared scalp and hairline. The editor exposes **Localize roots** and each metric coefficient. This supports separately placed populations with independent lengths or curl; `part.region` independently limits the combing field. Rejected candidates retain their original sequence identities so common roots keep their seats and variation after an edit.

Optional `guides` turns a layer into a hierarchy: `fraction` of the roots, chosen by their own sample identity, are integrated through the fields and surface contact as guides. The remaining roots blend their nearest guides on their own side of the part (`interpolateHumanFaceHairStrands`). Each strand grows its own canonical rooted transition before its interpolated remainder is projected. Placement must preserve the post-interpolation metric length and the free-chord bound within the existing rounding allowance; otherwise the same metric walk continues that root. A previous hierarchy measurement built three published subjects 2.2 to 2.5 times faster with an eighth of the roots as guides and no ribbon vertex inside the skin. That timing does not cover the increased fallback that a stricter launch and metric check can require. Optional `clump` in [0, 1] gathers a placed strand toward its nearest guide, nothing at the root and that fraction of the way at the tip. A strand returned to integration uses the authored regional field instead. The playground's **Guide hierarchy** toggle exposes the fraction, neighbour count and clump.

Optional `gather` makes a tied hairstyle from the same numerical layer. An anchor specified by polar and azimuth angles is ray-attached to the shared scalp and follows shape edits through that triangle's barycentric coordinates. Curves descend a current-surface distance field to the authored tie radius, then continue along a tail direction. Optional `tail.spread` gives a target tube radius and a metric transition reach; stable root-sample coordinates distribute the locks through that cross-section. The tie is an event in each curve, so gathered layers integrate every root and refuse a guide fraction under one rather than blending mismatched pre- and post-tie intervals. Unreachable ties and too-short lengths refuse. These controls create no personal strand or guide asset, and the result still needs front, quarter, profile and back review: the shared generator does not infer a hairstyle or accept photographic likeness by itself.

`humanFaceHairEmergence` supplies a unit direction above the scalp tangent plane at an elevation chosen from the root's cited range (`humanFaceHairEmergenceRange`). The convention is 30 degrees in the mid-scalp and 15 at the frontal hairline, with the shared hairline ramp between them: the lower ends of the surgeon placement guidance in Shapiro & Shapiro (2013), used as conventional targets rather than population measurements or biological bounds. The upper end is the same blend of that guidance's range tops (45 and 20 degrees, the Shapiro & Shapiro 2013 range top). `integrateHumanFaceHairCurve` keeps the convention wherever the root's stem is admitted, so such roots are unchanged; only when the stem provably cannot clear the skin from it (a named stem refusal under the construction curvature) does the root rise, to the smallest admitted elevation the bisection of that interval visits. If even the range top refuses, the root refuses by name with every elevation tried. The direction always follows the combed field's tangential part, because the guidance gives no tolerance for the authored azimuth; a field without that part leaves the hair on its normal. Temporal and occipital figures are not modelled separately.

[createHumanFaceHairCurveStart](src/face/anatomy/hair/createHumanFaceHairCurveStart.ts) supplies the initial field direction and the caller's exact metric/contact instance. `integrateHumanFaceHairCurve` preserves that direction on its first discrete chord, then grows a curved rooted transition against the current host before the ordinary free walk. [createHumanFaceHairExteriorInterval](src/face/anatomy/hair/createHumanFaceHairExteriorInterval.ts) certifies each rooted chord on the same closed collider and original sampler support. Root tangency does not require an entire straight ray to reach the free clearance. The derived `freeFrom` index marks the first full-clearance station; all rooted stations are meshed, and simplification starts only in the free remainder. The rooted rows subdivide the existing surface attachment, with their positive width limited by the actual skin gap. This is a ribbon coverage proxy, not a measurement or replacement of shaft diameter or buried follicle anatomy. Free rows keep the existing requested-clearance fit and free chords retain the half-step margin. Stem and free distances both spend the same total metric, while the gathering clock follows their actual cumulative distance. A blocked exterior step, insufficient metric or exhausted count refuses with its cause.

Before a scalp tie is entered, the requested direction remains the normalized ordinary/gather direction blend. Geometric transport uses the actual first-free skin offset as a derived datum and advances its requested normal intent by actual chord metric. Strength continuously corrects only offset residual: zero and already tied tails retain their ordinary path, and flat-surface normal motion is preserved. Rooted trials read current and predicted contacts before admission; a changed contact can supply a two-normal outward goal under the same turn bound. Every actual station still needs its original exterior/floor and source/Float32 coverage proof, without a new authored waypoint, host-support exception or budget.

Direct `integrateHumanFaceHairCurve` callers supply `raycaster`, original sampler `rootBoundary` and a caller-owned `budget` alongside the signed query, all from the same current collider. Returned curves and rooted handoffs carry required boundary metadata; missing or malformed metadata refuses rather than being guessed by the mesher. These are derived numerical context, not new hairstyle document fields. A non-guide attempts its interpolated remainder after the same canonical rooted transition; rejected placement resumes that one walk with its remaining budget rather than starting the root again. The immutable-ray `launchHumanFaceHairCurve` remains a numerical ray query using the same exterior-interval owner, not the anatomical definition of the entire rooted transition. Hair-to-hair contact and physiological validity require separate qualification.

Direct `buildHumanFaceHairMesh` callers also supply the same source and Float32 resident separation readers, each curve's remaining budget and its original sampler attachment. [fitHumanFaceHairRibbonRows](src/face/anatomy/hair/fitHumanFaceHairRibbonRows.ts) qualifies complete transverse rows and swept convex cells in both representations. It keeps the centreline, paired rows, UV stations and nominal density coverage, and fits the actual positive row widths where the whole surface requires it. Outside corners alone do not prove a ribbon interior clear. Root fans require the original canonical seat and bounded contact on its incident supports; every other host face remains subject to strict separation. Non-root stem cells require strict positive separation and free cells retain the requested clearance. Unsupported centre chords, collapsed represented widths and exhausted shared budgets refuse. The emitted positions determine the fitted width; the nominal density width cannot stand in for that measurement.

`limitHumanFaceHairTurn` uses a 6 mm reference radius as a numerical regularizer: the requested direction turns at most `h / 0.006` radians for a nominal metre step `h`. Loussouarn et al. (2007) classified washed, dried 6 cm hairs by two-dimensional curve diameter and other descriptors; the below-1.2 cm class boundary does not establish a minimum local radius or a biological maximum curvature. Contact projection and shortened steps can change the realised polyline, so its actual chords and turns are verified separately from this direction rule.

A ribbon has no authored width. It stands for the whole neighbourhood of one root, so `humanFaceHairDensity` measures the scalp that root is responsible for from the population's own local density: with `d` the distance to a root's fourth neighbour, the density is 3 / (pi d^2) and the ribbon is `d sqrt(pi / 3)` wide, falling back on the area the sampler accepted over the population when a layer is too small to have neighbours. On the published documents that reads 8.1 mm where a fixed 4 mm was authored, and roots thinned by a hairline or a root region widen their ribbons exactly as far as they thinned. The fibre path is no longer paid for the ribbon either: `humanFaceHairContact` keeps half a sampling step and the requested clearance, which lowered the published hair from 4.0 mm to 2.0 mm above the scalp, and `buildHumanFaceHairMesh` instead measures each ribbon's own corners against the same surface and narrows the station where they would enter, both sides together so the ribbon stays centred on its fibre. A half width within the station's own free distance less the requested clearance needs no query, since the nearest surface point is that far away. Thinner hair is a smaller `count` or a lower `finish.coverage`; there is no width to widen until gaps close.

`finish.grey` paints a greying head as the admixture it is. Greying is a follicle's own switch, so a greying head carries white fibres beside pigmented ones rather than one faded colour (Tobin & Paus 2001; Jo et al. 2018), and the largest fibre-level survey classified its 3,343 hairs as pigmented or white against a black-and-white card (Van Neste 2004). The proportion in [0, 1] is how many of a card's painted fibres are left unpigmented; each takes one side of that switch by its own coordinate, and the unpigmented fibre is painted thicker, 67.68 against 57.41 micrometres, as that survey measured. The finish's `color` is then the pigmented fibre's own colour, the base finish becomes the unpigmented one, and the scalp under the hair sees the mixture. A fibre part-pigmented along its length is documented but has no published frequency, so none is invented. Greying runs temples first and the occipital region last, so a head grey only at the temples is a layer of its own with its own `rootRegion`. Omitting the field paints every fibre pigmented, byte for byte as before.

Optional `iris` gives each articulated eye its own pigment: `{ left, right }`, the subject's own eyes, each an `IPortraitIrisPigment` with the constructed portrait eye's band meaning (`base` is the limbal ring, the stroma takes `base + (i/7) * variation` along deterministic radial fibres). The basis eye texture paints sclera, iris and pupil together, so a material colour could only tint the whole eye; `createHumanFaceIrisPigment` instead repaints only the anatomical iris disc. It finds each globe as the textured region fully bound to that eye owner, takes the optical axis from the corneal protrusion over a two-pass sclera sphere fit (`locateHumanFaceIrisDisc`), sets the limbus at asin(11.71 / 24.2) from the adult visible iris and globe diameters and the pupil at a 3.5 mm light-adapted diameter, rasterizes the disc's texels through the neutral surface (`rasterizeHumanFaceIrisTexels`) and paints them (`humanFaceIrisTexelColour`), blending both edges over 0.3 degrees so the sclera keeps its painted detail. The texture is decoded and re-encoded by `decodePng` and `encodePng`; the first pigment costs about 0.7 s on the published basis and a repeated pigment reuses its bytes. Omission or null leaves the texture byte for byte. The editor's **Iris pigment** section adds, edits (both eyes together or one at a time) and removes the field. The pigments are authored colours under the renderer's light, not reflectances recovered from a photograph.

Optional `eyes` gives each eye independent optical dimensions through the connected optical generator, and `lashes` selects independent upper/lower shaft populations through the connected lash generator. Omission preserves resident source globes and cards. Generated shaft counts, including zero, are authored populations rather than card vertices, follicle density or clinical acquisition. The person eye controls, worker, document history and save/reload consume these fields. Generation requires the applicable producer-qualified optical support and anterior lash-root registration; a basis missing that source support refuses by name. Historical registration records alone do not qualify a source for the current producers.

Optional `eyelids`, `periocularTissues`, `brows` and `ocularSurfaces` extend the coarse eye neighbourhood with independent lid section elevation/projection, periocular shell offset/thickness, brow shaft populations, medial caruncle/plica and upper/lower wet-margin dimensions. Their generators consume generation-qualified native skin stations, a forehead implantation band and an explicitly authored canthal support sheet. Shared skin identity precedes shape, pose, refinement and contact. Generated tissue shells and visible ocular surfaces undergo resting and performed optical-space admission; a penetrated resting shape is not a valid reference. Brow flow, shaft count and source painting remain independent. Station roles, support-sheet construction and finishes are source-authoring conventions; clinical histology, follicle eligibility, tear secretion and population ranges remain unknown. Source preparation, actual model/static readback and current rendered observations must qualify each generation separately. The existence of these generators does not certify a pending coarse source cage or whole-eye appearance.

Eye-region anatomical targets and observations retain the registered measurement and observation rules under `face/anatomy/resolution`. Their readers use the current optical, lash and source-landmark context. A source that lacks a required landmark, rule or registration reports that exact absence and refuses an unavailable target; a generated dimension does not establish independently measured personal anatomy.

Optional `anatomical` carries the face's measured record: `targets` (a registered measurement name and value in its unit) and `observations` (`IAutoMovieHumanFaceAnatomicalParameters`). The builder admits it before evaluation (`admitHumanFaceAnatomicalRequest`): every target names a registered measurement once with a finite value, and every supplied observation field resolves to its longest matching rule in `HUMAN_FACE_OBSERVATION_RULES`, kept as an observation compared with its measurement or refused by name (a non-permanent dentition, a tooth that is not erupted, a habitual-closure jaw reference); a field with no rule is refused. After posing, every measurement in `HUMAN_FACE_MEASUREMENTS` is read on the final Float32 surface and reported through `observeMeasurements`, as a value or the named reason it cannot be read (`missing landmark: <name>`, `missing rule: <name>`, `missing registration: <what>`). A target whose measurement reads unavailable refuses, and a pose beyond the record's own `motionCapacity.jaw` refuses. Only a target moves shape: the editor solves it onto the channels its measurement lists (`solveHumanFaceMeasurementTarget`, through the shared `invertHumanMeasurement`), and a measurement listing none is report-only. Omission reads nothing and changes nothing.

A material override may also carry `pigment` (the fibres' linear RGB albedo, each component in [0,1]) and `density` (a coverage factor in [0,4]) for a material whose embedded texture holds fibre coverage in its alpha, the brow and lash cards cut by a mask or blended. The source cards paint one dark brown for every subject and a colour override can only darken them, so `createHumanFaceFibrePigment` repaints each covered texel as the pigment times its luminance over the median luminance of the texels the card draws, held at one (a darker texel keeps its shade, the source's brighter coverage fringes take the pigment itself), sets the base-colour factor to white, and multiplies coverage by the density, so a factor below one thins fibres under the material's own cutoff. Omission leaves the card byte for byte; an out-of-range value or a material without coverage is refused. The editor's **Brow and lash fibres** section adds, edits and removes both values per card. They are authored colours under the renderer's light, not reflectances recovered from a photograph.

Under a hair document the scalp takes the hair's colour (`createHumanFaceScalpTint`): each growth-domain vertex is covered fully inside the hairline, ramps up across the 1 cm transition zone at it (`humanFaceHairlineCoverage`, the first 0.5 to 1.0 cm of the hairline in the hair restoration literature; the 2 to 3 cm often quoted beside it is the whole frontal hairline region) and follows the layer's root region, and the builder multiplies the skin finish toward the hair colour by that coverage as a vertex colour, clamped so a hair lighter than the skin leaves the skin. Nothing new is stored: the rule reads the hairline, root region and colour every document already has, so skin no longer shows between ribbons of dark hair.

The playground's **Numerical hair** section edits every layer field through the document transaction and history. Mean length scales the six canonical regional lengths by one ratio, preserving their authored differences. Adding a layer selects a resident shared growth domain. Strip count, static combing/lift and procedural fibre coverage are authoring quantities; they do not calibrate biological density or elastic mechanics, and the derived ribbon width states coverage, not a fibre's diameter. The free-strip clearance argument excludes root fans and hair-to-hair contact. Closed, oriented manifold queries do not prove that a deformed head is embedded or physiologically valid.

Each basis channel may carry a nonempty `description` explaining its authored sign and shape meaning. The connected editor displays it as text beside the endpoint's measured displacement. This metadata belongs to the shared basis. Compact documents save numerical shape, performance and appearance values. Source weights and descriptive names do not establish measured biological ranges.

`createHumanFaceComponentTree(basis, manifest)` validates a basis-specific nested anatomy map and returns an owned tree plus label paths. Every shape/expression channel, resident surface and appearance document field needs exactly one owner; shared skin remains one `Human` surface even when a child such as the nose or eyelid moves it. A stale basis revision, duplicate/missing owner or aliased node refuses. The manifest organizes authoring and does not change saved flat channel IDs, geometry evaluation or the appearance builder. The selected application's node owners are separate modules under `packages/playground/src/human/face/anatomy/`; a new source basis must supply its own map.

`createHumanFaceControlMap({ basis, map })` compiles disjoint groups of fine shape coordinates into a simpler authoring view. Calling the result with a shape record returns the current `controls` and a `resolve(values)` function. Resolution starts from that captured record, preserves each member's normalized residual and every unlisted coordinate, and refuses values outside the displayed feasible interval. Documents still store only fine weights. The transformation is an authoring coordinate system; it supplies no biological age calibration or anatomical acceptance of the basis.

`createHumanFaceBasisBuilder(basis)` compiles a caller-supplied `IAutoMovieHumanFaceBasis` once and returns a builder for compact `IAutoMovieHumanFaceBasisDocument` edits. The immutable basis supplies connected surfaces, sparse signed shape endpoints, expression endpoints, material regions and resident finishes in metres. Evaluation applies all channels in basis order, computes common normals, then separates material and UV identities. Preparation admits the neutral model's structure, materials and topology. Edits check channel/material domains, finite normals and the welded vertex partition; a changed partition takes the full model gate again. Document overrides cannot repair an invalid source palette. Authored endpoints do not establish physical joint motion or collision-free arbitrary combinations.

The builder's `createHumanFaceBasisPoseEvaluator` stage owns rest deformation, articulation, aperture-scaled closure, contact and common normals. `createHumanFaceBasisPoseCache` retains only the last validated shape/expression state. A skin, iris, material or hair edit with those same weights reuses the posed foundation; region meshes are still freshly gathered into caller-owned arrays. `createHumanFaceHairResultCache` retains one generated hairstyle for the exact pose and numerical hair values, returning owned copies across unrelated appearance edits. Shape/expression or hair-field changes regenerate it; every incoming hair document still passes admission. A generated result is certified only after complete model validation; a certified hit still validates the current base model and checks part/material identity collisions. The contact observer receives an owned copy so a consumer cannot alter a later cached report. These caches change neither saved documents nor the exported model.

`createHumanFaceBasisBuilder(basis, { occlusion: { rays, size } })` also bakes the evaluated face's ambient occlusion (`bakeHumanFaceOcclusion`), the first layer of the surface maps a document's own geometry determines: from every vertex of each opaque material whose meshes all carry UVs, `rays` cosine-weighted directions about its normal are cast from 0.05 mm off the surface to the model's bounding diagonal against every opaque triangle (the engine's `createAutoMovieMeshRayCaster`), and the share that escapes is rasterized over the material's UVs into a `size` square texture (four rings of seam filling) set as its `occlusionTexture`. A renderer applies it to indirect light only, so a lid crease's cleft, the mouth's interior, the nostrils and the ear's concha darken under the sky and fill light as a real head's do, while direct shadows stay the lights' own. The editor bakes it with 32 rays at 1024 texels, about 2.5 to 5 s for a new pose; without the option nothing is baked and the materials stay as they were. GLB export carries the map and its strength.

`createHumanFaceOcclusionCache` retains the baked images for one posed face in a fixed-option builder. The bake precedes hair generation, and document colour, roughness, iris, fibre and hair changes leave its opaque facial positions, normals and UVs untouched; they reuse the same image bytes in an owned map. Shape or expression changes replace the pose and rebake. Hair cards were never occluders in this AO stage, and cache reuse does not add them.

A basis may declare `landmarks` (the source's joint-cube centroids with their own sparse shape rows), an `articulation` (one mandible: pivot landmark plus condylar offset, unit axis, opening degrees with a coupled translation, protrusion, both laterotrusions and a sagittal translation limit; two globes: centre landmark and gaze channels, each an axis, degrees and an eccentric translation) and per-surface sparse `attachments` (`[vertex, weight]` rows per owner, the cranium as the complement). `createHumanFaceBasisBuilder` then evaluates the rest layer on surfaces and landmarks (`evaluateHumanFaceRest`), resolves the joint motions from the shaped landmarks (`resolveHumanFaceArticulation`), poses each attached surface by linear blend skinning (`poseHumanFaceSurface`) and only then reconstructs normals. Expression rows on an articulated basis are rest-space residuals over that motion, which is what the offline preparation measures from the source (`test/scripts/face-review/prepare-articulated-basis.ts`, with `unposeHumanFaceSurface` as the exact inverse). A mandibular arch or globe attached at unit weight is rigid by construction and on the arc at every fraction of opening; a document whose opening and protrusion together exceed the budget is refused by name. `summarizeHumanFaceArticulation` states the requested degrees and millimetres for an editor. Landmarks, weights, angles and translations are measured from the shared source and cited in the study receipt; they establish no clinical trajectory and no contact freedom, which the crossing census measures separately.

A basis may further declare `contact`: vermilion seam and incisal edge vertex pairs, a `closure` channel decomposed as a delta at the reference opening (the ARKit sense of `mouthClose`), a tongue `passage` rule, rigid `colliders` and `soft` surface budgets. Closure scaling reads the preliminary posed central lip aperture and the same pair posed with the closure rows at gain one (`measureHumanFaceClosureRatio`); because posing is affine in rest position, closure weight one brings the central pair exactly to margin contact and a fraction closes that fraction of the current aperture. An optional `contact.margin` registers the fissure's vermilion margin chains from commissure to commissure; the lower chain is solved onto the upper chain and any upper vertex left above the lower chain is lowered onto it (`createHumanFaceClosureGain`), so weight one leaves no point of either chain open while the mandible keeps the central gain, and a chain vertex beyond the lips' soft-tissue budget refuses by name. After the attached surfaces are posed, `resolveHumanFaceContact` applies the declared rest-clearance floor against the dental arches and globes, refusing excess beyond a surface's budget. Its oriented sheet query leaves rim features without a side. Final aperture pairs and the tongue's resident triangle/slab intersection are then measured on those corrected positions. A protruding tongue thicker than either final aperture refuses, naming the deficient channel and millimetres (`evaluateHumanFacePassage`). These are geometric admission rules; anatomical acceptance, whole-skin orientation and self-contact remain separate obligations. The builder's `observe` callback delivers each successful build's `IAutoMovieHumanFaceContactSummary`: final apertures and passage, preliminary closure ratio and resolution counts. The preparation (`test/scripts/face-review/prepare-contact-basis.ts`) owns the source pairs, collider closures, decomposed rows and budgets.

The package root and `face/basis/evaluateHumanFacePassage` subpath keep exporting the symbol; the compact document schema and `createHumanFaceBasisBuilder` inputs retain their signatures.

`clipHumanFaceBasisSurface` in the `face/basis/` subpath prepares an open neck boundary at a neutral Y plane. It shares edge intersections and affine endpoint stencils while retaining corner UV seams. Its region-local maps identify wholly retained triangles whose barycentric attachment coordinates remain usable. `interpolateHumanBasisSourceTriangle` in the `common/basis/` subpath evaluates one geometry, normal or attribute component from ordered corner values and two affine coordinates `[u, v]`. Inputs remain read only, with finite `u >= 0`, `v >= 0` and `u + v <= 1`; the implicit weights are `(1-u-v, u, v)`. Exact corners preserve stored values, and inactive-edge coefficients evaluate no unused difference. Nonfinite inputs and unrepresentable active arithmetic refuse. The caller retains the component's unit and frame, source compatibility and geometric validity.

## Layout: face, body and what they share

The connected anatomy dependency direction is `face -> common <- body`; `human/` assembles face and body into people. `face/` and `body/` are the two anatomies; `common/` holds what both need (material-region splitting, mesh normals and buffers, the PNG codec, the document text envelope, the glTF document and extensions, the endpoint-scale type) and imports neither. The two anatomies never import each other. `boundaries/element-types` in `lint.config.ts` enforces this at error severity, so a wrong-way import stops the build at its import line. `src/index.ts` re-exports the connected anatomies, common owners and person APIs, and the package exports `./face/*`, `./body/*` and `./common/*` subpaths symmetrically. Each anatomy keeps its static export in its own `export/` folder and its document reading and writing in `document/`; the body's `anatomy/` groups its types by what they declare (`identity`, `generated`, `articulation`, `measurements`) beside the regional folders. A file in `common/` is named for what it does (`areaWeightedNormals`, `float32MeshBuffers`, `createGltfDocument`, `encodePng`), not for the face prototype it came from, and `git mv` keeps its history.

## Body below the neck

A body document (`IAutoMovieHumanBodyBasisDocument`) carries its anatomical measurements in `anatomy?: IAutoMovieHumanBodyAnatomicalMeasurements`, the only saved place of each anatomical value. `admitHumanBodyDocumentAnatomy` admits only values a product path consumes: a path `HUMAN_BODY_EXTERIOR_TARGETS` binds (whose solving channel must then not also appear in `shape`) and the humeral and femoral sphere-fitted head radii. With an exact-basis registered source assembly, its declared internal quantity paths and protocols also have a consumer, and source-bound observations remain raw acquisition records without inferred shape. Without that context, unregistered observed values refuse as `acquisition-not-registered`; gap paths and other unconsumed paths retain their own refusals. `createHumanBodyBasisBuilder` solves the bound targets into channel weights before shaping (`resolveHumanBodyAnatomy`, remembered for the last authored weights and measurements), so the measurement holds however other weights change; a document without `anatomy` builds as before. The separate numerical request document of earlier revisions (`IAutoMovieHumanBodyAnatomicalDocument`, its tiers and generator revisions) is removed.

Each body build carries its independently owned `evaluatedDocument`, including the channel weights actually solved from its anatomical targets. The one-skin person builder reads this result for its body rest rows and face endpoint gains, so its skin uses the same shape as the body's rig and posed surface. The caller's authored target document remains the saved authority. The separate rest-skin measurement path resolves those same targets before evaluating its shape; it does not reinterpret observations as targets.

An optional `basis.anatomicalAssembly` supplies one registered anatomical rest graph and actual bone, muscle, connective and adipose source surfaces. `document.anatomicalMotion` addresses closed bone identities and named motion coordinates in degrees or metres; unavailable coordinates, conflicting authorities and unsupported source ranges refuse. The body pose resolver evaluates that source graph once, admits its public rest projection against the skin rig, and reads actual final-frame coordinates before skin and tissue consume the same result. Source tissues use the graph's named attachments and offline weights. `build.anatomicalRig` retains its paired bone frames and posed sites; final ground placement moves those frames and the rendered parts together. A source assembly currently requires its exact registered shape, and the complete internal measurement vocabulary is not yet consumed. Coarse acquired or authored surfaces remain distinct from tetrahedral solids and independently validated personal anatomy. An atlas source inventory or a connected callable alone is not a generated, registered or visually accepted whole-body source.

Static source-assembly assets require `createHumanBodyAssemblyExportQualification`, passed as the fifth argument to `exportHumanBody` or the third to `exportHumanPerson`. The writer binds original and compiled source digests, rights, authored registration, attachment accounts and unavailable clinical resolution to actual source-part intervals. Numerical JSON remains the editable authority. A model carrying anatomical source parts without the corresponding qualification refuses export; qualification does not establish physiological motion, skin fit or whole-body completeness.

`createHumanBodyAnatomicalInspection` reads a body document's head radii and places the target spheres at the neutral reference rig centres (`createHumanBodyArticularCandidateModel`); it does not infer a radius, and imaging radii are refused by admission because no acquisition centre or posture is registered. The playground's [body anatomy inspection](../playground/connected-body-anatomical.html) page edits a body document in its own worker (`createConnectedBodyAnatomyRuntime`), with apply, save/load and transactional undo/redo. A document whose anatomy holds bound surface targets shows the exterior report; one holding only head radii shows the spheres; one holding both is refused, as one frame is one inspection. **Export** writes only the observed static candidate through the existing exporter. The JSON remains the editable input; the GLB does not restore clinical provenance or whole-body anatomy. The same material-merged primitive carries opt-in source-part element intervals and candidate-only qualification. `readHumanBodyArticularAssetCorrespondence` reads these two namespaces from a decoded primitive; it preserves reference-rig-only provenance and unavailable whole skin/bones, rather than certifying personal anatomy. Assets without the body namespace remain legacy; present malformed or unsupported metadata refuses. This inspection is not completion of the anatomical generator, clinical cohort or connected-person acceptance.

`createHumanBodyExteriorTargetBuilder` (`source-conditioned-exterior/2`) reports every authored absolute surface target of a body document's anatomy that `HUMAN_BODY_EXTERIOR_TARGETS` binds (for example `surface.leftLowerLimb.foot.length` or `surface.trunk.bustGirth`). Each binding names a rule of `HUMAN_BODY_MEASUREMENTS`, the side it is oriented to, the one-sided source channel that solves it and a protocol sentence stating how the source-rest instrument departs from the cited survey definition. The body builder solves the bound targets along their channels in table order (`solveHumanBodyExteriorRequests` over `solveHumanBodyMeasuredChannel`), repeating the passes until every reading holds; when the passes stall on coupled channels, or one target is out of its channel's reach from where the others left the body, the bounded joint solver `solveHumanBodySimpleOffsets` solves every bound channel together within its reach (`humanBodyChannelReach`), and only targets the joint solve cannot meet either refuse (`inconsistent-measurements`, or the out-of-reach path with the inverse's message); the report then reads each instrument again on the emitted Float32 skin, and a residual beyond 0.05 mm refuses. Its source registration (`IAutoMovieHumanBodyExteriorReference`) names only the basis, the rest frame and the physical incidence mode: `createHumanBodyBasisBuilder(basis, { physicalSource: "native-indexed" })` registers the actual preUV indexed source with a content fingerprint; `"source-partition"` uses the supplied canonical generation and samples. The bare source-rest convention does not register an observed tape or scan posture, plane or site. Document admission retains raw observations only through the exact registered source context; unregistered observed values and unconsumed paths refuse before the build. The result separates a physical exterior candidate from `GeneratedAnatomy`, which `assembleHumanBodyGeneratedAnatomy` assembles from region resolvers that each name their parts' exact unavailable reasons (`missing-bone-landmark`, `missing-tissue-boundary`, `anatomical-variant-absent`, `acquisition-not-registered`); clinical skin and every named internal component remain unavailable. The anatomy inspection page commits exactly one articular or exterior report, retains the last valid frame after refusal, and replays its complete document through history. Static exterior export does not establish individual anatomical validation.

Foot length and horizontal foot breadth (ANSUR II 6.4.37 and 6.4.36) are `extent` rules: the caliper reading between the extreme skin points of the vertices dominantly weighted to the foot and toe bones, along or across the horizontal ankle-to-second-toe-tip joint axis, found on each shape's final skin. Named approximations: the rest foot is unloaded, the joint axis stands in for the Brannock device's long axis, and the breadth is the region's maximum rather than the slide set at the first metatarsophalangeal protrusion, which the source does not register. They are authored on the left and read on the right through `orientHumanBodyMeasurement`. `humanBodyChannelReading` gives a channel's instrument: its own rule, or the rule and side the target table binds a one-sided channel to (`footScaleDepthLeft` reads the left foot length), so the editor, the inverse and the exterior generator share one binding.

Knee height, midpatella (ANSUR II 6.4.57) is a `skin-height` rule: the registered `midpatella-right` skin point's height above the plane through the source's `joint-ground` cube, oriented to the left knee by its `midpatella-left` mirror. The point is fixed on the neutral body with about ±10 mm vertical ambiguity, which the source records; `upperlegScaleVert{Left,Right}` solves it, moving the knee between a fixed hip and foot.

Hip breadth and buttock depth (ANSUR II 6.4.51 and 6.4.18) are `extent` rules on the skin dominantly weighted to the pelvis bone, along and across the hip-joint line. Skin weighted to the thighs is left out, so where the survey's lateral buttock point lies on thigh-weighted skin the breadth reads short; the caliper level is not set to the buttock points, which the source does not register. Both are named approximations.

`measureHumanBodyGroundSupport` reads each foot's lowest posed skin point (the skin dominantly weighted to the foot and toes bones, `humanBodyDominantVertices`) against the horizontal plane through the shaped `joint-ground` landmark, the source rig's ground cube, or an explicitly supplied plane height. A positive gap is clear, a negative one through the ground; no landmark and no explicit plane answers null. The body and person editors' contact checks show this geometric reading without asserting pressure, balance or tissue contact.

Optional body document `groundPlacement: "lowest-foot"` keeps every joint angle and translates the whole performed body so its lowest foot meets the source-neutral ground plane. `placeHumanBodyOnGround` gives the static parts, unsplit skin and posed bone frames one translation, and the person builder carries the head with those frames. `groundPlaneHeightMetres` records that fixed plane for the support instrument, independently of shaped landmarks; leg-length changes therefore cannot move the requested floor. The shared body/person pose controls expose the choice through the existing transaction and history. Omission preserves the source-root pose, including intentional flight. This placement leaves a higher foot airborne and does not solve bilateral foot orientation, IK, balance or intersecting toes.

`HUMAN_BODY_MOTION_GAPS` names the lower-limb motions the connected rig cannot represent (knee varus and tibial rotation on a one-hinge knee, subtalar inversion and eversion combined into one foot turn, toe splay without rays); the body editor appends them to the affected axis notes.

A basis may declare toe ray phalanges beyond the humanoid set (`toeRays`, `AutoMovieHumanBodyToeBone`: two hallux and three lesser-toe phalanges per ray, after the source rig) and, per surface, a `toeSplit` dividing each vertex's whole toes weight among them by shares summing to one (on the few midline source vertices that carry both feet's toes weight, both sides' toes slots together). The humanoid toes bone stays the parent and common metatarsophalangeal driver. A document's `toes` rows pose phalanges relative to their parents (`resolveHumanBodyToeRays`: flexion about the horizontal axis across the phalanx, splay at the proximal phalanx only), within `HUMAN_BODY_TOE_RANGE`, a stated convention without a clinical source yet. Ray flexion is positive toward the sole (the clinical sign), opposite to the humanoid toes bone's source sign, whose positive flexion lifts the toes. Without posed phalanges skinning uses the toes bone alone, unchanged to the bit. The static body export carries no skeleton, so phalanges leave only through the skin they shape.

`createGltfDocument(model, { sourcePartIdentity: true })` opts into anatomy-free source model/part IDs and POSITION/index element intervals, recorded from the same prepared material members that form each final primitive. `readHumanStaticPartCorrespondence` admits the actual accessor partition. Omitted, undefined or false options leave this source-part namespace absent; legacy face/body/person models without physical correspondence retain their existing static bytes. `exportHumanBody(model, inspection)` additionally joins the supported inspector report in the same Document before the existing writer; `exportHumanBody(model, undefined, { sourcePartIdentity: true })` requests only the generic source-part namespace for an exterior, without articular qualification. The third option is closed and only true opts in. A one-argument body call leaves source-part and articular namespaces absent while preserving any supplied physical correspondence independently. Numerical document IO remains the editable input path.

Supplied `mesh.physicalVertices` is a separate source-pair/null incidence protocol. The standard static writer always preserves it in the `automoviePhysicalVertices` namespace and `_AUTOMOVIE_PHYSICAL_SOURCE` unnormalized Uint16 VEC2 accessor (low/high words of a 32-bit table reference), independently of source-part opt-in. `readHumanMeshPhysicalVertices` restores owned domain/safe-integer IDs and nullable legacy references from actual decoded accessors, refusing malformed versions, components, counts, source references or displaced aliases. The section instrument can consume these engine-resolved labels to close UV seams at the same final Float32 plane and seed without welding explicit contact points or changing geometry. Source IDs certify neither personal anatomy nor clinical posture. Input meshes without physical correspondence preserve legacy metadata absence and bytes.

`body/` evaluates a connected body basis, the complement of the connected face's triangles below the neck ring, in the face's frame (metres, +Y up, +Z forward, +X anatomical left) so the two bases meet by vertex identity. The shipped basis and its receipts live in the [connected body study](../../test/studies/human-body/connected-basis/README.md).

`body/structures/shape/` owns channel and corrective declarations; `body/structures/rig/` owns shape-dependent landmarks, public rig joints, couplings and pelvic rhythm; `body/structures/surface/` owns the one shared-vertex skin surface contract. `body/constants/simple-shape/` holds the ordered empirical term populations consumed by the simple editor tier. The committed connected-body study is the legacy external-skin basis. Optional acquired atlas candidates and anatomical source assemblies are separate augmented sources; public rig frames alone are not anatomical bone or tissue geometry.

`body/anatomy/shoulder/createHumanBodyHumeralHeads.ts` creates spherical articular heads from measured left/right millimetre radii or, only for the sampled adult age and stature range, a Utah shoulder CT population estimate. Each head follows its posed glenohumeral rig centre; the existing rig does not establish an individual's CT head centre or the shaft's anatomical frame. `body/anatomy/contact/measureHumanBodySpheresSkinClearance.ts` computes exact point-to-triangle skin room for these heads on an explicit contact check after ruling out self-crossed skin. This is a named internal component and a geometric fit reading, not a full humerus, scapula, muscle, tissue material model or contact deformation solver. No CT mesh or compressed anatomy asset is shipped.

`body/anatomy/lower-limb/createHumanBodyFemoralHeadsFromAnatomicalMeasurements.ts` accepts explicit radii for a future resolver of registered hip components. It reads each side's named target or CT/MRI sphere-fitted head radius, converts millimetres to metres and places a candidate at that side's posed hip rig centre. An absent radius produces no candidate, and no population prior is substituted. The observed radius retains its acquisition context, but the rig centre does not establish the individual's anatomical head centre. Independent centre registration and `measureHumanBodySpheresSkinClearance` on a skin checked for self-crossing are required before treating a candidate as internal anatomy. The connected skin builder and editor currently consume neither these candidates nor a registered femoral-head component; they remain an inspection API and do not resolve the femoral shaft, acetabulum, tissue thickness or hip contact deformation.

The body editor accepts identity-card and tape inputs in its simple tier and measured detailed targets in millimetres where a girth, breadth, height or landmark-distance rule exists. It solves a target against the current body and refuses unreachable or nonmonotone readings. Source morph endpoints without a physical measurement rule remain internal replay data; the editor no longer offers their RMS vertex displacement as a sculpt control. The legacy r16 basis still uses authored sparse surface targets internally. Its replacement by registered bone, muscle and fat components with shared-skin contact remains unfinished.

For hip, wrist, calf and ankle tapes with comparable protocols, the detailed controls show the 1st–99th percentile intervals of the [ANSUR II Army sample](https://www.army.mil/article/188601/) (ages 17–58, women and men separately). The [Army measurer's handbook](https://tools.openlab.psu.edu/publicData/ANSURII-TR11-017.pdf) defines those tape sites. These intervals describe that military sample; they do not reject a person's edit or replace the loaded basis's measured reach. Chest, navel waist, flexed arm and upper-thigh protocols differ from this editor's rules and receive no borrowed survey band.

A body basis has no head, so the simple tier reads stature (floor to the top of the head) and the closed volume its mass comes from on the whole person, through an `IAutoMovieHumanBodySimpleWhole` the caller supplies (`createHumanPersonSimpleWhole` reads a person's closed rest skin). It solves stature through the same bounded measurement inverse as the detailed controls, revisits height as mass and tape controls change the body and measures the final shape again. A shape corrective may bend the height response between source endpoints, so the committed stature is checked by reading the resulting body rather than by assuming a linearly interpolated morph weight.

`projectHumanBodySimpleShape` compiles one rest skin and landmark set for the selected tape measurements it reads back from a detailed document, and reads stature and volume through the whole-person reader; a selected tape the body cannot read refuses by name. `createHumanBodyMeasurementReader` owns that shared candidate; each inverse trial still compiles its own different candidate, so measured reach and refusal keep the same geometry as the editor's committed body.

`resolveHumanBodyDocumentPose` supplies the body editor's current-draft source-rig clinical readout without generating skin. It uses the builder's shape/corrective landmarks and pose resolver, admits both authored and actual post-pelvis coordinates, and retains the separate TT shoulder owner. These double-precision coordinates carry the engine inverse's finite and near-gimbal conventions; they establish no certified angular interval or personal clinical capacity.

Optional `thighGoals` requests source-reference thigh orientations only on a basis that declares the corresponding `sourceReferenceGoal` capability. `prepareHumanBodyReferenceGoalDocument` shares one goal-independent shaped rig and the pose owner's pre-pelvis reference with the existing converter, then feeds converted source rows into weights, correctives, pelvic coordination and final skinning. The person builder reads that evaluated body document. Exact zero remains a request distinct from omission; unsupported capabilities, competing source-pose authority and requested or converted range violations refuse. Saved JSON retains the original reference goals, while rest measurements remove performance goals. Source-specific geometry, shape-motion combinations and current rendered acceptance remain separate from this conversion.

A connected surface may opt into numerical rest-detail filtering through `mush: { iterations, blendWidth, spreadRings, spreadDecay }`. The sweep and ring counts are safe integers (positive sweeps, nonnegative rings); width is in (0,1] and decay in [0,1). `createHumanBodySurfaceMush` prepares the shared topology and a normalized skin-influence mask, holds open rims and samples with at most one distinct positive bone influence, then transports rest residuals between equally smoothed local frames. Its explicit tangent uses the first sorted neighbour; collapsed frames retain the posed sample. Output-rim pinning does not pin the intermediate smoothing operator. `createHumanBodyPosedSurface` filters the neutral shape's skinning and preserves the full corrected-minus-neutral skinning displacement on top, before sag; sag still reads the gravity derivative of pure skinning. Positions and normals are finalized before material-region and underwear projection. Omission retains the earlier path, and a document without public pose, shoulder or anatomical motion goals bypasses filtering. The published r16 basis remains without this option. This numerical policy neither establishes tissue mechanics, volume or clearance nor admits new physiological poses; an opted-in basis needs its own observation and derivative assessment.

`measureHumanBodyBasisChannels` uses one neutral reader for every authored metric it reports while evaluating each positive or negative endpoint on its own shape. This keeps the detailed editor's displayed neutral measurements about one physical skin without sharing a candidate across unlike endpoints.

`solveHumanBodyArmsDown` tests both lateral-plane arms at each whole-degree elevation from hanging down toward their rest goals. It keeps an arm at its first safe goal while the other continues and checks the combined goals for new cross-arm penetration before returning them. Contact can disappear and return as an arm passes different body regions, so the search does not assume a monotone contact response. The body worker yields between evaluated steps; the cost grows with the first safe angle.

`createHumanBodyBasisBuilder` retains each build's posed connected skin in `posedSurfaces`, one shared-position and normal array per basis surface before material or UV corners split. `createHumanBodySegmenter` compiles the admitted basis's dominant-bone and UV-corner partition once. The body worker and arm search reuse it across builds; segmentation checks that the render regions agree with that connected skin and copies its positions and normals into fresh contact parts and source maps. `segmentHumanBodyModel` remains the direct single-build entry. The partition reports which skin segments cross and does not create internal bone or tissue geometry.

`assertHumanBodyBasis` admits one immutable basis in ordered stages: unique names, channel/corrective endpoints, connected surfaces and material partitions, landmark endpoint correspondence, then rig and clinical ranges. The matching files under `body/basis/admission/` own those checks separately. This is representation admission; a legal body document can still have a contact or anatomical-form problem, which needs pose-space measurement and visual review.

A preparing body basis can retain its field registry while marking source-incomplete targets in `unavailableTargets`. Admission accepts only unique declared target IDs. Evaluation prepares the actual ordered channel/corrective gains and refuses every active unavailable target before writing any skin or landmark buffer; exact zero does not read that field. The error names the target, preserves caller edits, and permits recovery after the missing source is prepared. This describes numerical source dependencies, independently of anatomy, cohort or review status. Omitting the property preserves legacy behavior and certifies no complete source. A default-only candidate with these refusals cannot claim the original identity or pose range until its source derivatives and actual consumers are qualified.

Surface admission rejects nonadjacent triangle crossings in the neutral shared skin before UV or material regions are split. This does not certify every shaped or posed combination; the editor's contact reading and the full body census still inspect those states.

Basis names used as record keys also cannot collide with inherited JavaScript Object properties. The common identity check covers channels, landmarks, endpoints, surfaces, materials and regions before shape evaluation reads their named rows.

The body builder passes each shared surface through `createHumanBodyPosedSurface` for joint skinning and optional gravity response. `createHumanBodySurfaceParts` then computes normals and pose relief before `createHumanBodySurfaceRegionParts` gathers the authored material regions; underwear receives the same unsplit posed surface. These are processing owners for the legacy skin, not internal anatomical components or a contact solver.

When the rig distributes twist along a bone, `humanBodySkinDownDirection` derives the posed direction of rest-frame gravity from that position-dependent skin map. Its backward difference step follows floating-point error balance at the body's metre scale; it is not a softness or tissue thickness parameter.

`body/basis/appearance/` owns the body's material stage. `createHumanBodyAppearance` copies materials for each document and applies site colour before its detail, overlay and tone stages. `createHumanBodySkinDetail` owns the optional micro-normal map; `createHumanBodySkinOverlays` binds nail plates and requested veins independently and refuses a vein request without a declared vein layer; `createHumanBodySkinTone` owns age-dependent chromophore tone maps. Their generated texture caches belong to the compiled basis revision. The current UV repeat count uses the median physical UV scale, so local distortion remains to be resolved.

`IAutoMovieHumanBodyBasis` carries ordered shape channels with explicit left/right mirrors, correctives driven by channel sides, clinical joint ramps or thorax-relative shoulder orientation kernels (a family's kernels divided by their sum where it exceeds one, so a lattice of solved poses interpolates rather than stacks; the correctives of one pose solved on different shapes are shape examples interpolated the same way, so a mixed body wears a blend of its traits' corrections rather than their sum), landmark-pivoted joints with pinned ranges, and one or more connected surfaces with four-influence skin weights; a joint may spread its axial twist along its bone (`distributeTwist`, a continuous twist joint: the skin takes the parent-relative swing whole and the twist in proportion along the bone). The forearms declare a distal twist (`HUMAN_BODY_DISTAL_TWIST_BONES`, the engine's `AutoMovieJointTwistPlacement`): pronation and supination turn the forearm about its own long axis after the elbow's flexion, so a bent forearm that twists keeps pointing where the elbow put it, and the skin's swing-and-twist split is the same composition; every other joint keeps the proximal order. `createHumanBodyBasisBuilder(basis)` admits the basis once (`assertHumanBodyBasis`, `assertHumanBodyRig`) and evaluates a revision-bound document in the order channels → correctives → landmarks → skeleton → pose → skin. The document stores only named channel weights, ordinary non-humeral clinical joint poses, optional thorax-relative upper-arm tilt-and-torsion goals (`shoulders`), an optional cheek albedo (`skinColour`) and material edits; an arbitrary vertex displacement is rejected. With a cheek albedo, `createHumanBodySkinColour` colours the skin material's regions by anatomical site: per-vertex multipliers of a base colour, each site's albedo a power of the cheek fitted over the International Skin Spectra Archive's group means (`HUMAN_BODY_SKIN_SITES`), and the neck's cut kept at the cheek's colour so the body meets the face. With a detail strength (`skinDetail`), the skin material takes a tileable normal map of the skin's micro-relief (`createHumanBodySkinDetailTexture` over `HUMAN_BODY_SKIN_DETAIL`: primary-line groove families and pores in micrometres), repeated over the source UVs at the layout's measured scale (`humanBodySkinMetresPerUv`) and deepening with age. A basis surface may carry an anatomical `relief`, a tangent-space normal map over its UV layout of the flexion creases and wrinkles its vertices are too coarse to carry; with a skin detail it becomes the skin's normal map and the tiled micro-relief its detail normal map. A posed body's relief follows the pose (`humanBodyReliefWeights` over `HUMAN_BODY_SKIN_RELIEF_POSE`): the skin regions carry per-vertex relief weights, so a bent joint's creases deepen on the side it folds toward and its wrinkles flatten on the side it stretches, smooth at the end of the range. A basis surface may also carry `overlays`, skin-material layers over its UV layout: a `nails` layer is the nail plates (a colour image whose alpha is their coverage, an optional normal map and a roughness), which the builder binds as a replacing overlay independently of skin detail of the skin at full strength, so the plates show their own colour and surface; with the cheek the image was drawn for, a document's cheek tints them by the palm's albedo against that cheek's, so they follow the person's pigmentation. A `veins` layer is the superficial veins as they show over the lean body its surface's `sag` declares: with a document's `skinVeins`, independently of skin detail, it binds as a tinting overlay at the veins strength times `exp(-attenuation · t)`, where `t` is the mean tissue the body carries over its lean self at the vertices the veins lie over, so a heavier body shows them less; the regions keep different tissue over their veins, so a basis may carry a veins layer per region, four layers in all per material. With a tone strength (`skinTone`), it also takes a tileable base-colour map of the skin's uneven tone (`createHumanBodySkinToneTexture` over `HUMAN_BODY_SKIN_TONE`): melanin and haemoglobin varying about the site colour by their absorbance at the three primaries, the base colour compensated so the site albedo stays the mean, less even with age. A shoulder goal gives its plane of elevation, total humerothoracic elevation and independent axial rotation, and is admitted inside the basis's humeral joint sinus: `humanBodyShoulderElevationLimit` reads the plane's maximum elevation from the periodic `[plane, maximum]` knots of `range.envelope`, and `humanBodyShoulderReaches` judges a goal by that maximum and the axial range, with the overhead pole judged by direction. `resolveHumanBodyShoulders` derives the humeral local transform after girdle motion so 180° total elevation stays overhead. `humanBodyBasisWeights` and `evaluateHumanBodyShape` share the measurement path. `resolveHumanBodySkeleton` forms rest transforms from landmarks, and `skinHumanBodySurface` applies each bone's `posed ∘ rest⁻¹` through a unit dual-quaternion blend. A surface may declare a soft-tissue sag (`sag`, `createHumanBodySurfaceSag`): the outward difference between the document's rest and lean exterior skins (the declared lean channel weights), times an authored softness, moves with the change of gravity's direction in the skin's frame, smoothed, zero at the rest pose and held at the neck's cut; it does not establish tissue thickness or contact. A pose corrective is a rest-space row fired before skinning. A basis may declare `couplings`: an upper arm's TT total elevation, or another joint's clinical swing-cone elevation, drives a bounded piecewise-linear addition to another joint's axis. `resolveHumanBodyCouplings` returns those additions, the builder validates their summed angles without clamping, and the editor shows them without writing them into the document. A basis may also declare a `pelvifemoral` rhythm: the legs' document flexion is then trunk-relative, `resolveHumanBodyPelvifemoralRhythm` turns the larger lift into a declared posterior tilt and scalar coordination increments (admitted by `assertHumanBodyPelvifemoral`). The builder turns only the pelvis about the bilateral hip line, then reads and admits the actual changed parent-relative source-rig coordinates; combined or oblique coordinates are not those scalar increments.

`measureHumanBodyBasisChannels` reports every channel's per-unit displacement and, for a channel with a rule in `HUMAN_BODY_MEASUREMENTS`, the girth, breadth, distance or height it measures at the neutral and at each end, so the editor prints `measureWaistCirc` as millimetres. `measureHumanSection` is the plane-cut instrument behind the girths: it reports the section's contour perimeter and its tape girth, the perimeter of the section's convex hull, which bridges the gluteal cleft and the inframammary fold as a tape does, and how far back its loop reaches; the girth rules read the tape girth, and the hip rule takes it where the buttocks stand furthest back, as ANSUR does. `segmentHumanBodyModel` partitions every built surface and material region by dominant bone for the crossing census, which counts segments against each other and each against itself (`measureAutoMovieModelCrossings` with `withinParts`); `solveHumanBodyArmsDown` lowers both arms in the lateral plane to the lowest elevation at which their chains cross nothing the rest pose did not, which the editor's Arms down preset runs in its body worker one step at a time through `stepHumanBodyArmsDown`, so a later edit interrupts it; and `exportHumanBody` writes the evaluated static body to GLB or glTF through the shared static writer, without a rig.

The simple tier, `IAutoMovieHumanBodySimpleShape`, is the numbers a person knows about a body: sex, age in years, stature in metres, mass in kilograms, a muscularity from -1 to 2 (2 the source's competition node), and optionally the tape measurements (waist, hip and bust girth, shoulder breadth). `expandHumanBodySimpleShape(basis, whole, simple, over?)` turns them into the detailed channel weights a document stores, and the detailed tier stays canonical: applied over an existing shape it keeps that shape's residue, so the same values change nothing and a detailed edit survives an age or mass change. The expansion is the numeric table `HUMAN_BODY_SIMPLE_SHAPE` (product-of-curves rows for the age, sex, fat and muscle effects, with their clinical sources pinned in the study) plus measured inversions along directions (`humanBodySimpleShapeDirection`): stature against the whole person's stature, mass along the weight macro, whose field covers the whole skin, through the whole person's closed volume at the age-specific Deurenberg fat estimate's density (the definition rows read that estimate less the fat-free mass the muscle adds, so a trained body reads an athlete's fat; the rows calibrated on adult training, and that fat-free mass, read the muscle as far as each sex's adolescent maturity has let the body build it), and each girth against its rule (`evaluateHumanBodyMeasurement`), together until the weights settle. `projectHumanBodySimpleShape` reads the same values back off any detailed shape. `humanBodySimplePosture(basis, simple)` gives the standing posture a body's age implies, as document pose rows: the thoracic kyphosis past the source body's young 25 degrees (to the 35 to 38 of adults over 65, Koelé et al. 2020), as flexion of the chest and upper chest, with the neck extending as much within its range so the head keeps its orientation. A value the basis cannot reach is refused with the reach. The millimetre measurement channels are the middle tier between the two and need no structure of their own.

A document may wear plain default underwear, `underwear: { style: "boxer-briefs" }` or `{ style: "bra-and-briefs" }` with an optional linear `color`; omitted, the body is built exactly as before. `createHumanBodyUnderwear` cuts it from the posed skin rather than simulating cloth: the regions are rules on the body's landmarks in `HUMAN_BODY_UNDERWEAR` (waistband and leg line against the pelvis, lumbar, hip and knee landmarks; the bra's band and straps against the basis's `nipple-left` skin landmark, lower chest, clavicle and shoulder), read on the document's body at rest, and the kept triangles are lifted 3 mm along the posed normals, after `closeHumanBodyUnderwearCreases` has carried them across every skin crease narrower than the table's `spanMetres` (the closing of the body by a ball of half that radius, so the fabric bridges the intergluteal cleft, the cleavage and the fold under a breast instead of following them down). The garment therefore follows every shape, pose and soft-tissue sag, and the builder appends it after the skin's regions as one part per surface in its own `underwear` material; the segment partition and the editor's contact reading leave it out. Where the skin itself folds through itself in deep flexion, the garment folds with it.

## Construction surface

`face/anatomy/` owns cranial and cervical continuation, cheeks, eyes and eyelids, nasal subunits and cavities, lips, dental arches and crowns, pinnae and material defaults. `face/build/`, `face/mesh/`, `face/surface/` and `face/export/` own construction orchestration, mesh operations, surface layers and static face export; shared basis and export utilities live in `common/`. Each definition states its units and admission rules. The root barrel and the corresponding `face/*`, `body/*`, `common/*` and `human/*` file subpaths expose the documented public surface.

`buildPortraitHead(host, components, rounds, layers, anatomy)` fits all selected components to the same input host, rejects overlapping cut ownership, joins their surfaces, subdivides common skin and resolves final contact. Optional `anatomy` selects cranial and cervical profiles. An empty component population leaves the host's facial skin intact. `createPortraitEyeComponent`, `createPortraitNoseComponent`, `createPortraitMouthComponent` and `createPortraitDentalComponent` receive caller-owned attachment bindings and shape values. Shape arrays are copied at admission rather than retained as mutable caller state.

`preparePortraitHead` owns the shared surface phase used by `buildPortraitHead`: fitting, attachment, continuation, refinement, surface layers, paired replacements, final proposals and reference colour sampling. Legacy finishers consume the same final surface during ordered output. The preparation boundary preserves resident IDs and exposes no collision-free or anatomical-validity guarantee. Reference coordinates serve colour sampling; they are not a physical tissue rest shape.

`blendPortraitSkin` resolves all component attachments together on the original host connectivity. Exact pins and skin outside geodesic reach form the boundary of a positive inverse-distance graph interpolation. Its sparse Dirichlet solver checks the original equation residual before returning and refuses numerical breakdown or exhausted convergence. It preserves the caller's arrays and attachment order independence. Residual tolerance describes equation satisfaction; ill-conditioned geometry can amplify displacement error. This interpolation does not infer anatomy or simulate tissue elasticity.

`nose` carries named nasal measurements only: `widthScale` and the optional `depthScale` (a projection ratio against the socket's three-point support plane), `tipProjection` and `alarProjection` (millimetres along host Z), the aperture's `nostrilWidthScale`, `nostrilHeightScale`, `nostrilRise` (millimetres) and `nostrilTilt` (degrees), the lining's `cavityContraction`, `rimSupport` and `cavityOffset`, the `rimRoundness` blend toward a fitted ellipse, and the skin `blendReach`. `resolvePortraitNoseShape` admits them and returns an owned copy. No input addresses a vertex, curve or patch: an earlier family of section grids, lobule ellipsoids, final-body stations and per-opening envelope profiles was removed because it let a caller sculpt the surface directly. A future measured nose (length, dorsal height, alar width, columella inclination) should convert its named measurements into these fields by a documented deterministic rule.

Optional `anatomy.performance` supplies the `IPortraitHeadPerformance` reference and pose callbacks. Reference coordinates form the cranial/cervical continuation; only appended vertices receive the pose. Both callbacks receive owned coordinates and must return finite XYZ in millimetres. Existing component vertices retain their current positions and shared indices. `buildHumanFace` connects this protocol to the jaw continuation field; direct assembler consumers may provide their own numerical field.

`eye.skinBridge: "sampled"` requires `skinAttachment: "reserve"`. Unequal ring populations retain each original ID, and the two authored rings must still have matching projected winding. `eye.upperLidProfile` supplies two through 32 complete medial-to-lateral sections for the margin, tarsal body, both crease banks, hood and preseptal transition. Every section has strictly ordered outward offsets, signed anterior projections and a farther live-skin attachment, all in millimetres. `createPortraitUpperLidProfile` uses the same order-preserving interpolation as `createPortraitLowerLidProfile`. These are visible-surface controls, not a muscle simulation or recovered tissue thickness.

Optional `eye.upperLidProfile.closedSections` supplies a complete, strictly ordered unfolded target for a fully closed eye. It uses exactly the same witness positions and attachment distances as `sections`. Selecting it permits the observed hood to return inward across the crease; the remaining stations stay ordered, and the hood remains between the margin and preseptal skin. The shared engine planar predicate rejects a crossed or touching transverse curve at authored and sampled sections. During performance the same named rows interpolate by `(blink - observedBlink) / (1 - observedBlink)`. Reopening past the observation extrapolates and must remain valid. No closed target means the prior ordered shape and performance remain unchanged. Both arrays are source-basis geometry; unilateral edits may retain or clear them but cannot author new sections. The section test is not a proof that the final subdivided skin, optical contact and surrounding head are collision-free; those still require an actual build and multi-view inspection.

`eye.upperLashProfile` opts into independent upper-lash shape. Provide all seven fields, for example `{ length: 7.5, elevation: 10, curl: 40, fan: 60, radius: 0.065, taper: 0.92, variation: 0.12 }`. Length and radius use millimetres; elevation, curl and fan use degrees; taper and variation are fractions. Length is the maximum centreline arc length, reduced towards the canthi and by deterministic per-strand variation. `upperLashes` retains control of count. The seven detail sliders become available once the complete profile is present, and independent side overrides use the normal eye-region path. `buildPortraitEyelash` also exposes this geometry for a caller-owned root. The launch angles describe the observed head frame. During lid motion, the current root stays on the final margin and the strand turns by the shortest rotation between observed and current globe-to-lid directions. Gaze alone does not apply this turn. This rigid radial attachment preserves length and thickness; it does not model torsion about the radial axis, hair dynamics or collisions between strands. Omission preserves the original short upper lashes exactly. This profile does not add lower lashes.

`eye.globeLift` places the optical body independently of the surrounding skin attachment. Positive millimetres move it along the normalized observation ray toward the recorded camera; negative values recess it. The lid's inner contact follows the globe while its outer attachment targets do not translate with it. Shared subdivision and final optical contact still adapt the emitted skin; this is not a promise that every surrounding vertex stays fixed. This differs from `socketLift`, which translates the socket and its skin targets together. Omission or zero retains the original fitted globe. The scalar editor exposes a signed authoring envelope, not a clinical range; combined geometry still requires construction and render inspection. Blink and gaze use the resulting identity centre rather than adding the depth again.

Final eye contact uses `portraitMinimumDirectionalSurfaceTargets` to minimize area-weighted squared travel against the resident optical support. The shared engine retains every clipped triangle condition and bounds each vertex by the previous conservative face-deficit correction. Distances use metres at this boundary; shared-skin propagation converts back to head millimetres. Closed margins retain their correspondence. The pinned [engine numerical kernel](../engine/vendor/quadratic/README.md) runs synchronously, including inside the editor worker, and refuses an incomplete solve. This is directional geometric contact, not a tissue model or a reconstruction of eyelid anatomy. Subsequent skin propagation and Float32 serialization still require contact inspection; neither solver convergence nor parameter input precision certifies anatomical accuracy.

`await exportHumanFace(model)` returns `{ glb, gltf }`: GLB bytes plus a glTF JSON document with its resident binary resources. It validates the actual Float32 output geometry and preserves supported optical material fields. The package owns both document construction and serialization, so these portable outputs work across CommonJS and ES-module consumers. Register `gltfMaterialExtensions` when reading the assets with glTF-Transform.

`createGltfDocument(model)` remains the low-level static document converter. Resident PNG data URIs in the base-colour and normal slots carry UV0, alpha masks and normal strength into the asset; external images, transformed texture bindings and other texture slots refuse. Normal RGB is linear tangent-space data. Export checks the PNG container header and positive dimensions; the receiving image decoder validates the compressed pixels. Its writer must use the same glTF-Transform module instance and register `gltfMaterialExtensions`. Mixing CommonJS and ES-module Document/writer instances can silently lose geometry; prefer `exportHumanFace` unless the application deliberately manages that boundary. Both routes refuse bone bindings and unsupported resources; neither is a general scene or animation exporter.

### Surface hair and eyebrow cost

`recipe.hairLayers` carries up to eight additional source `{ id, profile }` populations; `detail.hairLayers` may copy those exact cards, add a guide-free layer or clear the population while changing numerical styling. Each `IPortraitHairLayer` has a unique nonblank id and a complete `IPortraitHairShape`, so dense inner coverage and fine outer locks can use independent guides, coverage, pigment masks and normals. `buildPortraitHairGroom` assembles these layers with optional legacy hair, and `buildHumanFace` calls it directly. Additional parts use `scalp-hair-layer:<id>` and finishes use `human-hair-layer:<id>`; resident collisions refuse. A layer's base finish must belong to the input palette, never to a preceding generated layer. Empty profiles emit nothing but still validate their settings. The limits bound authoring cost, not biological density.

Select `hairLayers` and a named layer in the editor to adjust that profile through the existing hair scalar controls. `setHumanFaceHairLayerDetail(document, layerId, "hair.coverage", 0.8)` writes one field into a complete additional-population override while preserving the other authored profiles, guides and omitted fields. Applied profiles display normal strength zero, taper start zero and shade strength one when omitted; those display defaults are not written into unrelated layers. The `hair` region still edits the separate legacy owner. Individual layer scalars do not have an inheritance button because array inheritance restores the whole population.

The complete-region JSON editor may retain source guides, add guide-free layers or clear the additional population; it cannot introduce new card guides. Arrays replace completely, `[]` removes only additional layers, and inheritance restores the basis. Appearance controls expose each named resident base finish used by either population; sharing a base intentionally shares those base colours, while the layers' generated masks remain independent. Layer ordering does not change either layer's geometry or finish values. Omitted layers preserve the existing single-profile output.

Numerical setters detach containers along the edited path. Reusing one JavaScript profile object for several layers, sides or the basis does not link their edits: changing or removing a field on one owner retains every other owner's authored values. Shared material identities still intentionally refer to the same resident finish.

`hair.fibreShadeStrength` separates the procedural RGB pattern from the base finish's pigment. Omission or one preserves the original PNG bytes; zero uses white RGB without changing alpha, normals, guides or triangle count. Intermediate values interpolate the encoded RGB pattern towards white, not physical pigment concentration. The hair-region scalar editor and portable document preserve the [0,1] control. `createPortraitHairTexture` accepts the same strength as its fifth argument. Reducing it can retain pale hair colour without filling the gaps between fibres; it does not repair the groom or simulate light scattering.

`recipe.hair` supplies the complete guide-bearing `IPortraitHairShape`; `detail.hair` may vary scalar styling, inherit source cards by omission or clear them. Each `IPortraitHairCard` has root-to-tip guide stations, paired transverse width directions and an authored width in head millimetres. The author places those guides against the current scalp; changing cranial proportions requires inspecting and refitting their attachments. `buildPortraitHairCards` emits two triangles per longitudinal interval regardless of painted fibre count. Width, tip taper, coverage and segments have scalar editor controls; the complete guide array belongs to the immutable source recipe. An empty card array removes the hairstyle, while omission adds none. The supplied finish must exist and the derived `:hair-cards` finish identity must be free.

`createPortraitHairTexture` creates a deterministic 128 by 256 PNG with multiple painted fibres, sparse roots and staggered tips. The builder embeds that mask without a source photograph, network request or native image library. This is a bounded static card renderer, not a physical hair-scattering model, dynamic strand simulation or automatic hairstyle fitter. Inspect the front, sides and back for scalp gaps and card intersections.

`hair.fibreCurl` opts into a 512-square curled-fibre alpha and normal pattern. Supply all three values, for example `{ amplitude: 0.16, cycles: 4.8, aspectRatio: 0.57 }`. Amplitude is the maximum transverse excursion as a fraction of UV width, cycles is the nominal wave count along UV length, and aspect ratio is the nominal card width divided by its length for the normal direction. Seeded fibres vary their phase, amplitude and frequency. These are pattern controls, not measured hair diameters or a physical scattering model. Different card proportions can require different authored profiles; one nominal aspect does not infer every guide's metric. Zero amplitude or zero cycles can describe a straight pattern, but only omission preserves the original mask bytes. `assertPortraitHairFibreCurl` admits complete profiles, including for empty grooms. The hair-region editor saves the complete optional profile and exposes its three scalar controls once present. Pattern edits change rendered coverage and shading without adding triangles or changing the authored guides.

`hair.taperStart` holds a lock's full geometric width until the authored root-to-tip fraction, then narrows it linearly to `tipWidth`. Its [0,0.95] envelope leaves a positive taper interval. Omission or zero preserves the earlier full-length taper. A later start keeps the body of long hair covered without changing the root width, guide, UVs, painted mask or triangle count. The scalar editor and complete hair region both retain it; this control does not repair incorrect guide paths or an unsuitable hairstyle silhouette.

`hair.fibreNormalScale` adds a scalar editor control in [0,1]. `createPortraitHairNormalTexture` derives a linear RGB normal PNG from the same fibre centres and radii as the colour mask. Positive strength replaces the normal binding on the owned card finish; zero or omission retains the base finish's binding unchanged. One uses the full circular cross-section, while intermediate values scale the transverse normal. The texture and strength survive GLB/glTF export. This changes shading without adding triangles or changing the silhouette; it cannot repair scalp gaps or guide intersections.

Use base-colour alpha, not normal RGB, to determine painted coverage. A fibre centre can encode the same nearly flat normal as empty space. Conversely, a softened edge can retain a transverse normal when its small coverage rounds to zero in the 8-bit alpha channel. The normal texture describes orientation, not occupancy.

`createPortraitHairMaterial` supplies the builder's independent card finish and retains an explicitly authored base finish's `alphaCutoff`; omission uses 0.45. Set `alphaMode: "mask"` on that base finish when supplying a cutoff. This threshold changes coverage after texture filtering, not card geometry or the painted fibre population. Inspect the intended viewing distance: fine, sparse tips can disappear and reappear as their projected width changes. A lower threshold is an appearance choice, not a geometric collision repair.

`eye.browProfile.representation: "ribbon"` uses skin-following strips instead of the default eight-sided tubes. At the same longitudinal sampling it uses one eighth of the triangles. Both paths keep the current brow boundary and surface contact, so brow elevation moves the attached hairs. Omission preserves earlier documents.

`eye.browProfile.flow` authors two through 32 medial-to-lateral direction witnesses. Each section has `at`, `lower` and `upper`; each direction gives a `tip` across the supporting brow (lower zero, upper one) and signed `outwardBend` in millimetres. Lower and upper address the ends of `rootBand`, allowing upper hairs to converge downward with lower hairs. `createPortraitEyebrowFlow` blends along the brow with cubic smoothstep and across that band linearly; a collapsed root band uses the midpoint direction. Flow replaces the ordinary `span` and `outwardBend` in both tube and ribbon construction without adding fibres or subdivisions. Omission preserves the basic direction formula. Declare the complete flow profile in the source recipe; eye and independent side edits may retain or clear its array but cannot author new direction witnesses.

Set `eye.browProfile.densitySeed` to an unsigned 32-bit integer, including zero, to thin faded ends independently of root height. Different seeds select different retained strands without changing each strand's dimensions; no random state enters replay. With no endpoint fades the seed changes no geometry. Omission retains the original coupled density pattern for existing numerical documents, including the time-capped study; that pattern can leave root-height bands empty near faded ends. New authored profiles can select the independent pattern explicitly.

The extracted construction owners retain the `Portrait` symbol names and their numerical recipe meanings. Historical subject coordinates and settings live in the studies outside this package. A successfully constructed or exported face is not by itself an accepted likeness.

### One-skin source generations

Optional person `headShape` selects closed cranial, facial, cervical, nasal and paired pinna source traits as source-neutral differences in millimetres or degrees. The generation's `headShapeSource` supplies each trait's signed support, unit magnitudes and one body-channel owner. `createHumanPersonHeadShapeResolver` creates an effective copy for both the person builder and rest measurement path; the existing generation drivers carry its endpoint into both skin partitions and attached parts. Every present field, including zero, requires registration, and duplicate raw body-channel authorship refuses. Saving retains the original numerical request. These source-relative authoring differences are distinct from clinical observations; a source descriptor or callable does not establish qualified geometry, supported combinations or current rendered appearance.

`createHumanPersonGenerationBuilder({ generation })` evaluates the same `IAutoMovieHumanPersonDocument` against one source generation read as one connected skin with a head/body partition (`IAutoMovieHumanPersonGeneration`): the face basis is the head partition view, the body basis is the body partition view, both register `sourcePartition` on the generation's id, and `headSkin` supplies the generation's one weight map on the head cells. This is the adopted person path. The generation ships as two files, a head view (`IAutoMovieHumanPersonHeadView`: `id`, `face`, `headSkin`, `aliases`, `drivers`) and a body view (`IAutoMovieHumanPersonBodyView`: `id`, `body`, `band`); `joinHumanPersonGeneration(head, body)` pairs them, refusing files of different generations or a view not registered on that generation, and creates no value. `createConnectedPersonRuntime` builds with this evaluator when given `[head, body]` (joined) or a joined generation (one carrying `headSkin`); given only `{ face, body }` it uses `createHumanPersonBuilder` and its runtime seam, which remain for documents that name the separately published face and body bases.

- **Ownership.** The face owns the whole head partition's shape, neck stub included. The body gives the head only a rigid carry by the displacement of the body's eye-joint midpoint, the anchor the face basis is defined around (`humanPersonEyeCentre`, also used by the two-basis builder). Body endpoints that shape the head once over the skin (the source's age, sex, weight and muscle macros, bound part rows and face landmark rows) reach the face view through `drivers`: driver-only face channels whose weight is the body's own gain for that endpoint, applied before expression and articulation.
- **Neck band.** Channels without a counterpart across the cut are continued only on the body side (`band`: face rows and the jaw attachment carried down, body rows returning to the anchor carry at the cut). The face producer evaluates the band through an added, never-emitted view (`createHumanPersonBandFaceView`). There is no cut evaluation, collar conform, boundary subdivision or normal fairing: shared cut samples have one rest value and one skinning row, and `createHumanPersonSourceNormals` evaluates one normal field over both halves. `boundary` reports the largest face- and body-field displacement at the cut.
- **Refusals.** Views not registered on the generation id, a head weight map that is not four influences per head vertex or names an undeclared joint, a missing driver channel, a face document stating an aliased face channel (`aliases`) or a driver channel, unavailable body source targets, and every existing face, body, source-normal and resident-model admission refuse by name.
- **Known gaps.** The jaw attachment reaches the cut, so jaw opening combined with a head turn can still invert a few submental triangles (owners #2736, #2731). Earlier generation observations found rigid eyes, teeth and tongue that did not follow head-size changes (#2728, #2738, #2739, #2704); a registered head-shape provider routes source endpoints through the common generation drivers, but its actual attached-part geometry still requires current-source qualification. Stature enlarges the head as the source macro does; head-to-stature proportion and the standard viewer people that pair an adult face with other bodies without `population: "linked"` are identity questions (#2704). The two-basis seam path folds submental skin under head turns that its current guards do not detect; it is not the adopted path. None of this establishes clinical neck motion.

### Person measurements

Some measurements belong to the whole person rather than to either partition view, because their site crosses the head/body cut or reaches the top of the head. `HUMAN_PERSON_MEASUREMENTS` names them, keyed by the body channel a solve moves:

- `measureNeckCirc`: neck circumference, ANSUR II 6.4.63. It is read on the plane through the body view's `neck-anterior-midline` skin landmark, perpendicular to the `joint-neck`→`joint-head` segment, on the joined final Float32 skin.
- `macroHeight`: stature, ANSUR II 6.4.76. It is the highest minus the lowest Float32 skin height of the closed person skin at rest.

Each rule records the observed range of its cited source sample. A target outside that range is solved and reported as `outside-source-sample`, not refused.

`compileHumanPersonGeneration(generation)` compiles what a generation fixes before any document. `measureHumanPersonDocument({ compiled, build, document, channel })` reads a rule at rest. `solveHumanPersonMeasuredChannel({ compiled, build, document, channel, targetMetres })` inverts it along its body channel with the body tier's own bounded inverse; it changes only that channel and keeps pose and expression. It refuses by name:

- a target outside the channel's reach;
- a skin the instrument cannot close;
- a generation whose head view lacks the channel's driver rows.

`createHumanPersonSimpleWhole(compiled, person)` supplies the body simple tier with the whole person's stature and closed volume for any body shape, with the person's face held as stated.

Body bases name skin points instead of numbering vertices: `IAutoMovieHumanBodyBasis.skinLandmarks` maps a name to one surface vertex. The bust girth and the bra read `nipple-left`, and the person neck girth reads `neck-anterior-midline`. A basis that does not declare a name cannot answer a rule that uses it (the rule leaves the measured list), and solves and garments that need it refuse by name. The published body study (r16) declares none.

Head measurements follow ANSUR II and are read on the head view of the skin at rest. `HUMAN_HEAD_MEASUREMENTS` names them by measurement, and `measureHumanPersonHead(compiled, document)` reads all five on one rest evaluation, each with the points its instrument touched:

- `tragionTopOfHead` (6.4.83): the highest head view vertex above `tragion-right`.
- `headLength` (6.4.48): glabella to the farthest midsagittal point at or above the tragion height.
- `headBreadth` (6.4.46): the X extent above the ears, with the `ear-right` and `ear-left` areas left out and each side bounded by its ear's top.
- `mentonSellionLength` (6.4.62): the straight distance from `menton` to `sellion`.
- `headCircumference` (6.4.47): the tape girth on the plane through glabella and the opisthocranion, level from side to side. It is held level where it would rise behind the glabella, and raised at the back to touch the highest ear point where it would cut an ear.

`solveHumanPersonHead({ compiled, document, targets })` meets the four measurements of `HUMAN_PERSON_HEAD_SOLVE` (tragion–top of head, head length, head breadth, menton–sellion) with eight face channels, each a distinct effect: `headHeight`, `foreheadHeight`, `chinHeight`, `headDepth`, `posteriorHeadDepth`, `headWidth`, `cranialBreadth` and `templeWidth`.

- Head circumference, when given a target, is pursued second: by least squares within the freedom the four measurements leave. Its miss is reported, never refused.
- The rest of the choice is the least departure from the standard head. Each weight is priced by the skin its endpoint moves (RMS displacement per unit weight), and the result reports that departure in metres.
- A measurement is met within 0.5 mm, half the 1 mm resolution of ANSUR II's records.
- A solve that ends unmet refuses with the closest readings and the channels it left at a limit.

Gap (#2722 precision item): head circumference at a given head length and breadth. ANSUR II subjects' circumference exceeds the ellipse of their own length and breadth by 1.3 % to 7.3 % (5th to 95th percentile); this head's shape space holds 0.7 % to 1.3 %. With length and breadth held, the solve's channels move circumference by about +12 / −22 mm, so fuller heads keep a miss. The hair the ANSUR tape compresses cannot be separated from the data. A cranial fullness channel is an open authoring item.

Historical cranial source observations (#2722) found faults near channel ends and at some moderate combinations. A revised cranial source needs new same-generation evaluation; these observations are not current-source acceptance:

- Earlier `posteriorHeadDepth` endpoint observations showed a backward balloon and a deep neck crease on solved heads of length 214-215 mm.
- Earlier high `cranialBreadth` observations showed temple bosses and a posterior ridge, clearly at 2.5 and faintly at 1.17.
- Earlier moderate values (`posteriorHeadDepth` 0.43, `cranialBreadth` 0.61, `templeWidth` 0.31) showed an occipital shelf and lateral parietal bulge.

Each solution retains its complete channel values, so the reader can see the source endpoints it uses. Cranial fullness, occipital length and parietal breadth still need source-specific shape and rendered qualification.

Named approximations:

- The source's rest head orientation stands in for the Frankfurt plane.
- The skin carries no hair, so the skin top stands in for the vertex under a compressing blade.
- `glabella`, `sellion`, `menton` and `tragion-right` are fixed vertices chosen on the neutral generation. A shape that moves a definition's extreme to another vertex is not followed.
- The tragion height stands in for the Frankfurt plane at the back of the head when the opisthocranion is searched.
- The circumference plane passes through glabella itself, not just above the brow ridges, and is the admissible plane nearest the longest front-to-back line rather than a search for the maximum girth.
- The ear areas are bounded by an attachment loop read from renders.

The following limitations describe the legacy person head-view channels and measurement protocols, not every registered source provider. The editor groups those channels by the face editor's anatomical tree (`createConnectedPersonFaceComponents`). A generation with `headShapeSource` can additionally consume the [closed source traits](src/human/structures/AutoMovieHumanPersonHeadShapeField.ts) through [createHumanPersonHeadShapeResolver](src/human/document/createHumanPersonHeadShapeResolver.ts), including independent paired alar traits, inner-pinna sections, retroauricular recession and cervical traits. Each requested field needs that generation's registration, endpoints and supported units; missing registration refuses even zero. These authored source controls do not supply missing clinical measurement protocols or establish accepted rendered anatomy. Each listed element still requires source-specific precision and assembly qualification.

- Nasal root and dorsum (#2726): the current nasion rule is unavailable, and source readouts do not provide independently authored numerical root and dorsum shape.
- Nasal tip and columella (#2727): subnasale has a source skin registration and the pronasale reader searches each shaped midline profile. These report-only source conventions do not provide independent numerical tip-columella shape or a qualified clinical aperture.
- Alae and nostrils (#2725): every identity channel is bilateral, so the two nostrils cannot differ in shape; only the sneer expressions are one-sided. The procedural nostril owners (`appendPortraitNostrils`, `fitPortraitNostrilRim`) have no product consumer.
- Inner auricle (#2729): the 11 channels per ear set outer size, position and outline; helix, antihelix, concha, tragus and thickness have no channel.
- Retroauricular sulcus (#2730): widening the vault carries each ear by the displacement of its nearest non-ear skin, which shears the ear; the sulcus and the mastoid attachment are not built.
- Cheek (#2721): malar and buccal sections and the nasolabial transition are not measured; the cheek channels move authored geometry only. Bizygomatic breadth refuses on a skin that keeps widening toward the ear root, because there the zygomatic arch makes no lateral maximum of its own (`findHumanZygia`).
- Mandible and chin (#2741): the millimetre vocabulary of `IAutoMovieHumanFaceCraniofacialParameters` (bigonial width, lower face height, pogonion projection and others) is declared without a consumer; menton–sellion is the only mandibular measurement the editor solves. Bigonial width has no rule: the jaw attachment weights fade before the mandibular angle and the skin has no registered mandibular border.
- Submental and neck (#2731): on a person the neck is the body's (`neckDouble`, `neckScaleHoriz`, `measureNeckCirc` and the rest); the cervicomental profile and submental section are not measured.

Bases also name areas of the skin: `skinRegions` on the face and body bases maps a name to a set of vertices of one surface. Admission refuses an area off its surface, an empty or unsorted vertex list, and a feature whose `-right` and `-left` areas on one surface share a vertex. A rule that keeps a feature out of a search names its area (`ear-right`, `ear-left`) instead of listing vertices.

Gaps:

- Neck circumference at the base: the anterior and lateral neck landmarks are not registered.
- Neck length: no anthropometric protocol defines it.
- Child and older-adult protocols: ANSUR II measured adult soldiers aged 17 to 58.

The resident development viewer lists `person:connected-reference` and `person:reference:<body state>` alongside the individual domains. These previews use the same person builder and precision boundary as the static export.

An offline body basis may supply `anatomicalCandidates`, individually named acquired atlas bone resources with source rights, original bytes and registered mesh digests, exact reference basis and shape, and a carrying rig frame. A body document's `anatomicalInspection` selects closed bone IDs explicitly. The body builder appends those actual surfaces as separate static parts, and the person builder keeps them under its `body:` prefix. Omission displays no atlas bones. Missing or stale resources, duplicate selections and a shape outside the exact registration refuse by part; no dimensional scaling converts an atlas into personal tissue. The acquired atlas, authored reference placement, independently validated personal anatomy and outer skin are separate results. `GeneratedAnatomy` retains its clinical unavailable answers.

After a successful build, `createHumanBodyAtlasExportQualification` verifies the registered source mesh SHA-256 and carries each selected source receipt into the static writer. `exportHumanBody` accepts this separate fourth argument and `exportHumanPerson` its optional second argument. The writers opt into the common actual source-part accessor partition and join `automovieAtlasInspection` provenance only to the selected atlas members. `readHumanBodyAtlasAssetCorrespondence` reads that namespace beside the actual Float32 geometry intervals, retaining attribution, acquisition, exact reference registration and unavailable personal anatomy. The source reference mesh digest does not hash the final posed asset. Save the numerical document separately to edit or replay it.

The offline study compiler is `test/scripts/body-review/compile-human-atlas.ts`, run from `test/` through `pnpm exec ttsx -P tsconfig.scripts.json scripts/body-review/compile-human-atlas.ts PLAN BODY_VIEW OUTPUT`. The plan names original OBJ files, their anatomical identities, rights and an explicit signed axis convention. The compiler preserves source faces and adjacent parts' relative dimensions, normalizes rounded source normal directions, records authored placement, verifies each resource's mesh digest on file readback and writes a separate derived candidate basis. It does not publish the shared skin generation. A bbox-to-rig placement is an authored approximation with unverified tissue contact and no independently registered articular centre.

## Browser editor and studies

Run `pnpm --filter @automovie/playground dev` from the repository and open `/face.html`. The development command builds the human browser entry before starting Vite. Both face page entries mount the connected-basis editor with committed numerical studies, anatomy-nested fine controls, simple projection, hair/skin/iris fields, expression presets, orbit views and clay; historical procedural guide-array editing is a source-level tool, not a page control. Model construction runs in a worker. Failed geometry keeps the last valid model; history and JSON/GLB/glTF downloads refer to that committed state. A JSON glTF download also needs all its sibling buffer and image files in the same directory.

The [reference studies](../../test/src/subjects/README.md) own photo selection, numerical fits and observation status. Their files are examples, not defaults shipped by this package. Reconstruction remains provisional: single-view depths, posterior anatomy and material choices are estimates; matching landmarks and passing topology checks do not establish photographic identity. Reproducibility should name the runtime and compare both numeric geometry and serialized bytes; separate JavaScript runtimes can differ at floating-point rounding even for the same document.
