# @automovie/human

Procedural anatomical face construction. Components fit to one immutable host, share their skin boundaries and finish internal geometry against the refined surface. The package contains no named person, photograph or fitting runtime. Construction coordinates use millimetres, +Y up, +Z anterior and anatomical left +X; the model boundary converts them to metres.

The [face requirements](../../docs/requirements/actors/facial-authoring/contract.md) and [parameter and editing specifications](../../docs/specifications/asset-and-representation/facial-authoring/contract.md) own the contract. Optional numerical hair cards and skin-following eyebrow ribbons belong to the same static facial asset.

The eye component separates shape contracts (`eyeShape`), copied input admission (`eyeComponentInputs`), transverse tissue formulas (`eyeLidRows`), shared ring attachment (`eyeMargins`), optical shell construction (`eyeOpticalSurface`), final skin contact (`eyeSurfaceContact`) and refined interior construction (`eyeInterior`). `eyes` orchestrates their fit/attach/finish lifecycle and retains its existing exports. Both skin constraints and emitted lid rings call the same section calculation; drawing and contact call the same optical shell builder. Keep those numerical owners shared when adding a shape control, and test section arithmetic separately from whole-face fitting.

Node consumers require Node 22.23.2 or later. Older Node 22 loaders can expose an unevaluated ES-module dependency when a CommonJS package and an external ES-module glTF reader share the same import graph. Consumer import order must not be used to mask that runtime defect.

## Face documents and editing

### Connected facial priors

Connected documents now author skin reflectance numerically. `materials` stores linear RGB and roughness. Optional `skin` maps shared basis surface IDs to compact `IPortraitColourField` arrays: named neutral-space centres and radii in metres, RGB gain and strength. The builder evaluates the common C2 compact-support field on reference vertices and transports its colours through shape, expression and UV/material separation. No individual skin image is loaded. Omitted/null/empty records add no buffer; an empty array gives its surface white multipliers. Fields narrower than the source vertex spacing need additional sampling before fine detail can be claimed. The editor's **Colour and surface** section edits global values through the same transaction and undo history; the **Pigmentation regions** section adds, renames and removes fields and edits centres/radii in millimetres, linear RGB gains and strength. Both sections preserve the numerical document and share undo/redo.

Connected `hair` now accepts `IAutoMovieHumanFaceHair`, whose layers contain numerical growth, length, styling and finish parameters. A basis surface supplies shared `hairDomains` and optional query-only `hairContactClosure`. `createHumanFaceHairBuilder` samples owned neutral area correspondence, seats the same barycentric roots on the current surface, integrates metric curves against a closed signed-distance query and meshes those exact stations. The first curve bend establishes a strip's initial transverse plane; minimal rotations transport it thereafter. Colour and fibre pixels are generated from numerical finish inputs. Generated guides, private bitmaps and personal resource keys are absent from this document schema.

Optional `rootRegion` localizes a layer's roots with six Gaussian coefficients, `center` and positive `spread` triples in neutral metres. Count remains the requested number of accepted strips, with relative density weighted over the shared scalp and hairline. The editor exposes **Localize roots** and each metric coefficient. This supports separately placed populations with independent lengths or curl; `part.region` independently limits the combing field. Rejected candidates retain their original sequence identities so common roots keep their seats and variation after an edit.

Optional `guides` turns a layer into a hierarchy: `fraction` of the roots, chosen by their own sample identity, are integrated through the fields and the surface contact as guides, and every other root grows from its `neighbours` nearest guides on its own side of the part (`interpolateHumanFaceHairStrands`), blended at equal arc-length fractions, weighted by scalp distance against the guides' mean spacing and scaled to the strand's own regional length (`humanFaceHairLength`). Every interpolated station is then projected by the guides' contact rule (`humanFaceHairContact`), so strands keep the clearance guides were integrated with. With an eighth of the roots as guides, three published subjects built 2.2 to 2.5 times faster with no ribbon vertex inside the skin; a fraction of one reproduces the flat layer exactly. Optional `clump` in [0, 1] then gathers each strand toward its nearest guide, nothing at the root and that fraction of the way at the tip, the linear profile of a groom's clump operator, so strands read as locks rather than scattered ribbons. The playground's **Guide hierarchy** toggle adds that ratio and exposes the three numbers.

Optional `gather` makes a tied hairstyle from the same numerical layer. An anchor specified by polar and azimuth angles is ray-attached to the shared scalp and follows shape edits through that triangle's barycentric coordinates. Curves descend a current-surface distance field to the authored tie radius, then continue along a tail direction. Optional `tail.spread` gives a target tube radius and a metric transition reach; stable root-sample coordinates distribute the locks through that cross-section. The tie is an event in each curve, so gathered layers integrate every root and refuse a guide fraction under one rather than blending mismatched pre- and post-tie intervals. Unreachable ties and too-short lengths refuse. These controls create no personal strand or guide asset, and the result still needs front, quarter, profile and back review: the shared generator does not infer a hairstyle or accept photographic likeness by itself.

Hair does not leave the scalp perpendicular. `humanFaceHairEmergence` turns the first step out of a root to the exit angle that place carries — 30 to 45 degrees over the mid-scalp and 15 to 20 at the frontal hairline in the hair restoration literature (Shapiro & Shapiro 2013), of which the lower end of each range is used so hair lies against the head and the surface contact holds it there. The tilt is toward the field's tangential part, the direction that hair is combed, and the hairline's own transition ramp carries the angle between the two figures. A field with no tangential part leaves the hair on its normal. The temporal hairline's 5 to 10 degrees is not modelled separately, since the sources give no occipital figure and a per-azimuth field would be this project's invention rather than theirs.

A step also cannot turn tighter than the tightest curl a head grows: the eight-class curl survey puts that curve diameter below 1.2 cm (Loussouarn et al. 2007), so one sampling step turns at most `h / 6 mm` and a field asking for more is asking for a kink, which has neither a ribbon frame nor a follicle. That bound is what let the exit angle ship: a shallow emergence sends hair along the scalp, where the curliest published document then asked for a reversal inside one step.

A ribbon has no authored width. It stands for the whole neighbourhood of one root, so `humanFaceHairDensity` measures the scalp that root is responsible for from the population's own local density: with `d` the distance to a root's fourth neighbour, the density is 3 / (pi d^2) and the ribbon is `d sqrt(pi / 3)` wide, falling back on the area the sampler accepted over the population when a layer is too small to have neighbours. On the published documents that reads 8.1 mm where a fixed 4 mm was authored, and roots thinned by a hairline or a root region widen their ribbons exactly as far as they thinned. The fibre path is no longer paid for the ribbon either: `humanFaceHairContact` keeps half a sampling step and the requested clearance, which lowered the published hair from 4.0 mm to 2.0 mm above the scalp, and `buildHumanFaceHairMesh` instead measures each ribbon's own corners against the same surface and narrows the station where they would enter, both sides together so the ribbon stays centred on its fibre. A half width within the station's own free distance less the requested clearance needs no query, since the nearest surface point is that far away. Thinner hair is a smaller `count` or a lower `finish.coverage`; there is no width to widen until gaps close.

`finish.grey` paints a greying head as the admixture it is. Greying is a follicle's own switch, so a greying head carries white fibres beside pigmented ones rather than one faded colour (Tobin & Paus 2001; Jo et al. 2018), and the largest fibre-level survey classified its 3,343 hairs as pigmented or white against a black-and-white card (Van Neste 2004). The proportion in [0, 1] is how many of a card's painted fibres are left unpigmented; each takes one side of that switch by its own coordinate, and the unpigmented fibre is painted thicker, 67.68 against 57.41 micrometres, as that survey measured. The finish's `color` is then the pigmented fibre's own colour, the base finish becomes the unpigmented one, and the scalp under the hair sees the mixture. A fibre part-pigmented along its length is documented but has no published frequency, so none is invented. Greying runs temples first and the occipital region last, so a head grey only at the temples is a layer of its own with its own `rootRegion`. Omitting the field paints every fibre pigmented, byte for byte as before.

Optional `iris` gives each articulated eye its own pigment: `{ left, right }`, the subject's own eyes, each an `IPortraitIrisPigment` with the constructed portrait eye's band meaning (`base` is the limbal ring, the stroma takes `base + (i/7) * variation` along deterministic radial fibres). The basis eye texture paints sclera, iris and pupil together, so a material colour could only tint the whole eye; `createHumanFaceIrisPigment` instead repaints only the anatomical iris disc. It finds each globe as the textured region fully bound to that eye owner, takes the optical axis from the corneal protrusion over a two-pass sclera sphere fit (`locateHumanFaceIrisDisc`), sets the limbus at asin(11.71 / 24.2) from the adult visible iris and globe diameters and the pupil at a 3.5 mm light-adapted diameter, rasterizes the disc's texels through the neutral surface (`rasterizeHumanFaceIrisTexels`) and paints them (`humanFaceIrisTexelColour`), blending both edges over 0.3 degrees so the sclera keeps its painted detail. The texture is decoded and re-encoded by `decodePortraitPng` and `encodePortraitPng`; the first pigment costs about 0.7 s on the published basis and a repeated pigment reuses its bytes. Omission or null leaves the texture byte for byte. The editor's **Iris pigment** section adds, edits (both eyes together or one at a time) and removes the field. The pigments are authored colours under the renderer's light, not reflectances recovered from a photograph.

A material override may also carry `pigment` (the fibres' linear RGB albedo, each component in [0,1]) and `density` (a coverage factor in [0,4]) for a material whose embedded texture holds fibre coverage in its alpha, the brow and lash cards cut by a mask or blended. The source cards paint one dark brown for every subject and a colour override can only darken them, so `createHumanFaceFibrePigment` repaints each covered texel as the pigment times its luminance over the median luminance of the texels the card draws, held at one (a darker texel keeps its shade, the source's brighter coverage fringes take the pigment itself), sets the base-colour factor to white, and multiplies coverage by the density, so a factor below one thins fibres under the material's own cutoff. Omission leaves the card byte for byte; an out-of-range value or a material without coverage is refused. The editor's **Brow and lash fibres** section adds, edits and removes both values per card. They are authored colours under the renderer's light, not reflectances recovered from a photograph.

Under a hair document the scalp takes the hair's colour (`createHumanFaceScalpTint`): each growth-domain vertex is covered fully inside the hairline, ramps up across the 1 cm transition zone at it (`humanFaceHairlineCoverage`, the first 0.5 to 1.0 cm of the hairline in the hair restoration literature; the 2 to 3 cm often quoted beside it is the whole frontal hairline region) and follows the layer's root region, and the builder multiplies the skin finish toward the hair colour by that coverage as a vertex colour, clamped so a hair lighter than the skin leaves the skin. Nothing new is stored: the rule reads the hairline, root region and colour every document already has, so skin no longer shows between ribbons of dark hair.

The playground's **Numerical hair** section edits every layer field through the document transaction and history. Mean length scales the six canonical regional lengths by one ratio, preserving their authored differences. Adding a layer selects a resident shared growth domain. Strip count, static combing/lift and procedural fibre coverage are authoring quantities; they do not calibrate biological density or elastic mechanics, and the derived ribbon width states coverage, not a fibre's diameter. The free-strip clearance argument excludes root fans and hair-to-hair contact. Closed, oriented manifold queries do not prove that a deformed head is embedded or physiologically valid.

All eighteen published documents now declare the guide hierarchy, and the study records their [acceptance](../../test/studies/human-face/connected-basis/global-face/README.md#eighteen-subject-acceptance): five GPU views each and fourteen coupled states with the crossing census. The application study's [data migration](../../test/studies/human-face/connected-basis/global-face/numerical-hair.md) converted all eighteen published documents to numerical hair; its shared scalp preparation and actual export entries are recorded there. Numerical construction, visual quality and anatomical acceptance remain separate obligations.

Each basis channel may carry a nonempty `description` explaining its authored sign and shape meaning. The connected editor displays it as text beside the endpoint's measured displacement. This metadata belongs to the shared basis. Compact documents save numerical shape, performance and appearance values. Source weights and descriptive names do not establish measured biological ranges.

`createHumanFaceControlMap({ basis, map })` compiles disjoint groups of fine shape coordinates into a simpler authoring view. Calling the result with a shape record returns the current `controls` and a `resolve(values)` function. Resolution starts from that captured record, preserves each member's normalized residual and every unlisted coordinate, and refuses values outside the displayed feasible interval. Documents still store only fine weights. The transformation is an authoring coordinate system; it supplies no biological age calibration or anatomical acceptance of the basis.

`createHumanFaceBasisBuilder(basis)` compiles a caller-supplied `IAutoMovieHumanFaceBasis` once and returns a builder for compact `IAutoMovieHumanFaceBasisDocument` edits. The immutable basis supplies connected surfaces, sparse signed shape endpoints, expression endpoints, material regions and resident finishes in metres. Evaluation applies all channels in basis order, computes common normals, then separates material and UV identities. Preparation admits the neutral model's structure, materials and topology. Edits check channel/material domains, finite normals and the welded vertex partition; a changed partition takes the full model gate again. Document overrides cannot repair an invalid source palette. Authored endpoints do not establish physical joint motion or collision-free arbitrary combinations.

A basis may declare `landmarks` (the source's joint-cube centroids with their own sparse shape rows), an `articulation` (one mandible: pivot landmark plus condylar offset, unit axis, opening degrees with a coupled translation, protrusion, both laterotrusions and a sagittal translation limit; two globes: centre landmark and gaze channels, each an axis, degrees and an eccentric translation) and per-surface sparse `attachments` (`[vertex, weight]` rows per owner, the cranium as the complement). `createHumanFaceBasisBuilder` then evaluates the rest layer on surfaces and landmarks (`evaluateHumanFaceRest`), resolves the joint motions from the shaped landmarks (`resolveHumanFaceArticulation`), poses each attached surface by linear blend skinning (`poseHumanFaceSurface`) and only then reconstructs normals. Expression rows on an articulated basis are rest-space residuals over that motion, which is what the offline preparation measures from the source (`test/scripts/face-review/prepare-articulated-basis.ts`, with `unposeHumanFaceSurface` as the exact inverse). A mandibular arch or globe attached at unit weight is rigid by construction and on the arc at every fraction of opening; a document whose opening and protrusion together exceed the budget is refused by name. `summarizeHumanFaceArticulation` states the requested degrees and millimetres for an editor. Landmarks, weights, angles and translations are measured from the shared source and cited in the study receipt; they establish no clinical trajectory and no contact freedom, which the crossing census measures separately.

A basis may further declare `contact`: the vermilion seam and incisal edge vertex pairs whose posed distances are the interlabial and interincisal apertures, a `closure` channel decomposed as a delta at the reference opening (the ARKit sense of `mouthClose`) that the builder applies scaled by the ratio of the current aperture to the reference aperture (`measureHumanFaceAperture`), so weight one seals the lips at any opening and never overshoots a half-open jaw; a tongue `passage` rule that refuses a tongue past the incisal plane thicker than either aperture, naming the short channel and the millimetres it needs (`evaluateHumanFacePassage`); and rigid `colliders` (the dental arches sealed at their crown root rings, the globes sealed at their posterior poles), against which the `soft` surfaces (skin, tongue, lashes) keep the clearance they have in the shape-only rest state, moved back along the nearest feature within a cited tissue budget and refused beyond it (`resolveHumanFaceContact`, on the engine's oriented sheet query, which reports rim features so a sheet's edge reads no side); the same floor keeps a lid at its rest clearance over the cornea as the globe turns under it and as it closes. The builder's `observe` callback delivers the `IAutoMovieHumanFaceContactSummary` of each build (apertures, closure ratio, passage, resolved vertices) so a runtime reports it without evaluating twice. The preparation (`test/scripts/face-review/prepare-contact-basis.ts`) finds the pairs, seals the crowns, decomposes the closure and measures the budgets from the shared source and the cited literature; nothing in the block is per person.

The playground's `face.html` and `connected-face.html` mount the same product consumer. It uses the [CC0 connected study](../../test/studies/human-face/connected-basis/README.md), numerical controls, the shared transaction/history owner and the shared viewport. `parseHumanFaceBasisDocument` and `serializeHumanFaceBasisDocument` save compact edits tied to one exact basis revision. `exportHumanFace` exports the resulting resident model. The photo and offline modeling application are absent from replay. Named source geometry stays with the application.

`clipHumanFaceBasisSurface` in the `face/basis/` subpath prepares an open neck boundary at a neutral Y plane. It shares edge intersections and affine endpoint stencils while retaining corner UV seams. Its region-local maps identify wholly retained triangles whose barycentric attachment coordinates remain usable. Callers own a new basis revision, dependent resource bindings and explicit handling of attachments on cut triangles. The ordinary builder reconstructs normals from the result.

### Procedural face documents

The following recipe APIs retain historical procedural studies and geometry authoring. Their guide-array profiles are not the connected parameter-only document contract and are no longer bundled by either face page entry.

`basis.recipe.skinColour` and `detail.skinColour` hold optional named skin-colour regions. Each region attaches to a reference host vertex with millimetre offsets/radii, a linear RGB multiplier and strength. `createPortraitSkinColour` evaluates these compact fields on transported reference coordinates, so the current expression does not slide skin through a stationary colour volume. `buildHumanFace` emits RGB on head, eyelid and pinna meshes; contact keeps separate tissue colours with shared normals. Arrays replace completely, and `detail.skinColour = []` removes inherited regions. Select `skinColour` in the editor's Region menu and open the complete-profile editor to replace the array or restore inheritance; it has no implicit region selection through a scalar slider. These controls are authored colour, not inferred pigment concentrations. A saved photo reference is never used as a skin texture.

`IAutoMovieHumanFaceDocument` separates a versioned observed host and part recipe from intermediate controls, exact detail overrides, side-specific settings, appearance and current expression. `parseHumanFaceDocument` and `serializeHumanFaceDocument` admit the complete JSON schema without fetching provenance. `resolveHumanFaceDocument` applies version defaults, basis settings, `humanFaceControlDefinitions` trait offsets, exact details and independent sides in that order. `mergeHumanFaceSettings` recurses through objects and replaces an array's entire population; it never merges array elements by position. Optional skin condition resolves to its zero-effect defaults. An absent optional component such as hair or dentition stays absent unless a complete valid profile is supplied.

`buildHumanFace(document, subdivisionRounds = 2)` constructs the resident model. `humanFaceExpressionDefinitions` and `resolveHumanFaceExpression` describe and admit independent lid closure, brow elevation, mouth-corner elevation, lip separation/protrusion, jaw opening and gaze. Omitted current channels mean neutral, not the photographed expression. Source expression is explicit. A nonzero mandibular angle needs an authored `basis.bindings.jawHinge`; its hidden position is an estimate, not a recovered scan. Eyes need a full limbus and corneal contact for performance. Upper crowns use separate `dentition` with a maxillary binding and an empty `mouth.crowns` array.

`frame.browProjection` changes the shared superior-orbit foundation before eyes and their skin attachments are fitted. Positive millimetres advance both brow supports; negative values recess them. This is a bilateral identity control, separate from expression brow elevation and the optional post-refinement orbital layer. The document keeps its original observed coordinates. A compact envelope starts 0.5 mm above the higher aperture, reaches the mean lower-brow height and fades into the forehead; overlapping medial shoulders use their maximum influence. These are construction controls, not measured bone or tissue thickness. Zero preserves earlier geometry. Direct `createPortraitFacialFrame` callers supply both eye sockets as its third argument when using a nonzero value; document resolution supplies its own bindings.

`eye.sphereFit` selects how the reference ocular cap is placed. Omission or `"aperture-plane"` keeps the original canthal-plane fit. `"observation-ray"` keeps the reference rim mean's image position while fitting centre depth along the recorded observation ray; tangent canthal support instead fixes that position at the canthal midpoint. Neither fit uses the current gaze or recovers a measured globe centre. Without separate canthal support, the selected radius must admit the complete rim and its contact rays. Set the choice in the complete eye-region JSON, including side-specific profiles when needed; it is not a scalar detail channel. Changing it requires inspecting the resulting lids, optics and expressions.

`eye.opticalFrame` independently selects `"head-plane"` (the omission default) or `"radial"`. Radial optics construct the iris, pupil and cornea in a centred local spherical frame, then turn that frame toward the observed iris intersection. This preserves the authored radii and axial shell thickness when the optical axis is oblique. It requires `cornealBoundary: "limbus"` and `lidContact: "cornea"`, retains the full globe even without expression performance, and uses the same shell for skin contact and rendering. Current gaze rotates the assembled layers afterwards. Set the choice through complete eye-region JSON, with optional unilateral overrides. It is not a clinical axis reconstruction or a guarantee that an arbitrary globe fits inside the head.

`eye.canthalSupport: "tangent"` separates the declared optical radius from the full aperture width. It requires observation-ray fitting and radial optics. `eyeSupport` places the optical centre under the canthal midpoint, fits depth using the rim rays inside its projected disk, and intersects the visible canthi's depth bounds. The sampled globe and fixed canthi form one convex support hull. Exposed spherical faces and connective lining partition that hull for rendering; eyelid contact uses the same triangles. Blink changes the lids, and gaze rotates the optical layers, while the support stays fixed. `globeLift` remains signed but refuses if it would bury a fixed canthus. Omission retains the previous all-rim spherical fit. Select the choice in complete eye-region JSON and inspect the resulting tissue sections in all affected expressions. This convex support is a geometric approximation, and the radius remains authored; neither is reconstructed clinical anatomy.

```ts
import {
  buildHumanFace,
  parseHumanFaceDocument,
  serializeHumanFaceDocument,
  setHumanFaceDetail,
} from "@automovie/human";

// suppliedJson contains the complete numerical basis and recipe, not a photo.
export function wink(suppliedJson: string) {
  const observed = parseHumanFaceDocument(suppliedJson);
  const edited = setHumanFaceDetail(observed, "eye.foldDepth", 0.4, "left");
  edited.expression = {
    ...edited.expression,
    blink: { right: 0, left: 1 },
  };
  return {
    model: buildHumanFace(edited),
    json: serializeHumanFaceDocument(edited),
  };
}
```

The document owns a `mediapipe-478/1` correspondence basis, including the 478 coordinates, original face triangles, view direction, anatomical bindings, observed expression and complete required eye/nose/mouth profiles. Its topology name defines landmark interpretation; the package neither invokes MediaPipe nor fits an image. Schema validation, finite-number admission, geometry admission and likeness are distinct checks. Provenance fields are descriptive and never fetched. A different basis revision requires rebuilding dependent bindings rather than reusing the old IDs blindly.

`humanFaceControlDefinitions` contains fifteen intermediate traits. `humanFaceDetailChannels` supplies scalar editing envelopes, each with units, signed effect, inherited neutral, paired ownership and attachment context. These are convenient scalar controls, not a claim that every nested profile is a slider. `humanFaceRegions` and `replaceHumanFaceRegion` also expose complete object/array profiles: hair guides, cranial stations, neck sections, ordered crowns, nasal section/loft alternatives, lower-lid sections, orbital sections and relief curves. The owning public type documents the coupled dimensions. `humanFaceRegionValue` and `humanFaceDetailValue` return applied values after resolution; undefined means that optional profile is not present. Exact details override earlier traits; clearing a detail restores inheritance. A side override is available only for eye, cheek and ear profiles; orbital right/left groups live explicitly inside `orbits`.

The scalar inventory is maintained by anatomical domain: [foundation and attachments](src/humanFaceEnvelopeChannels.ts), [ocular](src/humanFaceOcularChannels.ts), [nasal](src/humanFaceNasalChannels.ts), [oral](src/humanFaceOralChannels.ts), and [skin and hair](src/humanFaceSurfaceChannels.ts). Their [shared channel constructor](src/humanFaceDetailChannel.ts) owns stable IDs, side ownership and attachment descriptions. [Document detail editing](src/humanFaceDetail.ts) composes the established display order and owns inherited reads and immutable writes. These editing envelopes do not determine clinical anatomy.

Facial frame controls deform the common host before fitting any parts. Width/length use the nasion; jaw/chin/forehead/temple offsets use named compact supports. Dependent eye/nose/mouth boundaries and the jaw hinge use that same transformed basis. Cranial sections continue the resulting facial oval, ears sample the resulting temporal surface, and cervical sections join the shared cranial collar. These controls do not reconstruct unseen anatomy from one photograph.

Expression controls are builder-time kinematics, not a real-time skinned animation export, speech model or muscle simulation. Blink uses a common closed seam without shrinking the globe. Gaze rotates the iris/cornea around its optical centre. Brow movement carries its skin attachment. Lip separation, paired corner elevation and pucker alter common oral boundaries; jaw motion shares an authored hinge with the lower face and optional mandibular row. The upper arch remains maxillary. `lowerDentition` supplies an independently sized, upward-facing enamel row; lip separation does not translate its teeth. Gingival tissue and a general inter-arch collision solver are not provided. Individually valid scalar values can form an invalid combined geometry and must be built before publication.

`recipe.tongue` or a complete `detail.tongue` selects an `IPortraitTongueShape`. Its eight scalar dimensions control body width, length, thickness, observed dorsum rise, median groove width/depth and inferior/posterior placement. `material` names an existing palette entry; the component adds no implicit material. A selected tongue requires `basis.bindings.jawHinge`. Omission keeps the earlier part population unchanged. The editor exposes `tongue` as an independently replaceable region and uses `portraitTongueParameters` for its numerical controls.

`buildPortraitTongue` constructs the closed local volume, and `createPortraitTongueComponent` connects it to the actual face builder. `tongueRaise` and `tongueAdvance` are separate expression channels in [-8,8] mm. Their observed-relative differences raise the dorsal centreline or advance the anterior body while the posterior endpoint stays fixed. An excessive retraction that reverses the longitudinal coordinate refuses. Mandibular rotation fades smoothly from full influence at the tip to zero at the posterior end; lip-only movement does not carry the tongue. This fixed posterior attachment approximates visible kinematics, not muscular or hyoid motion, volume preservation or tissue clearance. Nonzero tongue performance without a selected profile refuses.

`attachPortraitOralMesh` and `IPortraitOralAttachment` share one orthonormal millimetre transform between lingual and dental interiors. `attachPortraitDentalRow` delegates to it with its existing upper-lip anchor. Authoring the cavity back-wall depth, enamel and tongue remains independent; a successfully constructed body can still be hidden behind a shallow cavity wall or intersect surrounding anatomy and needs multi-view inspection.

`mouth.cavityWall` selects a rim-connected oral enclosure. The ratio [0,0.95] keeps the opening cross-section through that fraction of the depth before a cosine taper closes it. The posterior pole is 1.8 times `cavityDepth` behind the average rim Z. Omission preserves the legacy detached backdrop; explicit zero selects an immediate taper. `buildPortraitOralLining` traces the actual final lip band's seeded free cycle, including subdivision vertices, and copies its rim exactly. `createPortraitMouthComponent` supplies that final connectivity; direct `buildPortraitMouth` callers selecting a wall must also supply final lip indices. Closed performed mouths omit the cavity while retaining dimension admission through `assertPortraitOralLining`. This enclosure does not model gingiva, reconstruct the palate or certify tongue/enamel clearance.

`components/mouth.ts` owns lip admission, fitting and shared skin attachment. Its final-surface consumer, `components/mouthInterior.ts`, owns the cavity and legacy static crowns after refinement. `preparePortraitMouth` returns owned head-millimetre interiors; `buildPortraitMouth` packs the same results into model metres. Both remain available from the package root and `components/mouth`; performed maxillary and mandibular dentition retain their separate component owners.

`preparePortraitDentalCrown` returns `{ mesh, cervical }`, retaining the directed cervical cap cycle at its constructor. `preparePortraitDentalRow` carries one such cycle per crown through placement, optional separation and merging. Upper, lower and legacy tooth interiors expose those cycles through `IPortraitInterior.loops`; the lower row reverses them with its reflected faces. `preparePortraitOralLining` returns `{ mesh, boundary }`, where each boundary entry names the skin vertex copied into the corresponding initial mesh vertex. The mouth carries these live identities as `IPortraitInterior.attachments`. The mesh-only builders retain their established results.

`assertPortraitInteriorBindings` is called by the head after preparing every native interior. It checks unique interior IDs, resident finite referenced coordinates, named directed cycles and exact millimetre agreement of declared attachment pairs. A target part of `null` names skin; another string names a prepared interior, including one appearing later in component order. The check changes no geometry and discovers no relationship from coincident coordinates. Declared cervical cycles need not be free boundaries. Ordinary mesh validity, closed-skin seam equivalence, fixed/free mechanics and collision freedom remain separate responsibilities.

`IPortraitComponentPlan.attach` can supply `prepareInteriors`, returning `IPortraitInterior` descriptors with stable part/material identities and fresh native meshes. The head stages every selected provider after contact sealing and before skin normals or model packing. An empty result is authoritative; components without a provider keep their `finish` path, and output order remains skin regions followed by component order. Upper/lower enamel, tongue and mouth use `createPortraitInteriorFinisher` to share one native producer with the existing direct `finish` API. Positions stay in head millimetres until `portraitPart` converts them once. Preparation preserves current anatomy and kinematics; it does not yet perform a joint collision solve or infer attachment identity from coincident coordinates.

`tracePortraitOralBoundary` in `components/oralBoundary` owns the seeded, oriented free cycle shared with the skin. It returns resident indices without changing caller coordinates and rejects incomplete, branched, nonmanifold or collapsed attachment data. `buildPortraitOralLining` consumes that boundary before choosing depth rings and chamber expansion. Keeping attachment topology separate lets an interior use its own shape while joining the exact refined lip opening; the boundary trace itself makes no clearance or anatomical-depth claim.

When the inherited mouth omits `cavityWall`, select it through the mouth region JSON or load a document that includes it. Detailed scalar fields appear for selected values; an absent optional field is not displayed as zero. Once selected, the ratio has the same numerical editing, per-field reset and document history as other mouth details.

`mouth.cavityChamber` adds independent internal room behind that connected rim. Supply the complete `{ horizontalExpansion, verticalExpansion, transitionDepth }` profile in millimetres alongside an explicit `cavityWall`. The first two nonnegative values expand the transverse and vertical half-extents; the positive depth controls a smooth vestibular transition. The original posterior taper still closes the enclosure. Rim, depth and all other components remain unchanged. Omission and two zero expansions retain the original mesh. A nonzero expansion requires positive finite projected rim extents. The editor exposes three selected scalar fields with 0..30 mm expansion and 0.1..60 mm transition envelopes. These are authoring controls, not measured hidden anatomy or a clearance guarantee. Check the cavity against teeth, tongue and skin across expressions.

`mouth.seamProjection` controls the depth of both oral rims separately from lip-body fullness and aperture. Positive millimetres advance the contact line, with a smooth fade to zero at the outer vermilion boundary and corners. A coincident closed seam stays closed. Omission is the legacy zero offset. This identity control does not infer a person's hidden oral anatomy from a photograph.

`createHumanFaceEditor({ document, model, build })` owns a validated initial pair, edit/reset/undo/redo history and the latest-request rule. Pass `buildHumanFace` through the application's asynchronous worker. Only the latest successful build commits its document and model together; failed builds preserve the last valid pair and do not consume undo history. `cancel()` withdraws pending publication authority and restores ready status without changing that pair or its history. The application still cancels worker work and disposes obsolete renderer resources. `snapshot()` returns owned settings and the renderer's read-only model. The application owns controls, camera interaction and file selection.

Build with `pnpm --filter @automovie/human build` before running a browser consumer in the workspace. The package emits CommonJS for Node and an ES-module `browser` condition for bundlers. Both are compiled through the schema transformer, so browser JSON admission uses the same generated validator as published Node consumption. A plain TypeScript transpiler is not a replacement for this build step.

`createPortraitJawContinuation` forms the cranium and neck in reference coordinates when the jaw angle changes. Its inverse transform retains compatible current-point residuals. Only appended tissue is posed before common subdivision; resident face and lip vertices retain their shared performed positions. `portraitJawSkinWeight` supplies the oral-band weight shared with facial performance. Tissue behind the hinge and at or below the lower cervical section stays anchored. A monotone rational-quadratic angular transition joins the observed lower face to those fixed boundaries. The fully mandibular cervical region retains radius, angular order and unit endpoint derivatives; the oral band retains its existing weighted rotation at the facial end. The chin must lie below the hinge and above the lower neck; a transition consuming the remaining angular clearance refuses. Reference cervical ordering remains required. Matching observed/current jaw angles omit this extra path, preserving earlier observed geometry. This does not model TMJ translation or guarantee self-intersection-free skin throughout the oral band or complete head.

`neck.submentalProjection` adds anterior fullness to the collar-to-upper-neck transition independently of section width, depth and axis. It is an optional 0..40 mm authoring envelope, not measured fat thickness. The maximum is on the anterior meridian halfway through the transition; lateral and endpoint fades retain the collar and upper-section positions and tangents before common subdivision. Lower sections and the rear surface stay unchanged. Omission and zero retain the earlier geometry. Select the field in the neck region JSON or with `setHumanFaceDetail(document, "neck.submentalProjection", value)`; once selected, the detail panel exposes its numeric control. The shared head assembly and jaw continuation carry the formed tissue into expressions. Coupled construction and visual inspection remain required.

### Skin condition and expression folds

`recipe.skin` and `detail.skin` contain optional `IPortraitSkinShape` settings. `laxity` runs from zero (taut underlying shape) to one (full authored resting condition). `wrinkleDepth` and `wrinkleWidth` set persistent crease depth and transverse support in millimetres. Independent `forehead`, `glabella`, `crowFeet`, `lowerLid`, `nasolabial`, `marionette` and `perioral` amounts weight the anatomical families. `cheekSag`, `jowlSag`, `underEyeBag` and `volumeLoss` control separate soft-tissue movements, weighted by laxity. These are visible-shape authoring envelopes, not a biological-age predictor, recovered tissue measurements or an elasticity simulation.

`expressionCreasing` is independent of laxity. Current brow elevation/furrowing, lid closure, smile and pucker drive transient folds, so a taut face can crease while performing without acquiring permanent folds. Both sides share skin settings but follow their own current anatomical attachments and expression. Default laxity and expression creasing are zero; earlier documents retain their shape. `portraitSkinParameters` supplies the defaults, units, bounds and editor meanings, and `resolvePortraitSkinShape` refuses invalid values without clamping.

`createPortraitSkinLayer` samples actual anterior skin depth for curved crease valleys and broad tissue supports. Creases request local surface sampling through `refinePortraitSurfaceSampling`, while broad tissue-only changes retain the existing sampling. Shared tangent-guided midpoint insertion retains original vertices, material ownership and linear open rims before displacement and common normals. Faces incident to exactly coincident free-rim samples keep their common sampling until contact sealing, so local detail cannot split a closed lip's two sides differently. This interpolates the existing curvature; it does not recover unseen anatomy. Fine creases cost additional vertices and construction time. Strong combinations can still fail the engine's orientation checks. The numerical skin region supports scalar editing, whole-profile replacement, reset, history and portable JSON through the same editor transaction as other anatomy.

## Body below the neck

`body/` evaluates a connected body basis, the complement of the connected face's triangles below the neck ring, in the face's frame (metres, +Y up, +Z forward, +X anatomical left) so the two bases meet by vertex identity. The [body requirements](../../docs/requirements/actors/body-authoring/contract.md) and [basis, joint and measurement specifications](../../docs/specifications/asset-and-representation/body-authoring/contract.md) own the contract; the shipped basis and its receipts live in the [connected body study](../../test/studies/human-body/connected-basis/README.md).

`IAutoMovieHumanBodyBasis` carries ordered shape channels with explicit left/right mirrors, correctives driven by channel sides or clinical joint ramps, landmark-pivoted joints with pinned ranges, and one or more connected surfaces with four-influence skin weights. `createHumanBodyBasisBuilder(basis)` admits the basis once (`assertHumanBodyBasis`, `assertHumanBodyRig`) and evaluates a revision-bound document in the order channels → correctives → landmarks → skeleton → pose → skin. The document stores only named channel weights, ordinary non-humeral clinical joint poses, optional thorax-relative upper-arm tilt-and-torsion goals (`shoulders`), and material edits; an arbitrary vertex displacement is rejected. A shoulder goal gives its plane of elevation, total humerothoracic elevation and independent axial rotation. `resolveHumanBodyShoulders` derives the humeral local transform after girdle motion so 180° total elevation stays overhead. `humanBodyBasisWeights` and `evaluateHumanBodyShape` share the measurement path. `resolveHumanBodySkeleton` forms rest transforms from landmarks, and `skinHumanBodySurface` applies each bone's `posed ∘ rest⁻¹` through a unit dual-quaternion blend. A pose corrective is a rest-space row fired before skinning. A basis may declare `couplings`: an upper arm's TT total elevation, or another joint's clinical swing-cone elevation, drives a bounded piecewise-linear addition to another joint's axis. `resolveHumanBodyCouplings` returns those additions, the builder validates their summed angles without clamping, and the editor shows them without writing them into the document.

`measureHumanBodyBasisChannels` reports every channel's per-unit displacement and, for a channel with a rule in `HUMAN_BODY_MEASUREMENTS`, the girth, breadth, distance or height it measures at the neutral and at each end, so the editor prints `measureWaistCirc` as millimetres. `measureHumanBodySection` is the plane-cut instrument behind the girths: it reports the section's contour perimeter and its tape girth, the perimeter of the section's convex hull, which bridges the gluteal cleft and the inframammary fold as a tape does, and the girth rules read the tape girth. `segmentHumanBodyModel` partitions every built surface and material region by dominant bone for the crossing census, and `exportHumanBody` writes the evaluated static body to GLB or glTF through the face's exporter, without a rig.

The simple tier, `IAutoMovieHumanBodySimpleShape`, is the numbers a person knows about a body: sex, age in years, stature in metres, mass in kilograms, a muscularity, and optionally the tape measurements (waist, hip and bust girth, shoulder breadth). `expandHumanBodySimpleShape(basis, simple, over?)` turns them into the detailed channel weights a document stores, and the detailed tier stays canonical: applied over an existing shape it keeps that shape's residue, so the same values change nothing and a detailed edit survives an age or mass change. The expansion is the numeric table `HUMAN_BODY_SIMPLE_SHAPE` (product-of-curves rows for the age, sex, fat and muscle effects, with their clinical sources pinned in the study) plus measured inversions along directions (`humanBodySimpleShapeDirection`): stature against the basis's height rule and the head allowance, mass along the weight macro, whose field covers the whole skin, through the skin volume (`measureHumanBodyVolume`, each boundary loop capped and separate surface interior checked) at the age-specific Deurenberg fat estimate's density over the Jensen-child/adult head-and-neck share, and each girth against its rule (`evaluateHumanBodyMeasurement`), together until the weights settle. `projectHumanBodySimpleShape` reads the same values back off any detailed shape. A value the basis cannot reach is refused with the reach. The millimetre measurement channels are the middle tier between the two and need no structure of their own.

## Construction surface

`components/` owns cranial and cervical continuation, cheeks, orbital support, eyes and eyelids, nasal subunits and cavities, lips, dental arches and crowns, pinnae and material defaults. `geometry/` owns component attachment, shared subdivision, surface layers, contact, topology, mesh buffers and static face export. Each definition states its units and admission rules. The root barrel and the corresponding component or geometry subpath expose the same definitions.

`buildPortraitHead(host, components, rounds, layers, anatomy)` fits all selected components to the same input host, rejects overlapping cut ownership, joins their surfaces, subdivides common skin and resolves final contact. Optional `anatomy` selects cranial and cervical profiles. An empty component population leaves the host's facial skin intact. `createPortraitEyeComponent`, `createPortraitNoseComponent`, `createPortraitMouthComponent` and `createPortraitDentalComponent` receive caller-owned attachment bindings and shape values. Shape arrays are copied at admission rather than retained as mutable caller state.

`preparePortraitHead` owns the shared surface phase used by `buildPortraitHead`: fitting, attachment, continuation, refinement, surface layers, paired replacements, final proposals and reference colour sampling. It returns the unsealed millimetre surface, region ownership, component interior declarations and blended host source without generating interiors. `buildPortraitHead` then seals declared contacts, stages native interiors, derives common skin normals and packs the material regions and interiors. Legacy finishers consume the same final surface during ordered output. The preparation boundary preserves resident IDs and exposes no collision-free or anatomical-validity guarantee. Reference coordinates serve colour sampling; they are not a physical tissue rest shape.

`blendPortraitSkin` resolves all component attachments together on the original host connectivity. Exact pins and skin outside geodesic reach form the boundary of a positive inverse-distance graph interpolation. Its sparse Dirichlet solver checks the original equation residual before returning and refuses numerical breakdown or exhausted convergence. It preserves the caller's arrays and attachment order independence. Residual tolerance describes equation satisfaction; ill-conditioned geometry can amplify displacement error. This interpolation does not infer anatomy or simulate tissue elasticity.

`nose.body.shape.lobules` selects local anterior ellipsoid targets on the final refined exterior instead of the pre-fit cage. It uses the same `IPortraitNasalLobule` profiles and copied, depth-scaled attachment datums as `nose.lobules`, but the two cannot be stacked. Save the array through the complete nose-region JSON. `joinWidth` preserves the actual lining boundary and its tangent; lining vertices never move. `depthReach` has full influence through half its positive millimetre range about the retained tip Z, followed by a cubic fade to zero. Complete body/loft alternatives retain their prior depth support and remain incompatible with `depthScale`; local final lobules may retain that scale. Empty lobules are identity. Direct `createPortraitNasalBodySurface` callers selecting lobules supply the pre-fit sculpted positions as its final argument. This supports a more faithful transfer of an authored section, not automatic recovery of a photograph or a correction of an incorrect aperture.

A detailed `nose.body.shape` selecting a different `stations`, `section` or `lobules` alternative replaces the inherited shape payload. Fields within the same alternative keep ordinary partial-override behavior, as do the surrounding `joinWidth` and `depthReach`. Supplying several alternatives in one shape is invalid; switching does not silently retain the previous alternative's control grid.

`nose.envelopes` selects a complete exterior-to-vestibule construction per `bindings.nose.nostrils` entry. Each profile has `segments` (integer 2..64) and a nonempty ordered `sections` array of `{ at, width, crest, crestPosition, roll }`. `at` starts at zero and increases below one around the original cut boundary, by edge ordinal rather than arc length. Width is positive mm, crest is signed mm, crestPosition is strictly between zero and one across that width, and roll is the signed angle in degrees from the aperture-plane outward direction towards its section normal, using the independently owned cavity axis. One station is uniform; more stations distinguish alar, sill and columellar tissue. Periodic interpolation does not overshoot section values. The real nose component uses `createPortraitNasalEnvelope` both to support the host during subdivision and to replace its reserved region afterward. The aperture and rolled section are not subdivided again; skin and lining meet on the same Hermite jet. Existing cavity offset and contraction still own the interior. This alternative cannot combine with `rimSection`, curve `rimRefinement`, or a final `body` field. Omitted/empty arrays preserve legacy construction. Use complete nose-region JSON for editing, independent opening profiles, history and export. The profile is not a hidden-anatomy fit or a global tissue-clearance guarantee.

Optional `anatomy.performance` supplies the `IPortraitHeadPerformance` reference and pose callbacks. Reference coordinates form the cranial/cervical continuation; only appended vertices receive the pose. Both callbacks receive owned coordinates and must return finite XYZ in millimetres. Existing component vertices retain their current positions and shared indices. `buildHumanFace` connects this protocol to the jaw continuation field; direct assembler consumers may provide their own numerical field.

`eye.skinBridge: "sampled"` requires `skinAttachment: "reserve"`. It retains original-skin interior height witnesses inside the replacement annulus and redistributes interior edges before common subdivision. `refinePortraitSkinBridge` preserves the admitted boundary; a missing supporting sample refuses before attachment mutates the cage. Omission preserves the earlier boundary-only bridge. This changes skin reconstruction, not eye size or optical identity.

`portraitSkinAnnulus` uses the engine triangulator's `sourceIndices` permutation to retain actual skin vertex identities through canonical ring winding. The input XY chart is in metres; resident XYZ stays in head millimetres and is never reconstructed from the chart. Unequal ring populations retain each original ID, and the two authored rings must still have matching projected winding. This changes identity transport while retaining the same bridge triangles and the head's later subdivision and normal ownership.

`eye.upperLidProfile` supplies two through 32 complete medial-to-lateral sections for the margin, tarsal body, both crease banks, hood and preseptal transition. Every section has strictly ordered outward offsets, signed anterior projections and a farther live-skin attachment, all in millimetres. `createPortraitUpperLidProfile` uses the same order-preserving interpolation as `createPortraitLowerLidProfile`. The eye replaces its basic upper rows within a canthal sine fade; it does not add fold depth and volume twice. The wet aperture and optical dimensions remain independently owned. Use the complete eye region to save or replace sections, including independent left/right profiles. Omission keeps the basic upper formula. These are visible-surface controls, not a muscle simulation or recovered tissue thickness.

Optional `eye.upperLidProfile.closedSections` supplies a complete, strictly ordered unfolded target for a fully closed eye. It uses exactly the same witness positions and attachment distances as `sections`. Selecting it permits the observed hood to return inward across the crease; the remaining stations stay ordered, and the hood remains between the margin and preseptal skin. The shared engine planar predicate rejects a crossed or touching transverse curve at authored and sampled sections. During performance the same named rows interpolate by `(blink - observedBlink) / (1 - observedBlink)`. Reopening past the observation extrapolates and must remain valid. No closed target means the prior ordered shape and performance remain unchanged. Edit both arrays in the complete eye-region JSON, including unilateral overrides. The section test is not a proof that the final subdivided skin, optical contact and surrounding head are collision-free; those still require an actual build and multi-view inspection.

`eye.upperLashProfile` opts into independent upper-lash shape. Provide all seven fields, for example `{ length: 7.5, elevation: 10, curl: 40, fan: 60, radius: 0.065, taper: 0.92, variation: 0.12 }`. Length and radius use millimetres; elevation, curl and fan use degrees; taper and variation are fractions. Length is the maximum centreline arc length, reduced towards the canthi and by deterministic per-strand variation. `upperLashes` retains control of count. The seven detail sliders become available once the complete profile is present, and independent side overrides use the normal eye-region path. `buildPortraitEyelash` also exposes this geometry for a caller-owned root. The launch angles describe the observed head frame. During lid motion, the current root stays on the final margin and the strand turns by the shortest rotation between observed and current globe-to-lid directions. Gaze alone does not apply this turn. This rigid radial attachment preserves length and thickness; it does not model torsion about the radial axis, hair dynamics or collisions between strands. Omission preserves the original short upper lashes exactly. This profile does not add lower lashes.

`eye.globeLift` places the optical body independently of the surrounding skin attachment. Positive millimetres move it along the normalized observation ray toward the recorded camera; negative values recess it. The lid's inner contact follows the globe while its outer attachment targets do not translate with it. Shared subdivision and final optical contact still adapt the emitted skin; this is not a promise that every surrounding vertex stays fixed. This differs from `socketLift`, which translates the socket and its skin targets together. Omission or zero retains the original fitted globe. The scalar editor exposes a signed authoring envelope, not a clinical range; combined geometry still requires construction and render inspection. Blink and gaze use the resulting identity centre rather than adding the depth again.

Eye performance keeps a resident globe and rotates its iris/cornea about the fixed centre. `createPortraitMouthPerformance` pairs oral margins in 3D, preserving vermilion thickness during closure; `posePortraitJawPoint` supplies the shared transverse hinge calculation. `createPortraitFacePerformanceComponent` moves the adjacent lower face and the brow attachments, while an `observed-maxilla` dental attachment retains the upper arch. `sealPortraitContactSeams` welds only explicitly closed free rims and removes opposed commissural folds after common refinement. `buildPortraitEars` accepts an optional side selector so different pinna profiles can attach to the same temporal skin independently.

Final eye contact uses `portraitMinimumDirectionalSurfaceTargets` to minimize area-weighted squared travel against the resident optical support. The shared engine retains every clipped triangle condition and bounds each vertex by the previous conservative face-deficit correction. Distances use metres at this boundary; shared-skin propagation converts back to head millimetres. Closed margins retain their correspondence. The pinned [engine numerical kernel](../engine/vendor/quadratic/README.md) runs synchronously, including inside the editor worker, and refuses an incomplete solve. This is directional geometric contact, not a tissue model or a reconstruction of eyelid anatomy. Subsequent skin propagation and Float32 serialization still require contact inspection; neither solver convergence nor parameter input precision certifies anatomical accuracy.

`await exportHumanFace(model)` returns `{ glb, gltf }`: GLB bytes plus a glTF JSON document with its resident binary resources. It validates the actual Float32 output geometry and preserves supported optical material fields. The package owns both document construction and serialization, so these portable outputs work across CommonJS and ES-module consumers. Register `portraitGltfExtensions` when reading the assets with glTF-Transform.

`portraitDocument(model)` remains the low-level static document converter. Resident PNG data URIs in the base-colour and normal slots carry UV0, alpha masks and normal strength into the asset; external images, transformed texture bindings and other texture slots refuse. Normal RGB is linear tangent-space data. Export checks the PNG container header and positive dimensions; the receiving image decoder validates the compressed pixels. Its writer must use the same glTF-Transform module instance and register `portraitGltfExtensions`. Mixing CommonJS and ES-module Document/writer instances can silently lose geometry; prefer `exportHumanFace` unless the application deliberately manages that boundary. Both routes refuse bone bindings and unsupported resources; neither is a general scene or animation exporter.

### Surface hair and eyebrow cost

`recipe.hairLayers` and `detail.hairLayers` carry up to eight additional `{ id, profile }` populations. Each `IPortraitHairLayer` has a unique nonblank id and a complete `IPortraitHairShape`, so dense inner coverage and fine outer locks can use independent guides, coverage, pigment masks and normals. `buildPortraitHairGroom` assembles these layers with optional legacy hair, and `buildHumanFace` calls it directly. Additional parts use `scalp-hair-layer:<id>` and finishes use `human-hair-layer:<id>`; resident collisions refuse. A layer's base finish must belong to the input palette, never to a preceding generated layer. Empty profiles emit nothing but still validate their settings. The limits bound authoring cost, not biological density.

Select `hairLayers` and a named layer in the editor to adjust that profile through the existing hair scalar controls. `setHumanFaceHairLayerDetail(document, layerId, "hair.coverage", 0.8)` writes one field into a complete additional-population override while preserving the other authored profiles, guides and omitted fields. Applied profiles display normal strength zero, taper start zero and shade strength one when omitted; those display defaults are not written into unrelated layers. The `hair` region still edits the separate legacy owner. Individual layer scalars do not have an inheritance button because array inheritance restores the whole population.

The complete-region JSON editor replaces the additional population. Arrays replace completely, `[]` removes only additional layers, and inheritance restores the basis. Appearance controls expose each named resident base finish used by either population; sharing a base intentionally shares those base colours, while the layers' generated masks remain independent. Layer ordering does not change either layer's geometry or finish values. Omitted layers preserve the existing single-profile output.

Numerical setters detach containers along the edited path. Reusing one JavaScript profile object for several layers, sides or the basis does not link their edits: changing or removing a field on one owner retains every other owner's authored values. Shared material identities still intentionally refer to the same resident finish.

`hair.fibreShadeStrength` separates the procedural RGB pattern from the base finish's pigment. Omission or one preserves the original PNG bytes; zero uses white RGB without changing alpha, normals, guides or triangle count. Intermediate values interpolate the encoded RGB pattern towards white, not physical pigment concentration. The hair-region scalar editor and portable document preserve the [0,1] control. `createPortraitHairTexture` accepts the same strength as its fifth argument. Reducing it can retain pale hair colour without filling the gaps between fibres; it does not repair the groom or simulate light scattering.

`recipe.hair` or `detail.hair` supplies a complete `IPortraitHairShape`. Each `IPortraitHairCard` has root-to-tip guide stations, paired transverse width directions and an authored width in head millimetres. The author places those guides against the current scalp; changing cranial proportions requires inspecting and refitting their attachments. `buildPortraitHairCards` emits two triangles per longitudinal interval regardless of painted fibre count. Width, tip taper, coverage and segments have scalar editor controls; the complete guide array is edited through the hair region. An empty card array removes the hairstyle, while omission adds none. The supplied finish must exist and the derived `:hair-cards` finish identity must be free.

`createPortraitHairTexture` creates a deterministic 128 by 256 PNG with multiple painted fibres, sparse roots and staggered tips. The builder embeds that mask without a source photograph, network request or native image library. This is a bounded static card renderer, not a physical hair-scattering model, dynamic strand simulation or automatic hairstyle fitter. Inspect the front, sides and back for scalp gaps and card intersections.

`hair.fibreCurl` opts into a 512-square curled-fibre alpha and normal pattern. Supply all three values, for example `{ amplitude: 0.16, cycles: 4.8, aspectRatio: 0.57 }`. Amplitude is the maximum transverse excursion as a fraction of UV width, cycles is the nominal wave count along UV length, and aspect ratio is the nominal card width divided by its length for the normal direction. Seeded fibres vary their phase, amplitude and frequency. These are pattern controls, not measured hair diameters or a physical scattering model. Different card proportions can require different authored profiles; one nominal aspect does not infer every guide's metric. Zero amplitude or zero cycles can describe a straight pattern, but only omission preserves the original mask bytes. `assertPortraitHairFibreCurl` admits complete profiles, including for empty grooms. The hair-region editor saves the complete optional profile and exposes its three scalar controls once present. Pattern edits change rendered coverage and shading without adding triangles or changing the authored guides.

`hair.taperStart` holds a lock's full geometric width until the authored root-to-tip fraction, then narrows it linearly to `tipWidth`. Its [0,0.95] envelope leaves a positive taper interval. Omission or zero preserves the earlier full-length taper. A later start keeps the body of long hair covered without changing the root width, guide, UVs, painted mask or triangle count. The scalar editor and complete hair region both retain it; this control does not repair incorrect guide paths or an unsuitable hairstyle silhouette.

`hair.fibreNormalScale` adds a scalar editor control in [0,1]. `createPortraitHairNormalTexture` derives a linear RGB normal PNG from the same fibre centres and radii as the colour mask. Positive strength replaces the normal binding on the owned card finish; zero or omission retains the base finish's binding unchanged. One uses the full circular cross-section, while intermediate values scale the transverse normal. The texture and strength survive GLB/glTF export. This changes shading without adding triangles or changing the silhouette; it cannot repair scalp gaps or guide intersections.

Use base-colour alpha, not normal RGB, to determine painted coverage. A fibre centre can encode the same nearly flat normal as empty space. Conversely, a softened edge can retain a transverse normal when its small coverage rounds to zero in the 8-bit alpha channel. The normal texture describes orientation, not occupancy.

`createPortraitHairMaterial` supplies the builder's independent card finish and retains an explicitly authored base finish's `alphaCutoff`; omission uses 0.45. Set `alphaMode: "mask"` on that base finish when supplying a cutoff. This threshold changes coverage after texture filtering, not card geometry or the painted fibre population. Inspect the intended viewing distance: fine, sparse tips can disappear and reappear as their projected width changes. A lower threshold is an appearance choice, not a geometric collision repair.

`eye.browProfile.representation: "ribbon"` uses skin-following strips instead of the default eight-sided tubes. At the same longitudinal sampling it uses one eighth of the triangles. Both paths keep the current brow boundary and surface contact, so brow elevation moves the attached hairs. Omission preserves earlier documents.

`eye.browProfile.flow` authors two through 32 medial-to-lateral direction witnesses. Each section has `at`, `lower` and `upper`; each direction gives a `tip` across the supporting brow (lower zero, upper one) and signed `outwardBend` in millimetres. Lower and upper address the ends of `rootBand`, allowing upper hairs to converge downward with lower hairs. `createPortraitEyebrowFlow` blends along the brow with cubic smoothstep and across that band linearly; a collapsed root band uses the midpoint direction. Flow replaces the ordinary `span` and `outwardBend` in both tube and ribbon construction without adding fibres or subdivisions. Omission preserves the basic direction formula. Save or replace the complete profile through the eye region, including independent side overrides.

Set `eye.browProfile.densitySeed` to an unsigned 32-bit integer, including zero, to thin faded ends independently of root height. Different seeds select different retained strands without changing each strand's dimensions; no random state enters replay. With no endpoint fades the seed changes no geometry. Omission retains the original coupled density pattern for existing numerical documents, including the time-capped study; that pattern can leave root-height bands empty near faded ends. New authored profiles can select the independent pattern explicitly.

The extraction initially retains the `Portrait` symbol names so the existing measured subject and its regression tests replay the same calculations. Subject coordinates and settings live in the test studies, outside this package. A successfully constructed or exported face is not by itself an accepted likeness.

## Browser editor and studies

Run `pnpm --filter @automovie/playground dev` from the repository and open `/face.html`. The development command builds the human browser entry before starting Vite. The page exposes the nineteen issue subjects, intermediate traits, scalar and complete-region detail, independent sides, expression presets/channels, material colour, roughness and clearcoat, orbit views and clay. Model construction runs in a worker. Failed geometry keeps the last valid model; history and JSON/GLB/glTF downloads refer to that committed state. A JSON glTF download also needs all its sibling buffer and image files in the same directory.

The [reference studies](../../test/src/subjects/README.md) own photo selection, numerical fits and observation status. Their files are examples, not defaults shipped by this package. Reconstruction remains provisional: single-view depths, posterior anatomy and material choices are estimates; matching landmarks and passing topology checks do not establish photographic identity. Reproducibility should name the runtime and compare both numeric geometry and serialized bytes; separate JavaScript runtimes can differ at floating-point rounding even for the same document.
