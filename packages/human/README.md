# @automovie/human

A human figure generated by code from typed parameters: body measurements, head dimensions, and optionally appearance, pose and expression. The result is an ordinary `IAutoMovieModel` in metres, so the engine and viewer treat it like any other model.

Human is optional in a production. Reach for it when a shot needs a particular person's build and face; a stick figure carries motion at a fraction of the cost. The package is being rebuilt, so expect its surface to change.

## Use

Node.js 22.23.2 or later.

```bash
npm install @automovie/human
```

```ts
import { AutoMovieHuman, type IAutoMovieHumanParameters } from "@automovie/human";

declare const parameters: IAutoMovieHumanParameters;

const { model } = AutoMovieHuman.generate(parameters);
```

`body` and `head` are required and everything else is optional. Each field's JSDoc gives its unit and what an unknown value means. Four complete parameter sets are in the playground's [`human-parameters`](../playground/src/human-parameters).

## Entry points

- `AutoMovieHuman.generate` returns the neutral body for one parameter set.
- `AutoMovieHuman.prepare` generates once and also returns the skeleton and an evaluator. An `AutoMovieHumanInstance` then holds one pose, expression and root over that shape, so posing never regenerates the body.
- `AutoMovieHuman.diagnose` lists the optional pieces that broke their contract and fell back to a base shape. It is empty for a sound figure.
- `AutoMovieHumanCanonicalBody.prepare(parameters, { mass, id })` builds the skeleton and contact profile on the canonical humanoid rig without any skin. This is the body `@automovie/motions` performs with.

## More

The anatomy, sources and lofting technique behind the generator are written up in [`docs`](./docs/README.md). The [debug viewer](./debug/README.md) is a development tool in this repository, not part of the published package; `pnpm debug` in `packages/human` serves it on port 5197.
