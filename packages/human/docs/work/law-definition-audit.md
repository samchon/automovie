## Modeler handoff definitions

The existing hand convention permits a pure bone construction without the old hand skin. It packs unequal MCP skin-breadth proxies inside hand breadth and divides the remaining width into three equal gaps (`anatomy/hand.md`, Finger widths and webs). This is a conventional placement rule, not a measurement of MCP joint-centre spacing. `DigitInterim` currently uses the second digit joint's skin breadth at the base, so that value can be named as a proxy without claiming it is an MCP caliper measure. A nonpositive remaining width needs an explicit input/placement decision, not silent negative gaps.

Keep the joint datums distinct: palm length reaches digit III's base crease; `WEB_HEIGHT = 0.1533` is the web above MCP III per web-to-tip length, not per MCP-to-tip length. `HandJoints.knuckles` currently computes `palm - 1.5 - 0.1533 * (handLength - palm)`. Reddy's 0.711/1.039/1/0.883/0.797 are metacarpal total-length ratios; `THIRD_METACARPAL = 0.774` converts a separate wrist-centre-to-MCP-III reach. Neither ratio determines transverse bases, thumb opposition or skin root centres. Level metacarpal bases and the thumb CMC position remain explicit conventions. Buryanov's interarticular distances becoming joint-centre spacing are a separate modelling inference.

One independent hand reach candidate uses de Leva's WJC-to-MET3/WJC-to-DAC3 ratios, female `78/170.1`, male `86.2/187.9`. For `T=handLength-delta`, the reaches are `rho*T` and `(1-rho)*T`; delta must use the actual stylion-to-WJC datum, not mix the source note's 1.5 mm forearm offset with its 2.2/2.4 mm hand offsets. MET3 is a metacarpale landmark, so treating it as an MCP joint centre is a stated proxy. For Buryanov web ratio w and MCP-to-tip reach F, web-to-tip is `F/(1+w)`. The public crease station remains independent. These are candidate constructions handed to BODY, not new measured joint-centre laws.

For foot breadth, use the same long-axis frame for the source curves and measuring device. Let `M=max z - min z` over the metatarsal-head region, excluding toe splay; extrema can occur at different along stations. Mapping every across coordinate by `z_new=(B/M)*z_old` preserves asymmetry and enforces the independent support width B when M is positive. Define the head region and solve the complete curves' extrema, rather than using only knots. Along coordinates retain their own length normalization. A formula using `l(s_b)+m(s_b)` is valid only for a same-cut breadth; the Brannock maximum does not establish that premise. Ball girth remains a separate 3D tape through heads I/V, and the first-head axial distance alone does not place the fifth head.

`FootToeJoints` documents its phalange shares as conventions awaiting measured lengths. `FootInterim.toes` currently uses one middle centre and a tip offset; these are not independently defined MTP/PIP/DIP centres. Move the anatomical toe-line record to one owner before using it for rig and skin, preserving the distinction between the bony tip and the skin's dome reach.

For the neck seat, write `m = stature - headHeight`, `c = cervicaleHeight` and `r > 0` for the current neck ratio. The inspected code has `L = max(0, (m-c)/r)` and `seat = m-r*L`. If `m >= c`, the result is `c`; otherwise it is `m`. Thus the ratio cancels without supplying a new anatomical law. Published neck lengths do exist with other datums: Roos 2020 uses the C7-to-tragion vertical distance, whereas the AMVO anterior length reported by NHTSA runs from suprasternale to the head-neck junction under the chin. Neither is this internal `L`.

The existing `leg/AutoMovieHumanLegSectionRows` is a more directly defined skin-shape source than reinterpreting `LegPrior.forward`: its eight angular guides contain normalized radii and two angular derivatives about the area centroid. `LegGuides` and `LegProfile` carry their channels along anatomical stations. Their normalization does not retain centroid-to-mechanical-axis translation. BODY must own that placement datum separately, and must compute actual front/back support extrema from the reconstructed sections; the radius at angle zero need not be a forward extremum when its angular derivative is nonzero. No new private reading or fitted centroid shift is implied.

## Equations for the source-curve batch

The published upper-lid record is `AutoMovieHumanReferenceOutlines.SHIN_UPPER_LID`, assigned to HEAD's `head/AutoMovieHumanHeadEyeParts.ts`; the inspected file has globe views but its margin import is still pending. The record contains S3's cubic four-point matrices, not the inconsistent introductory five-point prose. Its source note records the direct reading. For points Q0...Q3, `C(t) = (1-t)^3 Q0 + 3(1-t)^2 t Q1 + 3(1-t)t^2 Q2 + t^3 Q3`. End tangents are `3(Q1-Q0)` and `3(Q3-Q2)`. Interior extrema require roots of the quadratic derivative; control-point extrema alone are bounds, not the curve's actual extrema.

An endpoint-preserving transfer separates the source chord from its shape. For source C(t)=(u,v), let `s=(u-u0)/(u3-u0)` and `e=v-[(1-s)v0+s*v3]`. For chosen 3D endpoints A/B with `|B-A|` equal to public en-ex, use `P(t)=A+s(B-A)+k*e*U`, where U is world up. Since e=0 at both endpoints, their 3D distance stays fixed. For two margins at the pupil station, `k=Hvertical/[eUpper-eLower]` preserves a chosen vertical gap if the denominator is positive. If H is instead the 3D Ps-Pi distance, equal across coordinates and a forward difference df require `Hvertical=sqrt(H^2-df^2)`, or solve the full distance directly. Equal forward coordinates make the two metrics coincide. This derivation supplies no lower-margin or depth law. Shin's medial commissure still needs explicit reconciliation with the public endocanthion.

For a cubic Hermite scalar across-coordinate x over a station interval h, the equivalent Bézier controls are `[x0, x0+h*m0/3, x1-h*m1/3, x1]`. Requiring all four to lie in `[lo,hi]` bounds the entire curve there. For a median bound x>=0 this gives, among the endpoint conditions, `m0>=-3*x0/h` and `m1<=3*x1/h`. The engine must preserve those controls/jets through its later loft conversion; a second unconstrained spline can undo the source constraint. A chosen piecewise scheme must also match the required shared derivatives at joins.

For C2 Hermite segments, a quintic's controls are `[x0, x0+h*m0/5, x0+2*h*m0/5+h*h*a0/20, x1-2*h*m1/5+h*h*a1/20, x1-h*m1/5, x1]`. Shared endpoint slopes m and second derivatives a give C2 joins; all six controls inside the support interval bound the whole curve. Setting every jet to zero proves feasibility for in-range values but flattens stations, so it is not an automatic anatomical choice. Shape-preserving PCHIP is generally C1 and cannot silently replace a required C2 law. CORE owns admission and loft preservation, not this data module.

For a neck ring `R(t)=[cx+lambda*a*X(t), y0+k*Y(t), lambda*Z(t)]` with a chosen aspect a and fixed vertical course, its actual tape is `P(lambda)=integral sqrt(lambda^2*(a^2*X'(t)^2+Z'(t)^2)+k^2*Y'(t)^2) dt`. Solve `P(lambda)=G`, not the xz-only perimeter. The lower limit is `integral |k*Y'| dt`; a tape below it is incompatible with that retained course and requires an explicit diagnostic or a changed course definition. Polyline perimeter only proves the polygon's tape; an analytic/spline ring needs its own arc-length accuracy bound.

For a loft surface P(s,t), guide positions alone do not fix normals: the surface normal is proportional to `dP/ds cross dP/dt`. At a named across extremum, its across derivative in t is zero; its whole ring must remain between the corresponding support planes. A separate top ring owns its own cut's interior shape and must agree with those guide intersections and jets. Shrinking it to compensate for a different guide or input changes the construction contract.
