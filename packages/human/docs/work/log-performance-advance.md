## Method and alternatives

[MIT's surface-intersection treatment](https://web.mit.edu/hyperbook/Patrikalakis-Maekawa-Cho/node109.html) derives local marching from surface differential geometry and discusses adaptive numerical integration, while noting that marching alone does not discover every component. [Lundberg and Poore](https://epubs.siam.org/doi/10.1137/0912037) discuss predictor-error step control with Newton correction back to an implicit path. These support separating a local proposal controller from correction and global branch discovery; they do not establish this implementation's constants or global accuracy.

The chosen dyadic controller uses an already measured world defect no greater than one eighth of the unchanged acceptance allowance before proposing a doubled next step. That is a proposal heuristic; every new candidate is corrected and checked independently. The interface guarantees only exact two-jets, so no cubic local-error law is assumed across every supported C2 source. A one-third-power controller needs stronger error-model qualifications, and a Newton-iteration controller would require exposing additional solve state. Both are larger changes than this local proposal policy.

[BifurcationKit's continuation documentation](https://docs.sciml.ai/BifurcationKit/stable/library/#BifurcationKit.ContinuationPar) separates step adaptation, step-size bounds and a maximum continuation-step count. Its default count concerns a whole branch and is not copied here. Root explicitly chose the 1024-candidate per-call protection as product policy. At most 1024 calls to the existing atlas solver occur; each can still perform up to five face attempts, bounded Newton/backtracking and rate solves, plus its actual surface/law callback costs. Retained call state stays constant in the number of candidates; no cache, task, extra surface model or retained candidate history is added to production.
