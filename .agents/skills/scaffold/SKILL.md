# Scaffold

A production's own `AGENTS.md`, `README.md`, and source own its meaning; read them and the installed package APIs before interpreting, authoring, or reviewing it. Repository instructions never override them.

- The scaffold owns its production skills, directly linked resources, and contracts; they describe making a production, not developing this repository. Read its [production skill](../../../packages/template/scaffold/.agents/skills/production/SKILL.md) before changing that workflow. Installed package APIs own API documentation; the scaffold does not duplicate them. `@automovie/evidence` owns reusable evidence defaults, graph composition, and checking; the scaffold keeps one options object and a thin checker entry.
- The primary output is a whole deterministic motion-video hint from a complete LLM-authored screenplay: program the main scenes' motion and staging, then assemble the full video. Stills or pilot clips do not complete that commission. The production's [motion skill](../../../packages/template/scaffold/.agents/skills/motion/SKILL.md) owns programmatic choreography, constraints, scene time, and engine feedback; 3D modeling owns its asset representations. Simple representations must accurately carry the intended performance; Human and detailed 3D are optional. Keep separately commissioned screenplay, whole motion hint, finished direct 3D film, and finished post-diffusion film distinct. Direct 3D needs no diffusion, and a motion hint needs no finished diffusion film.
- Default lint and evidence configurations serve ordinary TypeScript development; narrative work opts into its additional workflow while retaining engineering checks. Long-form work preserves settings → treatments → scripts → final screenplay, with construction, expression revision, evidence, current independent review, and whole-work completion. Short video enters at final screenplay, and asset-only work has no narrative. Compact questions within those responsibilities rather than removing the architecture.
- The [instruction synchronizer](../../../packages/template/build/syncScaffoldInstructions.ts) mirrors only `development/repair.md` and `documentation/writing.md`. These copies are ignored by git and regenerated on `prepare` and `build`, so edit their repository sources and keep repository-only rules outside them. A newly shared path must also enter the root `.gitignore`.
- When retiring a mirror, remove its old generated files from existing checkouts before packaging; untracked files under `scaffold` can still ship.
- The generated project-root `PROJECT.md` owns adopted production scope, delivery and setup decisions; `docs/instructions` owns creative instructions. Runtime README and `.env.example` own nonsecret operational setup and variable names, ignored `.env` holds actual secrets, and `src/integrations` can hold provider or local-tool code.
- Installation is one-way: generated instructions, contracts, configuration, and authored files belong to the production, and package upgrades never overwrite them. Reusable package implementation stays with its package.
- For changed installation behavior, observe a generated project's installed entry point and its `lint`, `evidence`, and `test` commands.
