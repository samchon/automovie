# Documentation

Every document follows [Writing](writing.md). A README adds the rules below, and the project's development skill says what a doc comment must contain.

## READMEs

Write a README from the view of the person who uses its project or package, and keep it to the essentials:

- what it is and when to use it;
- how to install and start it;
- the few entry points;
- where the detail lives.

A README lists no API that the source and its types already own, because such a list goes stale at the next change. It carries nothing that only a maintainer needs. Every name, command and sample in it exists in the code, and every sample runs.
