# Verify the design and its reach

Finish a complete inspection round over the changed strategy, questions, callers and consumers before repairing findings together under [review](../review/SKILL.md). Check every declared failure against its cause and contributing conditions rather than revising one symptom and rerunning.

## Inspect the actual inputs

Check frontmatter, directory names, AGENTS triggers, local links and referenced H2 identities. Follow each changed rule from its entry point to the actual task and contract, repair owner and handoff. Keep repository rules outside the production bundle. A Markdown-only change needs these checks and its affected-consumer review; it does not justify inventing a test or generating a disposable production.

Inspect the materializer's rendered file map when changing what production instructions ship, including substitutions and any generated shared resources the changed links use. Installed files are project-owned: an existing production update follows [scaffold](../scaffold/SKILL.md), not an assumed upstream sync. Changed installation or program behavior requires development's actual consumer checks.

## Compare decisions before claiming effects

Use actual tasks and retained failures with their strongest legitimate counterexamples. Select cases affected by the change rather than requiring every project to run a universal suite. Useful route contrasts include a screenplay-only task, direct and compact-settings short routes, a complete coarse motion hint, and a commissioned finished film.

For a changed expression criterion, compare preserved meaning with the experience made by actual language, image, sound and timing. Check an informative but ineffective passage and a deliberate restrained form; a function list cannot acquit the first and a style label cannot condemn the second. Confirm that the existing overall question can judge what sentence classification alone misses.

When an independent context is available and authorized, give it the real task and minimum raw inputs without the expected answer, author defense or prior verdict. Observe which resources it reads and the artifact and decisions it produces. Preserve the actual result and limits. Do not launch an agent solely because a design changed when the user's delegation rules prohibit it.

Report what was established: instruction consistency, rendered distribution, observed author behavior, actual media result or unavailable checks. Static case comparison does not prove better storytelling, a clean sentence table does not approve the whole experience, and an instruction-only change does not verify an unrendered film.
