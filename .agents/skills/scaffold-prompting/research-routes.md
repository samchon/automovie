# Research routes

Read the relevant original before adopting a new instruction, and keep its support separate from the production judgment. These sources inform design: a source's existence or another medium's successful example does not establish improvement here.

| Source | What to examine | Application limit |
| --- | --- | --- |
| [Anthropic: Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5) | Clear goals, current context, explicit operating boundaries and observed harness behavior | Model-specific guidance needs verification on the actual author and task; it supplies no film-quality acceptance |
| [AFTRS: Screenwriting](https://medialab.aftrs.edu.au/wp-content/uploads/2021/07/AFTRS16_Screenwriting.pdf) | Resource-aware short-film design, characters, dialogue, rewriting and the handoff from script to production | This teaching resource's duration and cast suggestions are not universal limits for shorts, abstract films or other adopted forms |
| [Google Cloud: Veo best practices](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/best-practice) | An unchanged character description in every prompt that describes the character, and motion only from a source image, speech marked by a colon instead of quotes, and one event per shot rather than a chain | Written for Veo; another model's guide can mark speech differently |
| [BytePlus: Seedance 2.0 prompt guide](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/seedance-2-0-prompt-guide) | Fewer reference images than the limit, a headshot with a full-body image, and multi-view sheets read as several subjects | One model's reference handling |
| [Runway: Gen-4 references](https://help.runwayml.com/hc/en-us/articles/40042718905875-Gen-4-Image-References-Guide) | Even light and a neutral expression in a character reference, and one image enough for identity | One vendor's reference handling |
| [FreqEdit](https://arxiv.org/abs/2512.01755) | Quality loss across repeated image edits, from the gradual loss of high-frequency detail | Measured on editing benchmarks, not on a production's canon sets |
| [LooseControl](https://arxiv.org/html/2312.03079v1) | Why plain depth from approximate boxes generates box-shaped objects, and a looser depth condition for scene boundaries instead | A research method; hosted image models expose no such control |
| [ScreenSkills: Script supervisor](https://www.screenskills.com/job-profiles/browse/film-and-tv-drama/technical/script-supervisor-film-and-tv-drama/) | Script breakdown, timing, dialogue, action, eyelines and prop continuity across actual takes | A role description supports those responsibility boundaries, not a required document template or a native Evidence guarantee |
| [OpenBMB: VoxCPM](https://github.com/OpenBMB/VoxCPM) | Current installation, model inputs, fixed recordings and speech generation | Inspect the installed version's actual signature and execute it; a remote example, seed or model load does not establish usable speech or synchronized delivery |
| [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html) | Actual trimming, timestamp rebasing, resampling and retiming behavior | An encoder's success cannot establish retained action, intelligibility, synchronization or final playback quality |
| [Luma: Ray 3.2 video to video](https://lumalabs.ai/learning-center/articles/ray-3-2-video-to-video) | Separate motion and structure adherence, body-tracking modes, what low motion adherence keeps, the overlapping movement edits tend to lose, the face hold, shaded rather than flat sources, and turning prompt enhancement off | One vendor's settings; its scales do not transfer to another model |
| [fal: From clay 3D render to a real action short](https://blog.fal.ai/from-clay-3d-render-to-a-real-action-short-a-3d-to-ai-pipeline-with-total-control/) | An agent-built gray-box film finished by a video model: takes per shot, every key element in the first frame, framing repaired in the 3D camera, secondary motion authored in 3D, and an action prompt per shot for an adapter trained on gray layouts | One production's workflow and budget, with a person selecting at every stage |
| [LTX: Layout to Render](https://docs.ltx.io/open-source-model/vfx-post-production/layout-to-render.md), [IC-LoRA](https://docs.ltx.io/open-source-model/usage-guides/ic-lo-ra.md) | A gray layout animation turned into a finished shot at full strength from a restyled first frame, and the control adapters' strength and masks | An open model's adapter contract, which proprietary models do not expose |

Use the production's existing source, motion, audio and delivery records for observations. Keep a local tool failure and its correction with that tool's owner; do not turn one production's workaround into a mandatory scaffold rule.
