# Evidence configuration

Make the graph select the work and respondents that can establish the requested deliverable. Read the adopted requirements and [contracts](SKILL.md), then choose the route, population, and owners under [scope](scope.md). A screenplay, a film-generation hint, a finished film, and a standalone asset have different output observations; selecting one does not claim a later deliverable exists.

Read the installed `@automovie/evidence` README, public types, and JSDoc before changing the production's `evidence.config.ts`. They own supported options, graph composition, protected-input rules, and checking behavior. Installed `@wrtnlabs/evidence` documentation owns native selectors, annotations, addresses, and fingerprints. Use those APIs rather than copying a factory or maintaining local API instructions.

Keep one production configuration object and retain its engineering baseline when adding narrative duties. Bind every additional work or language requirement to its actual respondent population, layer, and pass. Keep questions, selected targets, respondent hosts, actual parent relationships, and review mirrors aligned; narrowing a selector cannot repair a failure of the work.

For a scope or layout change, inspect all affected populations and relationships together, including material outside a pilot and inactive narrative inputs protected from engineering claims. Resolve ownership before changing selections. [Upstream repair](../screenwriting/repair.md) owns changes that touch closed narrative proof or scope; preserve its boundary when updating the graph.

Hand a consistent configuration to [source, asset and delivery evidence](answering.md) for those answers, or [narrative evidence](../screenwriting/evidence/writing.md) for creative work. Narrative [writing workflow](../screenwriting/workflow.md) owns construction submission and pass checks, and [rewriting procedure](../screenwriting/rewriting/procedure.md) owns expression transfer; media [finishing](../production/finishing.md) owns the actual assembled output. Configuration and mechanical coverage grant neither creative approval nor output acceptance.
