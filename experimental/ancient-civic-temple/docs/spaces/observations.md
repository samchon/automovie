Follow the [CJS boundary](../settings/50-production.md#runtime-boundary). `src/viewer/server.cts` calls production source/public engine in CJS and passes current environment, actual meshes/transforms/materials, and same-generation observations. Browser imports no Node/engine runtime, rendering received geometry with actual 3D perspective, lighting, shadows, and depth without rebuilding the building as client data. Executable code belongs in src; HTML/style assets in public.

Server passes that environment to public `lowerBuiltEnvironment` for element placements including current leaf states and parent/child transforms, retaining original environment for spatial/boundary/opening measurement. Lowering `set` is world placement of elements bound to actual models, not wall/roof generation from boundary declarations. [Surface owners](ownership.md#surface-map) must supply visible solids as actual elements/models; logical volumes, boundaries, or bounding boxes do not replace them.

Preserve node/element/model/part identity, geometry, and material bindings. Public server tessellation supplies primitive triangles; explicit meshes retain original positions, normals, UVs, colors, indices, and absent attributes. `tessellateToMesh` UVs are `null`, not generated texture coordinates. Geometry/material owners provide necessary UVs; transport adds no arbitrary coordinates. Keep element world and part local transforms distinct without applying the same transform to vertices and nodes twice. Distinguish model-local materials from full-population lookup. Missing bound materials must fail rather than yielding a successful differently colored default-material view.

Support patches declare foot support/measurement rather than default physical floors. Render floors, steps, and ground from actual authored geometry. Distinguish supports/logical boundaries only in explicit inspection modes, excluding them from default color/depth/shadows so they cannot hide missing structure. Yard logical caps likewise generate no sky-blocking faces. Do not directly use existing viewer helpers that runtime-import engine in browsers; server-output rendering respects this module boundary.

When repetition is added, distinguish authored `IAutoMovieInstanceSetDesign` returned by lowering from actual compiled repetition. Pass prototypes and placements from the repetition owner's same rules/inputs; viewer chooses no new column/tile counts or spacing. Do not report uncompiled sets as compiled quantities or silently omit untransmitted repetition. Viewer, observations, and measurements share the same current generation. Transport values serve runtime only, not a separate JSON project store.

Server accepts `--port`, defaulting to user-specified 4175. The off-canvas English observation UI provides space/observation selection, exterior orbit/zoom, and explicit inspection modes. Labels, routes, boundaries, and cutaways default off. Compilation errors replace stale successful views with current errors and are not normal delivery. Package.json's `viewer` script/dependency declarations own code, dependencies, and startup; coordinator keeps the server running. Under the 2026-09-22 user correction, dependency changes require author-run root `pnpm install` and production plus changed `pnpm-lock.yaml` in the same commit.

Provide space descriptions and target text lists, with keyboard selection of spaces, views, and inspection modes. Selection/failure cannot rely on color alone. This access interface supports observations; actual successful operation requires viewer-source/observation verification.

Start from production root with `npm run viewer -- --port 4175` and open `/`. Lint.config.ts is the sole stage declaration; use no bypass source paths, arbitrary selectors, or ESM conversion. Every author self-check opens the page through Playwright `chromium`, checking hardware GPU RENDERER (ANGLE D3D11), no console errors, and nonempty canvas. This proves delivery-path operation only; room-reference reading and visual judgments after materials/members remain each stage's observations.
