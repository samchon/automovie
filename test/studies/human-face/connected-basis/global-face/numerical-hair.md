# Numerical hair migration

Issue [#2533](https://github.com/samchon/automovie/issues/2533) requires personal differences to be scalar or enum inputs to a common generator. A personal guide array selected by a resource name does not meet that requirement. The numerical implementation lives in `packages/human/src/face/anatomy/hair`; the connected worker calls it through the face basis builder for both preview and export.

The current `subjects.json` contains eighteen numerical hair documents, and the personal `grooms.json.gz` archive has been removed. Basis, documents and simple controls now name `mpfb-connected-head-2026-09-22-numerical-hair`. The [migration receipt](numerical-hair-migration.json) records exact sources and outputs. This is a representation migration with initial authored styling inputs. It does not approve the eighteen people, their likeness, anatomical validity or hair contact.

The eighteen documents total 154,119 bytes, including all facial weights, expression, skin fields, material overrides and numerical hair. Their previous total was 115,091 bytes; the removed personal guide archive was 3,528,872 compressed bytes. Every non-hair personal value is exactly preserved. The shared basis grows by 8,247 compressed bytes for scalp and query-closure metadata; its facial positions, targets, topology and materials remain exactly equal. Generated GLBs and pixel buffers are derived output, not additional personal authoring inputs.

## Shared correspondence

[`hair-topology.json`](hair-topology.json) records scalp membership against the exact `Human` surface of `mpfb-connected-head-2026-09-21-fine-141-rigid`. Its neutral Float64 and connectivity Uint32 hashes use little-endian encoding. Changing either source invalidates the metadata; the preparation helper refuses that mismatch.

The scalp comes from source polygon membership in [MPFB commit 817587ceb2ea03ea17a5b47e04396cbb4ddfa2d5](https://github.com/makehumancommunity/mpfb2/tree/817587ceb2ea03ea17a5b47e04396cbb4ddfa2d5), one subdivision and exact triangle-coordinate correspondence. All 2,672 triangles matched. The chart origin is the neutral `Human/skin` axis-aligned bounding-box centre in head metres. The [source license](https://github.com/makehumancommunity/mpfb2/blob/817587ceb2ea03ea17a5b47e04396cbb4ddfa2d5/LICENSE.md) distinguishes graphical assets/output from application code; no MPFB application implementation is copied here.

The 182 closure triangles reverse the existing planar neck boundary and use existing vertex identities. They close the signed-distance query only; they are neither displayed nor exported. The generic builder checks closed oriented manifold connectivity. Embeddedness, outward orientation and preservation under each facial deformation still require verification.

## Preparation and actual export

Run from `test/`, choosing new output directories. The first entry reads only shared basis and metadata, produces an independently owned candidate and writes byte hashes. The second reads an explicitly supplied numerical document and calls the same runtime used by the connected worker. It writes `model.glb`, `model.json`, `document.json` and a receipt after both preview and export succeed.

```sh
pnpm exec ttsx -P tsconfig.scripts.json scripts/face-review/prepare-numerical-hair-basis.ts HISTORICAL_BASIS_JSON_GZ studies/human-face/connected-basis/global-face/hair-topology.json mpfb-connected-head-2026-09-22-numerical-hair NEW_PREPARATION_DIRECTORY
pnpm exec ttsx -P tsconfig.scripts.json scripts/face-review/export-numerical-hair.ts studies/human-face/connected-basis/global-face/basis.json.gz PATH_TO_NUMERICAL_DOCUMENT NEW_OUTPUT_DIRECTORY
```

The preparation command above takes the historical source basis. Recover that exact `basis.json.gz`, `subjects.json` and `simple-controls.json` from commit `3bc7702058484fc8aa9bd2f648023c466abf98d2` into a separate directory; the current basis already contains metadata and deliberately refuses a second preparation. `migrate-numerical-hair.ts` takes six explicit arguments: historical basis, prepared basis, historical documents, historical simple map, numerical profiles and a new output directory. The current `subjects.json` supplies the profiles' `id` and `hair` fields, so there is one canonical owner of those values. The migration refuses changed facial geometry, duplicate or missing identities, stale revisions and invalid numerical inputs. It preserves all other document values and writes both documents and the rebound map. `prepare-fine-basis.ts` also reads pinned historical documents and guide data from Git; the earlier one-off revision scripts must be run against their declared historical predecessor, not against the current directory.

The styling candidates were authored after inspecting the eighteen source photographs. Length, flow, part, lift and curl values are estimates for this generator, not anatomical measurements or inverse reconstructions from a single photograph. RGB and roughness retain the historical numerical finish values. No historical root, guide, ribbon or personal image is an input to generation. Tied, gathered and updo structures visible in several references are not yet represented faithfully by the current field model; those are unresolved expression capabilities, not accepted hairstyle matches.

Use `IAutoMovieHumanFaceBasisDocument` with that new basis identity. Its `hair.layers` hold `IAutoMovieHumanFaceHair.Layer` values. A layer names a shared `surface` and `domain`, then supplies root population, four hairline angles, six regional lengths, flow, lift, optional parting, curl, taper and procedural finish. Generated root positions, curves, mesh buffers and PNG pixels are derived outputs. The layer schema has no personal guide, photograph or mesh-resource field.

An optional `rootRegion` supplies a centre and three positive metre-space standard deviations. It weights the common scalp area by a diagonal Gaussian and preserves the requested accepted-root count. This lets independent layers occupy different parts of the scalp while keeping length, flow and curl editable. It is separate from `part.region`, which weights styling after roots have been chosen. Neither field stores individual follicle or guide positions, and neither is calibrated biological density.

The native preparation produced a 23,491,139-byte candidate basis with SHA-256 `5dbb05ff01925fa6fca8af6e46720d4735ef8a36fba5f7a77dfe2666cfbf2a35`. The extra shared metadata accounts for 8,247 compressed bytes relative to its source. A diagnostic with 1,024 strips produced a 9,219,732-byte full-face GLB; that export size is not the personal numerical input size. These are observations for these inputs, not a storage or performance guarantee.

## Observed limits

The [historical length audit](hair-length-audit.json) records all eighteen sources and source hashes. `sample-historical-hair.ts` reads an explicitly selected historical basis/archive through the actual resolver and card tessellator; its output is offline observation data. The six-axis length fit has RMSE 4.54 to 151.71 mm across those sources. Several old root populations occupy narrow crown strips rather than the common scalp. These coordinates are not anatomical ground truth, and copying them into a new resource or an enum would retain the rejected representation. A fitted length objective alone does not accept a hairstyle.

The current static direction field is a styling model. Strip count is a geometric sampling control, not follicles per square centimetre; lift is a directional bias, not elastic stiffness. The free-strip signed-distance bound does not establish root-fan or hair-to-hair nonintersection. The editor exposes that distinction and keeps mean length as a ratio-preserving conversion of the six canonical regional lengths.

Actual GLB inspection found broad triangles at the frontal hairline, discontinuity above the ears, a bare posterior centre and jagged ends. Removing the parting field left posterior gaps, so parting is not their sole cause. An analytic planar emergence probe then found that the initial ribbon frame used a global axis because the first tangent and skin normal were parallel: a 2 mm strip along +Y at z=4 mm spanned z=3..5 mm instead of spanning X at z=4 mm. The curve and root were correct; the ribbon orientation was not. That frame defect requires a general geometric correction and repeated visual verification, without personal coordinate overrides.

The corrected mesh owner obtains the initial transverse direction from the first nonparallel curve tangent, then transports it by the existing minimal rotations. A fully straight curve retains the normal-based convention. The planar-width test failed on the original implementation and passed after the change, including cyclic coordinate rotations. On the same 1,024-lock input, roots remain exactly equal, all 49,480 paired-row centres differ by at most 2.78e-17 m and widths by at most 4.52e-17 m; indices, UVs, materials and non-hair parts remain exact. The new GLB has SHA-256 `5bba6ba235cf325c8f284c6c586bedbd3f7414486dee5aa295ecb5b9ff909b4a` and the same byte count.

Six colour views of that GLB and its posterior clay view were inspected under the same directional light on Radeon 8060S / ANGLE D3D11. The posterior uncovered band is reduced. The broad stepped hairline, gaps above the ears and remaining posterior part still prevent visual acceptance. This is a correction to strip orientation, not a complete hairstyle or facial-anatomy result.

The regional-root implementation passed 21 related unit scenarios, human CJS/browser builds and both test/script type checks. An actual runtime diagnostic added 256 localized fringe strips to the same short input. All eight previous model parts and materials remained exactly equal, and the added layer contained only numerical field inputs. Its document was 3,354 bytes and the derived full-face GLB 10,484,372 bytes, SHA-256 `1c84921f1b67e92fe9c262550050115da429bee27c5b61c33f762c6e3eb4fd58`. Six colour views and the three-quarter clay view show the front population, while protruding strips, stepped edges and the posterior gap remain unaccepted.

A separate 2,048-strip long diagnostic used 3,683 input bytes and produced a 30,212,024-byte GLB. Its broad parting field caused excessive lateral spread in the observed configuration. Changing part reach from 300 to 35 mm, its front/back Gaussian spread from 150 to 70 mm, and the global flow to vertical down reduced the model's measured X extent from 581.84 to 224.65 mm. Length inputs, population and other parameters stayed fixed. The changed input was 3,679 bytes; GLB size and 608,478 total vertices stayed equal, with SHA-256 `73c04d19110383eec8c86d5ba37f69e5921237fe3e8e6e6b6e4cae77db0e56f7`. This compares the changed styling fields together and does not isolate any one of them. All six colour views were inspected: the excessive spread is reduced, but a posterior gap and strands falling across the face remain. Neither long diagnostic approves a person's hairstyle or a physical hair model.
