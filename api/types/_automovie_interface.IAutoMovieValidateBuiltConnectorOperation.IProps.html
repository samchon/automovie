    Connector-operation validation context with shared element-drive ownership tracking.

    An operated connector must name the elements it is built from, and declare at least one carriage and one state. Each carriage needs a unique non-blank id, an element that resolves and is one of the run's elements or below one, and a valid travel by validateBuiltTravelMotion; no element may be driven by two members of the whole work, which driven records across every opening and connector and is updated here. Each state needs a unique non-blank id and a known drive, may drive in reverse only on a bidirectional run, and gives every carriage exactly one value inside its travel; a carriage value's serves is null when between stops, otherwise it names one of the run's endpoints or landings. The current state must resolve. Findings are pushed under path; a run with no operation is skipped.
