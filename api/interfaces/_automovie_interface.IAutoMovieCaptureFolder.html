    Interface IAutoMovieCaptureFolder

    Opened capture storage with explicit ownership of file names and publication order.

    Before offering this port, the host confirms a requested comparison has a complete record, lists the destination, refuses every foreign entry before deleting any file, and removes only files owned by its previous record. Creating the destination directory may precede that refusal. The root may additionally contain the preserved rounds directory. Callers await each operation in order: claim before writing or external file creation, await all owned writes/removals, then close. A running record owns every claimed name, including names not yet written, so interruption permits a later capture to clean up. A complete record lists surviving successful writes and record.json itself; not every claim must produce a file. Failed cells can therefore coexist with a completed capture.

    This structural port intentionally admits host implementations other than the concrete AutoMovieCaptureFolder class. It removes that class's private-field admission restriction; it introduces no brand and cannot statically enforce sequencing or filesystem ownership. The render class implements the checks; other hosts must honor the same obligations.
