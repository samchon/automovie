# Packages

AutoMovie is published as these npm packages. A production created by `automovie create` depends on every one except `@automovie/template`, which the CLI installs, through the catalogs in its `pnpm-workspace.yaml`.

| Package | Owns |
| --- | --- |
| [`automovie`](https://www.npmjs.com/package/automovie) | The CLI: creating a production, and the hosts that capture, inspect, render and review it |
| [`@automovie/template`](https://github.com/samchon/automovie/tree/master/packages/template) | The scaffold every production starts from: instructions, contracts and thin configuration |
| [`@automovie/interface`](https://github.com/samchon/automovie/tree/master/packages/interface) | The common and domain contracts, including the authoring AST, with no runtime dependency |
| [`@automovie/engine`](https://github.com/samchon/automovie/tree/master/packages/engine) | Deterministic validation and computation of what each frame contains, and the universal motion primitives |
| [`@automovie/human`](https://github.com/samchon/automovie/tree/master/packages/human) | A person's skeleton and contact profile, generated by code from typed parameters |
| [`@automovie/motions`](https://github.com/samchon/automovie/tree/master/packages/motions) | The human action vocabulary, its composition grammar, layers, refusals and verdicts |
| [`@automovie/archetypes`](https://github.com/samchon/automovie/tree/master/packages/archetypes) | Coarse seeded models of what people hold, use, sit on, ride and fight with, and their affordances |
| [`@automovie/render`](https://github.com/samchon/automovie/tree/master/packages/render) | Scene building, the passes, the polygon man, the inspection core, the capture plan and record, frame schedules and encoding plans |
| [`@automovie/viewer`](https://github.com/samchon/automovie/tree/master/packages/viewer) | The interactive inspector page as a React component, and an imperative canvas mount |
| [`@automovie/evidence`](https://github.com/samchon/automovie/tree/master/packages/evidence) | The evidence configuration of a production: engineering defaults and the narrative, research and development checks |
| [`@automovie/ingest`](https://github.com/samchon/automovie/tree/master/packages/ingest) | Deterministic import of glTF, GLB, VRM, WAVE and PPM inputs |
| [`@automovie/recovery`](https://github.com/samchon/automovie/tree/master/packages/recovery) | Curves recovered from a reference mesh, and geometry rebuilt from them |

## Boundaries

A few rules decide where code belongs:

- `@automovie/interface` holds the pure contracts the other packages expose, so importing a type validates nothing; the package that admits a record checks it.
- `@automovie/motions` owns every action law, and `@automovie/engine` keeps only universal motion primitives.
- `@automovie/render` and `@automovie/viewer` are the packages that import `three` in their public surface.
- `@automovie/render` launches nothing; the `automovie` command supplies the browser, the files and FFmpeg as hosts.
- No product package depends on `@automovie/archetypes`; a production imports it to stage its objects.

Finished content stays in productions. Example productions live in [automovie-examples](https://github.com/samchon/automovie-examples).
