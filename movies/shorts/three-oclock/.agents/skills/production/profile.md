# Maintain project context

The project-root [PROJECT.md](../../../PROJECT.md) holds the current overview, commissioned scope, adopted choices and constraints. Read it when starting or resuming work, and update it whenever a consequential choice is adopted or changed, before later work relies on it. Keep one concise current account for the user and the next agent; Git keeps superseded choices.

## What to record

Record only what this project needs; an instance-only request needs no story or soundtrack, and a screenplay-only request no renderer. Leave an undecided nonblocking choice explicit and continue the work that does not depend on it.

| Topic | Record when relevant |
| --- | --- |
| Overview and intended result | What is made, for whom, and the intended experience, linking the detailed creative owners |
| Commissioned scope | The promised output and its boundary: an asset, a screenplay, a complete motion hint, a finished direct 3D video or a generated video, with any authorized slice, deferred work and exclusions |
| Adopted approach | Programmed motion and staging, representation and detail options, required controls, engine feedback and sound, with the reasons and limits that affect later choices |
| Tools and operating constraints | Chosen providers or local tools, runtime and delivery profile, hardware, time, cost and rights limits, and approved setup |
| Authority and unresolved choices | What the user fixed, what the agent decided within delegation and why, and what remains open |

## How it controls the work

The recorded scope selects the skills and the acceptance boundary. An adopted user decision is fixed within its scope; routine delegated decisions are made and recorded without another permission round, and a proposal or inference is not an adopted choice. When the user changes direction, update this file and the affected owners together, keeping closed narrative work under [upstream repair](../story/correction/repair.md).

Keep each fact with its owner and link to it: creative instructions in `docs/instructions`, canon and text in their layers, findings and reviews in their records, and setup and secrets under [source layout](../development/layout.md). A recorded preference proves no execution or approval.
