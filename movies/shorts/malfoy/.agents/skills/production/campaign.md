# Run and resume a production

Use this for sustained writing, review or media work, or a requested observation of one production. The run record tracks execution; it grants no approval and adds no stage.

## Establish the actual state

Read the current instructions, bodies, source, outputs and run record before assigning work, and the Git history, findings and failed logs that explain a repeated failure. Keep one concise run record in ignored `.cache/` with the scope, exact inputs, roles, process identities, observations, open causes and next action, linking existing evidence rather than copying it and leaving out credentials.

## Execute and support

Dispatch each task through [story](../story/SKILL.md), [motion](../motion/SKILL.md), [audio](../audio/SKILL.md), [development](../development/SKILL.md) or [review](../review/SKILL.md). One writer owns a changing body. Each writer and reviewer the user commissions runs as its own agent process and session with a disjoint write scope, not as a subagent inside the coordinator, because a subagent shares the coordinator's context and ends with its turn, skipping this production's instructions and leaving no session to resume. Reviewers get the actual inputs in their reading order; without independence, self-review is recorded as such.

Inspect the actual process, artifacts and errors before calling a quiet run stalled, and resume a stopped run from its last valid output and [saved stages](stages.md), keeping its failure. A changed input starts a new result; a restart inherits no verdict. A blocking capability is repaired at its package owner and reconnected to its consumer, or reported with the exact missing behavior while independent work continues. File counts, a running agent, passing validation or a preview never establish an unwatched whole film.

## Observe

Keep one observer alive for the whole run, checking each worker at the requested interval: its process, the last progress in its log and its outputs, with one line per worker in the run record. A configured timer is not an executed check, so a scheduler does not replace the observer.

A worker has failed only when its process is gone, its log has stopped and neither a completion nor an intended-stop marker exists; a quiet or slow worker, or one waiting on a user decision or a review, has not. The observer resumes a failed worker once, by its actual session, from its last valid output, never duplicating a healthy one, and reports an intended stop instead of reviving it. Report only meaningful progress, completion, failure or a blocking decision, and take no publication or merge authority from the observation.
