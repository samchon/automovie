# Settings repair exposed by treatments

Each treatment H2 answers about its actual settings parents and inherited instruction choices. This is an audit of parents tested by creation, not permission to invent missing settings inside treatments. Repair follows the [closed-pass boundary](../../../../story/correction/repair.md#closed-passes).

## What did event design prove missing or unusable upstream? {#settings-repair}

Identify the exact settings owner for any false, missing, contradictory, overdetermined or unusable fact, constraint or adopted promise exposed by this event design. Correct that body locally before writing from the repair; covering the defect in treatments leaves other events to inherit it. Name the owner, defect and corrected passage. When no repair is needed, identify concrete parent decisions exercised unchanged and how the event tested them. A generic assurance or an answer without an exact parent cannot establish that negative.
